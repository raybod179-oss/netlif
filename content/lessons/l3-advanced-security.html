طرز فکر امنیت

امنیت یک ویژگی آخرِ کار نیست؛ عادت است. دو اصل: هیچ ورودی قابل اعتماد نیست (فرم، URL، کوکی، هدر، فایل، حتی پاسخ سرویس‌های بیرونی) و حداقل دسترسی (هر کاربر و هر کلید فقط همان‌قدر که لازم است). فهرست OWASP Top 10 نقشه‌ی خوبی از رایج‌ترین حفره‌هاست؛ این درس آن‌ها را به لاراول وصل می‌کند.

۲

XSS و CSRF

کدhtml
{{ $comment->body }}          {{-- ✅ خودکار escape می‌شود --}}
{!! $comment->body !!}        {{-- ❌ خطرناک: HTML/JS کاربر اجرا می‌شود --}}

<form method="POST" action="/orders">
    @csrf                      {{-- ✅ توکن CSRF؛ بدونش ۴۱۹ می‌گیری --}}
    ...
</form>
  • XSS: وقتی متن کاربر به‌صورت HTML اجرا شود، مهاجم می‌تواند کوکی و نشست دیگران را بدزدد. همیشه از {{ }} استفاده کن. اگر واقعاً HTML لازم است (ویرایشگر مقاله)، آن را با یک کتابخانه‌ی «پاک‌سازی HTML» (مثل mews/purifier) تمیز کن، نه با strip_tags دستی.
  • CSRF: سایت مخرب کاربر ورودکرده‌ی تو را وادار به ارسال فرم ناخواسته کند. لاراول با @csrf جلویش را می‌گیرد؛ توکن را در فرم‌های POST/PUT/DELETE فراموش نکن. مسیرهایی که CSRF را معاف می‌کنی (مثل Callback درگاه) حتماً باید راه تأیید دیگری داشته باشند.

SQL Injection و Mass Assignment

کدphp
<?php

use App\Models\Product;
use Illuminate\Support\Facades\DB;

$term = request('q');

// ✅ امن: Eloquent و Query Builder از پارامتر bind استفاده می‌کنند
Product::where('title', 'like', "%{$term}%")->get();

// ✅ SQL خام فقط با bind
DB::select('SELECT * FROM products WHERE price > ?', [$minPrice]);
Product::whereRaw('stock > ? AND price < ?', [5, 100000])->get();

DB::select("SELECT * FROM products WHERE title = '$term'");

// ❌ orderBy با ستون از ورودی کاربر: حتماً لیست مجاز بساز

$column = in_array(request('sort'), $allowed, true) ? request('sort') : 'created_at';
Product::orderBy($column)->get();

آپلود فایل امن

فایل آپلودی خطرناک‌ترین ورودی است: ممکن است اسکریپت PHP با پسوند جعلی باشد یا فضای دیسک را پر کند.

کدphp
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Str;

class AvatarController extends Controller
{
    public function store(Request $request)
    {
        $request->validate([
            // نوع واقعی فایل (نه فقط پسوند)، حداکثر ۲ مگابایت
            'avatar' => ['required', 'image', 'mimes:jpg,jpeg,png,webp', 'max:2048'],
        ]);

        // نام تصادفی؛ هرگز نام اصلی کاربر را استفاده نکن
        $name = Str::uuid().'.'.$request->file('avatar')->extension();

        $path = $request->file('avatar')->storeAs('avatars', $name, 'public');

        $request->user()->update(['avatar' => $path]);

        return back();
    }
}
  • فایل‌های خصوصی (فاکتور، مدارک) را روی دیسک local (خارج از public) بگذار و از طریق کنترلر با بررسی مجوز یا Signed URL تحویل بده.
  • اجرای PHP را در پوشه‌ی آپلود غیرفعال کن (تنظیم وب‌سرور).
  • برای تصاویر، ابعاد و حجم را محدود کن و در صورت امکان بازپردازش (Resize) کن که محتوای مخرب پنهان حذف شود.

ورود، رمز و نشست

کدphp
<?php

namespace App\Providers;

use Illuminate\Cache\RateLimiting\Limit;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\ServiceProvider;
use Illuminate\Validation\Rules\Password;

class AppServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        // ۵ تلاش ورود در دقیقه برای هر ترکیب ایمیل+IP
        RateLimiter::for('login', function (Request $request) {
            return Limit::perMinute(5)->by($request->input('email').'|'.$request->ip());
        });

        // قانون پیش‌فرض رمز
        Password::defaults(fn () => Password::min(8)->letters()->numbers()->uncompromised());
    }
}

// روت:  Route::post('/login', ...)->middleware('throttle:login');
// قانون رمز:  'password' => ['required', Password::defaults(), 'confirmed']

هدرهای امنیتی و HTTPS

کدphp
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class SecurityHeaders
{
    public function handle(Request $request, Closure $next): Response
    {
        $response = $next($request);

        $response->headers->set('X-Content-Type-Options', 'nosniff');
        $response->headers->set('X-Frame-Options', 'SAMEORIGIN');            // ضد Clickjacking
        $response->headers->set('Referrer-Policy', 'strict-origin-when-cross-origin');
        $response->headers->set('Permissions-Policy', 'camera=(), microphone=(), geolocation=()');

        if ($request->isSecure()) {
            $response->headers->set('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
        }

        return $response;
    }
}
کدphp
<?php

// bootstrap/app.php (فقط بخش middleware)
use App\Http\Middleware\SecurityHeaders;
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        $middleware->append(SecurityHeaders::class);   // روی همه‌ی پاسخ‌ها
    })
    ->withExceptions(function (Exceptions $exceptions) {
        //
    })->create();
Content-Security-Policy

CSP قوی‌ترین دفاع در برابر XSS است ولی اگر اشتباه تنظیم شود سایت را می‌شکند (اسکریپت‌های درون‌خطی، CDNها). با حالت Content-Security-Policy-Report-Only شروع کن و کم‌کم سخت‌گیری کن.

اسرار، وابستگی‌ها و سرور

  • .env و اسرار: هرگز در گیت؛ ریشه‌ی وب‌سرور باید پوشه‌ی public باشد تا .env و vendor از بیرون دیده نشوند. اگر کلیدی لو رفت فوراً عوضش کن.
  • وابستگی‌ها: composer audit و npm audit را مرتب اجرا کن و پکیج‌ها را به‌روز نگه دار (در CI خودکارش می‌کنیم).
  • رمزنگاری داده‌ی حساس: ستونی مثل کد ملی یا توکن‌ها را با cast encrypted ذخیره کن (کلید در APP_KEY است؛ گم‌شدنش یعنی از دست رفتن داده‌ها).
  • HTTPS اجباری: گواهی TLS را فعال و به HTTPS ریدایرکت کن؛ در لاراول URL::forceScheme('https') در پروداکشن.
  • لاگ و پایش: تلاش‌های ورود ناموفق، خطاهای ۴۰۳/۵۰۰ و کوئری‌های عجیب را لاگ کن؛ لاگ نباید رمز یا توکن داشته باشد.
  • بکاپ: بکاپ خودکار دیتابیس و فایل‌ها و تست بازیابی (بکاپی که هرگز restore نشده، بکاپ نیست).
  • SSRF: اگر کاربر آدرسی بدهد و سرور تو درخواست بزند، آدرس‌های داخلی (localhost، شبکه‌ی خصوصی) را مسدود کن.
کدphp
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Customer extends Model
{
    protected function casts(): array
    {
        return [
            'national_id' => 'encrypted',   // در دیتابیس رمز شده، در کد عادی
        ];
    }
}

تست امنیتی نمونه

کدphp
<?php

namespace Tests\Feature;

use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\Storage;
use Tests\TestCase;

class SecurityTest extends TestCase
{
    use RefreshDatabase;

    public function test_user_cannot_set_own_role_via_mass_assignment(): void
    {
        $user = User::factory()->create(['role' => 'customer']);

        $this->actingAs($user)->put('/profile', ['name' => 'علی', 'role' => 'admin']);

        $this->assertSame('customer', $user->fresh()->role);
    }

    public function test_only_images_can_be_uploaded_as_avatar(): void
    {
        Storage::fake('public');
        $user = User::factory()->create();

        $this->actingAs($user)
             ->post('/avatar', ['avatar' => UploadedFile::fake()->create('shell.php', 10, 'application/x-php')])
             ->assertSessionHasErrors('avatar');
    }

    public function test_login_is_rate_limited(): void
    {
        for ($i = 0; $i < 5; $i++) {
            $this->post('/login', ['email' => 'a@b.com', 'password' => 'wrong']);
        }

        $this->post('/login', ['email' => 'a@b.com', 'password' => 'wrong'])->assertStatus(429);
    }
}

اشتباه‌های رایج

  1. {!! !!} روی ورودی کاربر.
  2. $request->all() در create/update و Mass Assignment.
  3. APP_DEBUG=true روی سرور واقعی (نمایش کامل خطا و حتی کلیدهای .env).
  4. ذخیره‌ی فایل آپلودی با نام و پسوند اصلی در public.
  5. نداشتن Rate Limit روی ورود و ارسال OTP.
  6. کلید و رمز در گیت یا در پاسخ API.
  7. فرض‌کردن «کسی آدرس را حدس نمی‌زند»؛ امنیت با مخفی‌بودن آدرس ساخته نمی‌شود.
★

تمرین‌ها

تمرین ۱
  1. فرم نظر بساز و عمداً با {!! !!} نمایش بده، یک <script> امتحان کن، بعد درستش کن.
  2. تست Mass Assignment بالا را بنویس.
تمرین ۲
  1. آپلود آواتار امن را پیاده کن و تست کن فایل غیرتصویری رد می‌شود.
  2. لینک دانلود فاکتور را با Signed URL ۳۰ دقیقه‌ای بساز.
تمرین ۳
  1. Rate Limit ورود را اضافه کن و تست ۴۲۹ بنویس.
  2. با composer audit پروژه‌ات را اسکن کن و هر هشدار را بررسی کن.
