داده‌ی آزمایشی و مشکلِ داده‌ی دستی

برایِ توسعه و تست، به داده‌ی «کافی و واقع‌گرایانه» نیاز داریم: ۵ دسته، ۴۰ محصول، چند کاربر. ساختنِ همه با Tinker نه‌تنها خسته‌کننده است، بلکه باید آن را برایِ هم‌تیمی یا دیتابیسِ تازه‌نصب‌شده هم تکرار کنیم. Laravel دو ابزار دارد که این را «قابلِ بازتولید» می‌کند:

Seederداده‌ی کنترل‌شده و مشخص— دسته‌هایِ پایه، کاربرِ admin…
Factoryداده‌ی تصادفیِ انبوه با fake()— ۴۰ محصولِ واقع‌گرایانه
  • Seeder برایِ «داده‌ای که معلوم است و باید باشد» (مثلِ admin)؛ Factory برایِ «مقادیرِ تولدی انبوه».
  • داده‌ی seed همیشهِ پایگاهِ خالی‌شده را بازتولید می‌کند: یک دستور، همان وضعیت.
  • چون ریشه‌ی بسیاری از تست‌ها هم به همین factory هاست، یادگیری‌اش دو بخش است.
تلفیقِ فصل‌ها

این درس ادامه‌ی درسِ ۸ (کار با Eloquent) و درسِ ۷ (ساخت جدول‌ها) است: seed و factory بخشِ پایگاهِ داده را کامل می‌کنند و صفحه‌ی فروشگاه همان خروجی را نشان می‌دهد.

۲

ساختِ Seeder با make:seeder

$ php artisan make:seeder CategorySeeder INFO Seeder [database/seeders/CategorySeeder.php] created successfully.

کلاسِ ساخته‌شده فقط یک متدِ run() دارد که وقتی db:seed اجرا شد، صدا زده می‌شود:

کدdatabase/seeders/CategorySeeder.php
<?php

namespace Database\Seeders;

use App\Models\Category;
use Illuminate\Database\Seeder;

// اول مطمئن شو روی مدل، #[Fillable('name')] داری (درس ۸):
//   #[Fillable('name')]
//   class Category extends Model { ... }

class CategorySeeder extends Seeder
{
    public function run(): void
    {
        Category::create(['name' => 'کتاب']);
        Category::create(['name' => 'نوشت‌افزار']);
        Category::create(['name' => 'گجت‌']);
    }
}
  • داخلِ run() همان کدِ Eloquentِ عادی را بگذار؛ create() به mass-assignmentِ عادی (همان #[Fillable]یِ درسِ ۸) احترام می‌گذارد.
  • پس مطمئن شو روی مدلِ Category هم #[Fillable('name')] گذاشته‌ای، وگرنه create() خطا می‌دهد.
  • Seederهایِ دیگر را با آرایه‌ی $this->call([...]) پشت‌سر هم اجرا کن (در بخشِ ۶ همین درس).
  • دقیقاً همین ترتیب به ما می‌دهد «یک فرمان = دیتابیسِ پر».
۳

اجرا: db:seed

$ php artisan db:seed # اجرایِ DatabaseSeeder INFO Seeding database. $ php artisan db:seed --class=CategorySeeder # فقط یک seeder $ php artisan migrate:fresh --seed # بازسازیِ کامل + بذر $ php artisan db:seed --force # درِ تولید؛ بدونِ پرسش
  • پیش‌فرض، کلاسِ Database\Seeders\DatabaseSeeder اجرا می‌شود؛ با --class=... فقطِ مشخص‌شده.
  • migrate:fresh --seed پرکاربردترین است: همه‌ی جداول را می‌ریزد و دوباره می‌سازد و سپس بذر می‌کند.
  • درِ محیطِ production، اگر دستوریِ مخرب ببینی، قبل از اجرا از تو پرسش می‌کند؛ --force می‌گوید «همین حالا».
migrate:fresh عواقب دارد

migrate:fresh همه‌ی داده‌ی موجود را نابود می‌کند. فقط درِ توسعه/تست خوب است — هرگز رویِ دیتابیسِ واقعی اجرایش نکن (این هم یکی از دلایلِ همان پرسشِ production است).

۴

Factory با make:factory

$ php artisan make:factory ProductFactory INFO Factory [database/factories/ProductFactory.php] created successfully.

قلبِ factory، متدِ definition() است: «چه مقادیرِ پیش‌فرضِ تصادفی بده؟» از helperِ fake() (فِیکر) برایِ تولدیِ واقع‌گرایانه استفاده کن:

کدdatabase/factories/ProductFactory.php
<?php

namespace Database\Factories;

use App\Models\Category;
use Illuminate\Database\Eloquent\Factories\Factory;

class ProductFactory extends Factory
{
    public function definition(): array
    {
        return [
            'name'        => fake()->words(3, true),
            'description' => fake()->paragraph(),
            'price'       => fake()->numberBetween(10000, 500000),
            'category_id' => Category::factory(),  // یک دسته‌ی تازه
        ];
    }
}
  • fake()->name()، fake()->paragraph()، fake()->numberBetween() و صدها رشته‌ی دیگرِ فیکر در دسترس است.
  • طرفِ کلیدی: درِ category_id یک «factory» گذاشتیم — یعنی هنگامِ ساختِ محصول، خودکار یک دسته هم ساخته می‌شود (رابطه‌ی belongsToِ فصلِ ۹).
  • برایِ ستون‌هایِ مجرد (مثلِ ایمیلِ تکرارناشدنی) از fake()->unique()->... استفاده کن.
تا چه جور factory مدلِ من را می‌شناسد؟

مدل باید traitِ HasFactory را import داشته باشد؛ سپس قراردادِ نام: factory در نام‌فضایِ Database\Factories\ProductFactory + توافقِ نامِ مدل. مدلِ Productِ ما همین شرط را دارد. (برایِ مواردِ خاص، Attributeِ #[UseFactory(...)] هست.)

۵

استفاده‌ی عملی از factory

بعدِ تعریفِ factory، درِ Tinker یا seed از طریقِ استاتیکِ ::factory() درِ دسترس است:

کدPHP — انواعِ ساخت
use App\Models\User;
use App\Models\Product;

// فقط درِ حافظه (درِ دیتابیس ذخیره نمی‌کند):
$user = User::factory()->make();

// درِ واقعیتِ پایگاه ۵۰ کاربر بساز:
$users = User::factory()->count(50)->create();

// با جای‌گذاریِ بعضی فیلدها:
$user = User::factory()->create([
    'email' => 'admin@shop.test',
    'role'  => 'admin',
]);

// همان factory درِ رابطه‌ها (فصلِ ۹):
$products = Product::factory()->count(40)->create();
  • make() فقط نمونه‌سازی، create() نمونه‌سازی + save() (رویِ record).
  • آرگومانِ create([...]) فقط همان کلیدها را بازنویسی می‌کند؛ بقیه از definition() می‌آید.
  • ->count(40) و ->state([...]) (یا مقدارِ مستقیم در create) همه‌ی مهارتِ ماست.
به‌هم‌رسانی: کاربرِ adminِ فصلِ ۱۲

با User::factory()->create(['role' => 'admin', 'email' => 'admin@shop.test']) دیگر لازم نیست بعداً دستی role را عوض کنیم — از همان seed کلید می‌شود. این «یک فرمان = وضعیتِ کاملِ توسعه» است.

۶

Seeder با factory و ترتیبِ seeding

به‌ترین ترکیب: DatabaseSeeder چند seeder را با ترتیبِ درست صدا می‌زند، و هر seeder از factory برایِ انبوهِ داده استفاده می‌کند:

کدdatabase/seeders/ProductSeeder.php
<?php

namespace Database\Seeders;

use App\Models\Product;
use Illuminate\Database\Seeder;

class ProductSeeder extends Seeder
{
    public function run(): void
    {
        Product::factory()->count(40)->create();
    }
}
کدdatabase/seeders/DatabaseSeeder.php
use App\Models\User;

public function run(): void
{
    // ترتیب مهم: اولِ دسته، بعدِ محصول
    $this->call([
        CategorySeeder::class,
        ProductSeeder::class,
    ]);

    // و کاربرِ admin (درسِ ۱۲):
    User::factory()->create([
        'name'  => 'مدیر فروشگاه',
        'email' => 'admin@shop.test',
        'role'  => 'admin',
    ]);
}
  • Category::factory() داخلِ ProductFactory، دسته‌بندیِ تصادفی می‌سازد — کارِ خودش را می‌کند و به CategorySeeder نیازی ندارد.
  • ترتیبی که در call([...]) می‌نویسی همان ترتیبِ اجراست: قبل ازِ وابسته، مرجعِ اصلی.
ترتیبِ اجرا

اگر محصول به دسته‌بندی نیاز دارد، CategorySeeder را در call اول بگذار؛ وگرنه کلیدِ خارجیِ محصول به دسته‌ای اشاره می‌کند که هنوز ساخته نشده. حالا db:seed را بزن و ۴۰ محصول تحویل بگیر.

۷

paginate() در کنترلر

حالا که نیم‌صد محصول داریم، یک لیستِ «همه و یکجا» بهتر است صفحه‌بندی شود. الگویِ paginate(n): هم کوئریِ LIMIT/OFFSET را بر اساسِ ?page= می‌سازد و هم تعدادِ کل را حساب می‌کند (یک LengthAwarePaginator می‌دهد):

کدProductController.php
use Illuminate\View\View;

public function index(): View
{
    $products = Product::query()
        ->with('category')            // جلوگیری از N+1 (فصلِ ۹)
        ->paginate(12);

    return view('products.index', ['products' => $products]);
}
  • paginate(12) یعنی «۱۲ ردیف درِ هر صفحه»؛ صفحه از query string گرفته می‌شود (?page=2، ?page=3).
  • با query builder هم کار می‌کند: DB::table('products')->paginate(12).
  • اگر فقط «بعدی/قبلی» بخواهی و شماره‌ی صفحه ندانی، simplePaginate() سریع‌تر است؛ cursorPaginate() برایِ دیتاستِ بزرگ — درِ این دوره paginate() کافی است.
  • برایِ حفظِ فیلترها در لینک‌هایِ صفحات: ->appends(request()->query()).
۸

->links() و نمایشِ شماره‌ی صفحه

بلیدِ محصولات با «شماره‌ی صفحه» از خودِ paginator:

کدresources/views/products/index.blade.php
@foreach ($products as $product)
    <div class="card">
        <h3>{{ $product->name }}</h3>
        <p>{{ $product->price }} تومان</p>
    </div>
@endforeach

{{-- لینک‌هایِ صفحات (پیش‌فرض با استایلِ Tailwind): --}}
{{ $products->links() }}

{{-- با ۳ عدد در هر طرف: ۱ ۲ ۳ [۴] ۵ ۶ ۷ --}}
{{ $products->onEachSide(3)->links() }}

اگر خواستی شماره‌ها را با متنِ فارسی نشان بدهی، مواردِ عددیِ paginator را بخوان:

کدBlade — نمایشِ شماره‌ها
<p class="muted">
    نمایش {{ $products->firstItem() }} تا {{ $products->lastItem() }}
    از {{ $products->total() }} محصول
    — صفحه‌ی {{ $products->currentPage() }} از {{ $products->lastPage() }}
</p>
۴۰محصولِ seedشده
۱۲درِ صفحه— یعنی ۴ صفحه
2?page=2— پرشِ مستقیم به صفحه‌ی دو
فرمِ لینک‌ها Tailwind است

پیش‌فرضِ links() کلاس‌هایِ Tailwind می‌سازد. پروژه‌ی تو همین استایل‌ها را دارد

  • برایِ تغییرِ قالبِ لینک‌هایِ صفحه‌بندی، فایل‌هایِ پیش‌فرضِ Tailwind را منتشر کن و ویرایششان کن.
    • php artisan vendor:publish --tag=laravel-pagination آن‌ها را در resources/views/vendor کپی می‌کند.

    ۹

    گام پروژه: فروشگاهِ پُر از محصول

    تکمیلی: دیتابیسِ زنده با ۴۰ محصولِ صفحه‌بندی‌شده

    تا پیش از این، ۳-۴ محصولِ Tinker بود؛ امروز با یک فرمان به «فروشگاهِ واقعی» تبدیلش می‌کنیم.

    1. ۲ seeder بساز: make:seeder CategorySeeder و make:seeder ProductSeeder.
    2. ۲ factory بساز: make:factory ProductFactory (با fake() برای نام/توضیح/قیمت و category_id => Category::factory()) و make:factory UserFactory برای کاربران.
    3. DatabaseSeeder را کامل کن: با $this->call([CategorySeeder::class, ProductSeeder::class]) و آوردنِ کاربرِ admin (درسِ ۱۲).
    4. اجرا کن: php artisan migrate:fresh --seed و بعد با Tinker ببین Product::count() چند است.
    5. فهرست را صفحه‌بندی کن: درِ products.index از Product::with('category')->paginate(12) استفاده کن و درِ بالایِ لیست، $products->links() و کادرِ «نمایش ۱ تا ۱۲ از ۴۰» را بگذار.
    ادامه‌ی راه

  • از دستورهایِ db:seed و migrate:fresh --seed استفاده کن.
    • تکمیل می‌شود؛ پس یک بار خوب درش بیا.

    ۱۰

    تمرین‌ها؛ حالا نوبت توست!

    تمرین ۱: ۳۰۰ کاربرِ تصادفی
    1. UserSeeder بساز که ۳۰۰ کاربر (با User::factory()->count(300)->create()) بسازد.
    2. یک «state» به نامِ admin() درِ UserFactory بساز که role را admin کند و یک نمونه‌اش را بساز.
    3. داخلِ DatabaseSeeder یک کاربرِ شناخته‌شده (ایمیلِ خودت) با این state اضافه کن.
    تمرین ۲: صفحه‌ی مشتریانِ ۲۰‌تایی
    1. روتِ /customers با paginate(20) از User اضافه کن.
    2. می‌توانی خروجیِ صفحه را در قالبِ HTML ببینی؛ همین را در مرورگر باز کن.
    3. /customers?page=2 را در مرورگر ببین — آیا ردیفِ اولِ صفحه‌ی دو، درستِ ردیفِ ۲۱ است؟
    چالش

    دکمه‌ی «جستجو» برایِ صفحه‌ی محصولات را اضافه کن: بعد از جستجو، paginate() باید ?search=کلمه را در لینک‌هایِ صفحات حفظ کند. راهنما: withQueryString()

  • page در query string نگه داشته می‌شود.
    • ۲ هم باقی بماند.

    چیزی که از این بخش توی ذهنت بماند

    1. Seeder = داده‌یِ مشخص و قابلِ بازتولید (admin، دسته‌ها)؛ Factory = داده‌ی تصادفیِ انبوه.
    2. run() کلاسِ seeder و definition() با fake() کلاسِ factory — هر دو با artisan.
    3. اجرا: db:seed، --class=، migrate:fresh --seed، و --force برایِ production.
    4. مدل traitِ HasFactory و factoryِ دارایِ نام‌گذاریِ توافقی؛ ::factory()->count(n)->create([...]).
    5. داخلِ definition() می‌توانی factoryِ رابطه را بگذاری (مثلِ category_id) — همگامِ فصلِ ۹.
    6. paginate(n) تولیدِ LIMIT/OFFSET و دانستنِ تعدادِ کل؛ $products->links() تکمیلِ UI.
    7. نمایشِ شماره‌ها: firstItem/lastItem/total/currentPage/lastPage.
    مطالعه‌ی بیشتر (انگلیسی): نوشتنِ Seeder — اجرایِ db:seed، ساختِ Factory، ساختِ مدل با factory،
  • صفحه‌بندی در Eloquent با متدِ paginate() انجام می‌شود.
    • نمایشِ نتیجه‌ها با links().
