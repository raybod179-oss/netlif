API چیست؟

API راهی است که برنامه‌ها (اپ موبایل، سایت فرانت‌اند جدا، سرویس‌های دیگر) با سرور تو داده‌ی JSON رد و بدل کنند، نه صفحه‌ی HTML. اگر روزی اپ اندروید یا یک فرانت React برای همین فروشگاه بخواهی، همین API را صدا می‌زنند.

کدjson
{
  "data": {
    "id": 1,
    "title": "کیبورد",
    "price": 850000
  }
}
کدbash
php artisan install:api     # فعال‌سازی routes/api.php و Sanctum (آدرس‌ها با /api شروع می‌شوند)
هدر Accept

هنگام تست API هدر Accept: application/json را بفرست؛ وگرنه لاراول در خطا (مثل Validation) به‌جای JSON تو را redirect می‌کند و فکر می‌کنی API خراب است.

روت‌ها و کنترلر API

کدphp
<?php

// routes/api.php
use App\Http\Controllers\Api\ProductController;
use Illuminate\Support\Facades\Route;

Route::prefix('v1')->group(function () {
    Route::apiResource('products', ProductController::class);
});

// apiResource این ۵ روت را می‌سازد (بدون create/edit که مخصوص HTML هستند):
// GET    /api/v1/products
// POST   /api/v1/products
// GET    /api/v1/products/{product}
// PUT    /api/v1/products/{product}
// DELETE /api/v1/products/{product}

نسخه‌بندی (v1) باعث می‌شود بعداً بتوانی ساختار را عوض کنی بدون اینکه اپ‌های قدیمی خراب شوند.

API Resource: شکل‌دادن به خروجی

هرگز مدل را مستقیم برنگردان؛ ستون‌های داخلی (مثل رمز یا فیلدهای حساس) ممکن است لو بروند. با Resource دقیقاً مشخص می‌کنی چه چیزی خارج شود.

کدbash
php artisan make:resource ProductResource
کدphp
<?php

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

class ProductResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id'       => $this->id,
            'title'    => $this->title,
            'price'    => $this->price,
            'in_stock' => $this->stock > 0,
            // فقط وقتی با with('category') لود شده باشد (جلوی N+1)
            'category' => new CategoryResource($this->whenLoaded('category')),
            // فقط برای ادمین
            'stock'    => $this->when($request->user()?->role === 'admin', $this->stock),
            'created_at' => $this->created_at?->toIso8601String(),
        ];
    }
}

کنترلر کامل با Validation و کد وضعیت درست

کدphp
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Resources\ProductResource;
use App\Models\Product;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Http\Response;

class ProductController extends Controller
{
    public function index(Request $request)
    {
        $products = Product::with('category')
            ->when($request->query('q'), fn ($q, $t) => $q->where('title', 'like', "%{$t}%"))
            ->latest()
            ->paginate(12);

        // Resource خودش pagination (links و meta) را هم اضافه می‌کند
        return ProductResource::collection($products);
    }

    public function store(Request $request): JsonResponse
    {
        $data = $request->validate([
            'title'       => ['required', 'string', 'max:200'],
            'price'       => ['required', 'integer', 'min:0'],
            'stock'       => ['required', 'integer', 'min:0'],
            'category_id' => ['required', 'exists:categories,id'],
        ]);

        $product = Product::create($data);

        return (new ProductResource($product))
            ->response()
            ->setStatusCode(Response::HTTP_CREATED);   // 201
    }

    public function show(Product $product): ProductResource
    {
        return new ProductResource($product->load('category'));
    }

    public function update(Request $request, Product $product): ProductResource
    {
        $data = $request->validate([
            'title' => ['sometimes', 'string', 'max:200'],
            'price' => ['sometimes', 'integer', 'min:0'],
        ]);

        $product->update($data);

        return new ProductResource($product);
    }

    public function destroy(Product $product): Response
    {
        $product->delete();

        return response()->noContent();   // 204
    }
}
وضعیتکد
موفق (خواندن/ویرایش)200
ساخته شد201
موفق بدون بدنه (حذف)204
ورودی نامعتبر (Validation)422
نیاز به ورود401
دسترسی ندارد403
پیدا نشد404

کدphp
<?php

namespace Tests\Feature;

use App\Models\Product;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class ProductApiTest extends TestCase
{
    use RefreshDatabase;

    public function test_it_lists_products(): void
    {
        Product::factory()->count(3)->create();

        $this->getJson('/api/v1/products')
             ->assertOk()
             ->assertJsonCount(3, 'data')
             ->assertJsonStructure(['data' => [['id', 'title', 'price']], 'links', 'meta']);
    }

    public function test_it_validates_input(): void
    {
        $this->postJson('/api/v1/products', [])
             ->assertStatus(422)
             ->assertJsonValidationErrors(['title', 'price']);
    }
}

برای تست دستی، برنامه‌هایی مثل Postman، Insomnia یا افزونه‌ی Thunder Client در VS Code راحت‌تر از curl هستند.

Rate Limiting و امنیت پایه

  • محدودیت تعداد درخواست با middleware throttle:60,1 یا تعریف نام‌دار در AppServiceProvider با RateLimiter::for('api', ...).
  • هیچ‌وقت $request->all() را مستقیم داخل create() نگذار؛ همیشه validated() یا فیلدهای مجاز.
  • خروجی‌ها را با Resource کنترل کن؛ فیلدهای حساس را برنگردان.
  • برای مسیرهای خصوصی، احراز هویت Sanctum (درس بعد) و Policy برای دسترسی به رکورد.

شکل‌دهی پاسخ: شرطی‌ها، رابطه‌ها و صفحه‌بندی

کدphp
class ProductResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id'       => $this->id,
            'name'     => $this->name,
            'price'    => $this->price,
            'image'    => $this->image ? asset('storage/' . $this->image) : null,
            // فقط وقتی Eager Load شده؛ جلوگیری از N+1 در API
            'category' => new CategoryResource($this->whenLoaded('category')),
            'reviews_count' => $this->whenCounted('reviews'),
            // فقط برای ادمین
            'cost'     => $this->when($request->user()?->is_admin, $this->cost),
            'created_at' => $this->created_at->toIso8601String(),
        ];
    }
}

// کنترلر
public function index(Request $request)
{
    $products = Product::with('category')->withCount('reviews')
        ->latest()->paginate($request->integer('per_page', 15));

    return ProductResource::collection($products);   // meta و links صفحه‌بندی خودکار اضافه می‌شود
}
  • whenLoaded و whenCounted کلید را در صورت نبودن رابطه حذف می‌کنند و کوئری اضافه نمی‌زنند.
  • per_page را حتماً سقف بگذار: min($request->integer('per_page', 15), 100)، وگرنه کاربر per_page=100000 می‌فرستد.
  • تاریخ را همیشه ISO 8601 بده؛ تبدیل به شمسی کار کلاینت است.

فیلتر، مرتب‌سازی و جست‌وجوی امن

کدphp
public function index(Request $request)
{
    $allowedSorts = ['price', 'created_at', 'name'];
    $sort = in_array($request->query('sort'), $allowedSorts, true) ? $request->query('sort') : 'created_at';
    $dir  = $request->query('dir') === 'asc' ? 'asc' : 'desc';

    $products = Product::query()
        ->when($request->filled('category'), fn ($q) => $q->where('category_id', $request->integer('category')))
        ->when($request->filled('min_price'), fn ($q) => $q->where('price', '>=', $request->integer('min_price')))
        ->when($request->filled('q'), fn ($q) => $q->where('name', 'like', '%' . $request->string('q') . '%'))
        ->orderBy($sort, $dir)
        ->paginate(min($request->integer('per_page', 15), 100));

    return ProductResource::collection($products);
}

نسخه‌بندی، مستندات و قرارداد پایدار

  • نسخه در آدرس: /api/v1/products. تغییر شکننده (حذف/تغییر نام فیلد) فقط در v2؛ در v1 فقط افزودن فیلد مجاز است.
  • Idempotency: برای پرداخت و ثبت سفارش، هدر Idempotency-Key بگیر و تکرار درخواست را نادیده بگیر تا دو بار کسر نشود.
  • قالب خطا: همیشه message و برای اعتبارسنجی errors (لاراول به‌طور پیش‌فرض ۴۲۲ با همین قالب می‌دهد).
  • کدهای وضعیت: ۲۰۱ ساخت، ۲۰۴ حذف، ۴۰۱ ورود نکرده، ۴۰۳ بدون دسترسی، ۴۰۴ پیدا نشد، ۴۲۲ ورودی نامعتبر، ۴۲۹ سقف نرخ.
  • مستندات خودکار: ابزارهایی مثل Scramble (OpenAPI از روی کد) یا Scribe مستندات تعاملی می‌سازند؛ یک API بدون مستندات برای تیم/مشتری ناقص است.

اشتباه‌های رایج

  1. فرستادن درخواست بدون Accept: application/json و دیدن صفحه‌ی HTML به‌جای خطای JSON.
  2. برگرداندن مدل خام و لو رفتن فیلدهای حساس.
  3. همه‌ی خطاها را با کد ۲۰۰ برگرداندن؛ کلاینت نمی‌فهمد چه شده.
  4. N+1 در Resource: رابطه را با with لود کن و در Resource از whenLoaded استفاده کن.
  5. تغییر ساختار خروجی بدون نسخه‌بندی و خراب‌شدن اپ‌های قدیمی.
  6. اجازه‌ی per_page نامحدود به کلاینت.
  7. مرتب‌سازی با نام ستونِ مستقیم از ورودی کاربر (خطر Injection و افشای ساختار).
  8. تغییر نام فیلد در همان نسخه‌ی API و خراب‌شدن اپ‌های موبایل کاربران.
★

تمرین‌ها

تمرین ۱
  1. API دسته‌بندی‌ها را با CategoryResource و apiResource بساز.
  2. یک فیلتر ?min_price= و ?max_price= به لیست محصولات اضافه کن.
تمرین ۲
  1. تست بنویس که حذف محصول ۲۰۴ برگرداند و بعدش assertDatabaseMissing بزن.
  2. تست ۴۰۴ برای محصول ناموجود بنویس.
تمرین ۳
  1. مستندات ساده‌ی API را در یک فایل API.md بنویس: آدرس، متد، پارامترها و نمونه‌ی پاسخ.
تمرین ۴
  1. فیلتر قیمت، دسته، جست‌وجو و مرتب‌سازی (با Whitelist) را به API محصولات اضافه کن و برایش تست Feature بنویس.
  2. whenLoaded را در Resource خودت به‌کار ببر و با Debugbar/Telescope ببین کوئری اضافه نمی‌خورد.
تمرین ۵
  1. API را زیر /api/v1 ببر و قالب خطای JSON یکدست برای ۴۰۴ و ۴۲۲ بساز.
