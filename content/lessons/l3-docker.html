Docker چیست و چرا؟

«روی سیستم من کار می‌کرد!» مشکل همیشگی تفاوت محیط‌هاست: نسخه‌ی PHP، افزونه‌ها، دیتابیس. Docker کل محیط (PHP، وب‌سرور، دیتابیس) را در «کانتینر» بسته‌بندی می‌کند؛ هر کسی با یک دستور همان محیط را بالا می‌آورد، چه روی ویندوز، چه روی سرور.

اصطلاحیعنی
Imageقالب فقط‌خواندنی (نقشه‌ی ساخت)
Containerیک نمونه‌ی در حال اجرا از Image
Dockerfileدستور ساخت Image
docker composeاجرای چند کانتینر کنار هم (برنامه + دیتابیس + Redis)
Volumeذخیره‌ی ماندگار داده (دیتابیس) بیرون از کانتینر
نصب

روی ویندوز Docker Desktop با WSL2؛ روی لینوکس Docker Engine. با docker --version و docker compose version مطمئن شو. گاهی دانلود Image از Docker Hub برای کاربران ایران کند یا محدود است؛ در آن صورت از Mirror/رجیستری جایگزین یا اینترنت دیگر استفاده کن.

۲

ساده‌ترین شروع: Laravel Sail

کدbash
composer require laravel/sail --dev
php artisan sail:install        # سرویس‌ها (mysql, redis, ...) را انتخاب کن
./vendor/bin/sail up -d         # اجرای محیط
./vendor/bin/sail artisan migrate
./vendor/bin/sail test

Sail یک محیط توسعه‌ی آماده است؛ برای یادگیری و کار روزمره عالی است. برای فهمیدن اصل کار و استقرار روی سرور، یک محیط را خودمان با Dockerfile و compose می‌سازیم.

۳

Dockerfile برنامه

کدdockerfile
FROM php:8.3-fpm

RUN apt-get update && apt-get install -y --no-install-recommends \
        git unzip libzip-dev libonig-dev libicu-dev \
    && docker-php-ext-install pdo_mysql mbstring zip intl bcmath opcache \
    && rm -rf /var/lib/apt/lists/*

COPY --from=composer:2 /usr/bin/composer /usr/bin/composer

WORKDIR /var/www/html

# اول فقط فایل‌های وابستگی (کش لایه‌ها)
COPY composer.json composer.lock ./
RUN composer install --no-dev --no-scripts --no-autoloader --prefer-dist

COPY . .
RUN composer dump-autoload --optimize \
    && chown -R www-data:www-data storage bootstrap/cache

EXPOSE 9000
CMD ["php-fpm"]

Docker هر دستور را به‌صورت یک «لایه» کش می‌کند. وابستگی‌ها را قبل از کپی کل کد می‌گذاریم تا با هر تغییر کوچک در کد، Composer دوباره اجرا نشود و ساخت سریع بماند.

docker-compose: برنامه + Nginx + MySQL + Redis

کدyaml
services:
  app:
    build: .
    volumes:
      - .:/var/www/html
    depends_on:
      - db
      - redis

  web:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"
    volumes:
      - .:/var/www/html:ro
      - ./docker/nginx.conf:/etc/nginx/conf.d/default.conf:ro
    depends_on:
      - app

  db:
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: laravel
      MYSQL_USER: laravel
      MYSQL_PASSWORD: secret
      MYSQL_ROOT_PASSWORD: root-secret
    volumes:
      - dbdata:/var/lib/mysql

  redis:
    image: redis:7-alpine

volumes:
  dbdata:
کدnginx
server {
    listen 80;
    server_name _;
    root /var/www/html/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass app:9000;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}

DB_PASSWORD=secret

کدbash
docker compose up -d --build              # ساخت و اجرا
docker compose exec app php artisan key:generate
docker compose exec app php artisan migrate
docker compose logs -f app                  # دیدن لاگ
docker compose down                         # توقف (داده‌ی volume می‌ماند)
docker compose down -v                      # توقف + حذف داده‌ها (مراقب!)

حالا http://localhost:8080 را باز کن. برای Worker صف هم یک سرویس جدا با همان image و دستور php artisan queue:work اضافه می‌شود.

۵

نکات استقرار با Docker

  • Image را در CI بساز و روی رجیستری (GitHub Container Registry یا Docker Hub) بگذار؛ سرور فقط pull و up می‌کند، نه ساخت.
  • فایل .env را داخل Image نگذار؛ متغیرها را هنگام اجرا (environment یا secrets) بده.
  • برای فرانت: مرحله‌ی جدا (multi-stage) با Node برای npm run build و کپی فقط خروجی در Image نهایی.
  • رمزهای دیتابیس در compose بالا فقط برای توسعه است؛ در پروداکشن رمز قوی و از Secret استفاده کن و پورت دیتابیس را به بیرون باز نکن.
  • php artisan migrate --force را با دقت و بعد از بکاپ اجرا کن.
  • کانتینر Stateless باشد: فایل‌های آپلودی و Session را روی Volume یا S3 و Redis بگذار، نه داخل کانتینر.
۶

ساخت Image پروداکشن (Multi-stage)

Dockerfile بخش قبل برای توسعه خوب است، ولی Image پروداکشن باید کوچک، سریع و بدون ابزارهای اضافه (Node، Git، پکیج‌های dev) باشد. راهش «ساخت چندمرحله‌ای» است: هر مرحله کار خودش را می‌کند و فقط خروجی لازم به Image نهایی می‌رسد.

کدdockerfile
# مرحله ۱: ساخت فایل‌های فرانت (Vite)
FROM node:22-alpine AS assets
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# مرحله ۲: نصب وابستگی‌های PHP (بدون پکیج‌های dev)
FROM composer:2 AS vendor
WORKDIR /app
COPY composer.json composer.lock ./
RUN composer install --no-dev --no-scripts --no-autoloader --prefer-dist --ignore-platform-reqs
COPY . .
RUN composer dump-autoload --optimize --classmap-authoritative --ignore-platform-reqs

# مرحله ۳: Image نهایی
FROM php:8.3-fpm-alpine AS production
RUN apk add --no-cache libzip-dev icu-dev oniguruma-dev \
    && docker-php-ext-install pdo_mysql mbstring zip intl bcmath opcache pcntl

COPY docker/php-prod.ini /usr/local/etc/php/conf.d/zz-prod.ini
WORKDIR /var/www/html
COPY --from=vendor /app /var/www/html
COPY --from=assets /app/public/build /var/www/html/public/build
RUN rm -rf tests node_modules .git \
    && chown -R www-data:www-data storage bootstrap/cache

EXPOSE 9000
CMD ["php-fpm"]
کدini
; docker/php-prod.ini
expose_php=0
memory_limit=256M
upload_max_filesize=20M
post_max_size=25M
opcache.enable=1
opcache.memory_consumption=192
opcache.max_accelerated_files=20000
opcache.validate_timestamps=0   ; فقط پروداکشن: فایل‌ها بعد از ساخت Image عوض نمی‌شوند
چرا --ignore-platform-reqs؟

Image رسمی composer افزونه‌هایی مثل intl را ندارد و در مرحله‌ی ساخت شکایت می‌کند. چون Image نهایی افزونه‌ها را دارد، در این مرحله چک‌کردن آن‌ها را رد می‌کنیم. همیشه یک بار پروژه را در Image نهایی هم اجرا کن تا مطمئن شوی.

اندازه و سرعت

با docker images اندازه را ببین. Image پروداکشن معمولاً چند برابر کوچک‌تر از Image توسعه است و ساخت دوباره‌اش به‌خاطر کش لایه‌ها سریع می‌شود.

۷

محیط کامل پروداکشن: Worker، Scheduler و Healthcheck

پروژه‌ی واقعی فقط وب نیست: صف باید Worker داشته باشد و زمان‌بندی باید هر دقیقه اجرا شود. هر کدام یک سرویس جدا با همان Image برنامه است. Healthcheck هم کمک می‌کند برنامه فقط وقتی دیتابیس آماده است بالا بیاید.

کدyaml
# docker-compose.prod.yml
x-app: &app
  image: ghcr.io/your-name/shop:latest
  restart: unless-stopped
  env_file: .env.production
  depends_on:
    db:
      condition: service_healthy

services:
  app:
    <<: *app

  worker:
    <<: *app
    command: php artisan queue:work --sleep=3 --tries=3 --timeout=90 --max-time=3600

  scheduler:
    <<: *app
    command: php artisan schedule:work

  web:
    image: nginx:1.27-alpine
    restart: unless-stopped
    ports:
      - "80:80"
    volumes:
      - ./docker/nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./public:/var/www/html/public:ro
    depends_on:
      - app

  db:
    image: mysql:8.4
    restart: unless-stopped
    env_file: .env.db
    volumes:
      - dbdata:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    restart: unless-stopped
    volumes:
      - redisdata:/data

volumes:
  dbdata:
  redisdata:

نکته‌ی مهم: Nginx باید به فایل‌های public (CSS، JS، عکس) دسترسی داشته باشد. در این الگو پوشه‌ی public را روی سرور کنار compose نگه می‌داریم؛ روش جایگزین این است که Image جدا برای Nginx با کپی همان فایل‌ها بسازی.

کدbash
# اولین استقرار روی سرور
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml exec app php artisan key:generate --show   # فقط اولین بار؛ مقدار را در .env.production بگذار
docker compose -f docker-compose.prod.yml exec app php artisan migrate --force
docker compose -f docker-compose.prod.yml exec app php artisan optimize
docker compose -f docker-compose.prod.yml exec app php artisan storage:link

# هر استقرار بعدی
docker compose -f docker-compose.prod.yml pull && docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml exec app php artisan migrate --force
docker compose -f docker-compose.prod.yml exec app php artisan optimize
docker compose -f docker-compose.prod.yml restart worker
Worker بعد از هر استقرار

Worker کد را در حافظه نگه می‌دارد. بعد از استقرار حتماً php artisan queue:restart یا restart worker بزن، وگرنه Jobها با کد قدیمی اجرا می‌شوند.

بکاپ، لاگ و به‌روزرسانی امن

کانتینر را می‌شود هر لحظه دور انداخت و دوباره ساخت؛ داده‌ها را نمی‌شود. پس بکاپ بخشی از تعریف «استقرار» است.

کدbash
# بکاپ دیتابیس (روی سرور؛ نمونه‌ی روزانه با cron)
docker compose -f docker-compose.prod.yml exec -T db \
  sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines laravel' \
  | gzip > /backups/shop-$(date +%F).sql.gz

# بازگردانی
gunzip < /backups/shop-2026-10-19.sql.gz | docker compose -f docker-compose.prod.yml exec -T db \
  sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD" laravel'

# نگه‌داری فقط ۱۴ بکاپ آخر
find /backups -name 'shop-*.sql.gz' -mtime +14 -delete
  • بکاپ را روی همان سرور نگه نداری؛ یک نسخه را به جای دیگر (سرور دیگر، فضای ابری) بفرست.
  • حداقل ماهی یک بار بازگردانی را روی یک سرور تست امتحان کن؛ بکاپی که بازگردانی‌اش را امتحان نکرده‌ای، بکاپ نیست.
  • لاگ‌ها: docker compose logs --tail=100 -f app. برای جلوگیری از پر شدن دیسک، در compose برای هر سرویس logging: { driver: json-file, options: { max-size: "10m", max-file: "3" } } بگذار.
  • به‌روزرسانی Image پایه (مثلاً php:8.3-fpm-alpine) را هر چند وقت یک بار و با تست انجام بده تا وصله‌های امنیتی بگیری.

اشتباه‌های رایج

  1. DB_HOST=127.0.0.1 داخل کانتینر؛ باید نام سرویس (db) باشد.
  2. فراموش‌کردن Volume برای دیتابیس و از دست رفتن همه‌ی داده با حذف کانتینر.
  3. کپی‌کردن .env و اسرار داخل Image.
  4. نداشتن .dockerignore و Image خیلی سنگین.
  5. مشکل دسترسی storage (خطای 500 هنگام نوشتن لاگ): مالک پوشه را www-data کن.
  6. اجرای کانتینرها با root بدون نیاز.
  7. بدون healthcheck: برنامه قبل از آماده‌شدن دیتابیس بالا می‌آید و اولین درخواست‌ها خطا می‌دهند.
  8. فراموش‌کردن queue:restart بعد از استقرار؛ Worker با کد قدیمی کار می‌کند.
  9. بکاپ‌نگرفتن قبل از migrate --force روی دیتابیس واقعی.
★

تمرین‌ها

تمرین ۱
  1. Sail را نصب کن، پروژه را بالا بیاور و تست‌ها را داخل آن اجرا کن.
تمرین ۲
  1. Dockerfile و compose بالا را برای یکی از پروژه‌هایت بساز و با docker compose up اجرا کن؛ سپس migrate بزن.
تمرین ۳
  1. یک سرویس worker برای صف اضافه کن و یک Job را امتحان کن.
  2. داده‌ی دیتابیس را با down و up دوباره روشن کن و ببین ماندگار است (Volume).
تمرین ۴
  1. Dockerfile چندمرحله‌ای بالا را برای پروژه‌ات بساز و اندازه‌ی Image را با نسخه‌ی ساده مقایسه کن (docker images).
  2. فایل docker-compose.prod.yml را روی لپ‌تاپ اجرا کن؛ یک Job را dispatch کن و ببین Worker آن را اجرا می‌کند.
  3. اسکریپت بکاپ را بنویس، یک بکاپ بگیر و آن را در یک دیتابیس تازه بازگردانی کن.
تمرین ۵
  1. یک سرویس phpmyadmin فقط برای توسعه به compose اضافه کن و مطمئن شو در فایل پروداکشن نیست؛ دلیلش را در دو جمله بنویس.
