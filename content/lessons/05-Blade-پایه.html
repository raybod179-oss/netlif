۱

Blade چیست؟

تا این‌جا، کنترلرها متنِ خام برمی‌گرداندند: «فهرست محصولات فروشگاه». اما یک سایتِ واقعی باید HTML پس بدهد — با لیست، عکس، دکمه و... برای همین لاروال یک موتور قالب به نام Blade دارد.

فایل‌های Blade با پسوند .blade.php در پوشه‌ی resources/views/ قرار می‌گیرند. کنجکاو باش: این‌ها هم PHP هستند، هم HTML — و لاروال آن‌ها را هنگام اجرا «کامپایل» می‌کند. یک مثالِ ساده:

کدresources/views/home.blade.php
<!DOCTYPE html>
<html lang="fa" dir="rtl">
<body>
    <h1>سلام به فروشگاه ما!</h1>
    <p>{{ $message }}</p>
</body>
</html>

و در routes/web.php آن را با view() صدا بزن:

کدPHP
Route::get('/', function () {
    return view('home', ['message' => 'خوش آمدی!']);
});
  • view('home') یعنی فایلِ home.blade.php را برمی‌گردان (پسوند و مسیرِ views/ را ننویس).
  • آرایه‌ی دومِ view() متغیرهایی است که به قالب می‌فرستی: کلیدِ message در قالبِ `$message` می‌شود.
workflow چطور است؟

روت → کنترلر محاسبه می‌کند → view() داده می‌دهد → Blade HTML می‌سازد → مرورگر نشان می‌دهد. در بخش بعد (۰۶) یاد می‌گیری این را تمیز و ماژولار کنی.

۲

خروجی با {{ }} و اکسکیپ

برای چاپِ مقدار یک متغیر، آن را بین دو آکولادِ دونفره بگذار: {{ $variable }}. این ساده‌ترین و هم‌زمان امن‌ترین راه است:

کدBlade
# در روت / controller
$product = ['name' => 'کفش <b>ورزشی</b>', 'price' => 250000];

# در قالب
<p>نام: {{ $product['name'] }}</p>
<p>قیمت: {{ $product['price'] }} تومان</p>
خروجی نمونهچه می‌بینی؟

نام: کفش <b>ورزشی</b>

قیمت: 250000 تومان

دقت کن: <b> همان‌‌طور متن ساده مانده؛ تبدیل به تگ نشد!

اکسکیپ (escape) یعنی لاروال کاراکترهای ویژه‌ی HTML مثل < و > را بی‌خطر می‌کند تا به‌عنوان «متن» نمایش داده شوند، نه «کد». چرا مهم است؟

چرا اکسکیپ امنیت است؟

اگر کاربرِ بدجنس در اسمِ محصول بنویسد <script>alert('hacked')</script> و تو آن را بدون اکسکیپ چاپ کنی، در مرورگرِ همه اجرا می‌شود — به این حمله XSS می‌گویند. سینتکسِ {{ $x }} خودش اکسکیپ می‌کند، پس از آن استفاده کن.

هرگز با {!! !!} چاپ نکن

نوشتن {!! $x !!} اکسکیپ را خاموش می‌کند و HTMLِ خام چاپ می‌شود. این ناامن است. فقط اگر کاملاً مطمئنی که محتوا امن و کنترلی است — همین، و حتی آن‌وقت هم بهتر است راهِ بهتری پیدا کنی.

مطالعه‌ی بیشتر (انگلیسی): چاپ و نمایش داده‌ها در Blade
۳

شرط‌ها: @if / @elseif / @else

همه‌ی شرط‌های Blade با @ شروع می‌شوند و با @endif تمام. ساختار مثل PHP است، فقط بدون آکولاد:

کدBlade
@if ($product['price'] > 200000)
    <p>این یک محصول گران‌قیمت است </p>
@elseif ($product['price'] > 100000)
    <p>قیمتش متوسط است.</p>
@else
    <p>قیمتش عالی است! </p>
@endif
خروجی نمونهچه می‌بینی؟

این یک محصول گران‌قیمت است

چون در مثالِ قبل قیمت ۲۵۰۰۰۰ بود که بیشتر از ۲۰۰۰۰۰ است.

یک میان‌بر هم هست: @unless یعنی «مگر اینکه» — عکسِ @if است (اگر شرط نادرست بود اجرا کن):

کدBlade
@unless ($product['price'] > 200000)
    <p>این محصول ارزان است.</p>
@endunless
فرمِ خلاصه برای یک خط

برای شرطِ «فقط اگر درست بود، چیزی نشان بده» این کوتاه‌تر است: {{ $x ? 'بله' : 'خیر' }} (اپراتور سه‌گانه). ولی اگر بلوک بزرگ می‌خواهی، @if بهتر است.

مطالعه‌ی بیشتر (انگلیسی): دستورات شرطی، @unless، @isset و @empty
۴

حلقه‌ها: @foreach / @for / @while

رایج‌ترین حلقه در Blade، @foreach است — مثلاً برای نمایشِ فهرست محصولات. هر محصول را یک‌بار تکرار می‌کند:

کدBlade
$products = [
    ['name' => 'کفش', 'price' => 250000],
    ['name' => 'تی‌شرت', 'price' => 120000],
    ['name' => 'کلاه', 'price' => 80000],
];

<ul>
@foreach ($products as $p)
    <li>{{ $p['name'] }} — {{ $p['price'] }} تومان</li>
@endforeach
</ul>
خروجی نمونهچه می‌بینی؟
  • کفش — 250000 تومان
  • تی‌شرت — 120000 تومان
  • کلاه — 80000 تومان

اگر به «شماره» هم نیاز داشتی، می‌توانی کلید را هم بگیرید @foreach ($x as $key => $value).

@for و @while هم مثل PHP اند ولی کمتر به کار می‌آیند:

کدBlade
@for ($i = 1; $i <= 3; $i++)
    <span>دور {{ $i }} </span>
@endfor

@php $n = 0; @endphp
@while ($n < 3)
    <span>تا سه بشمر: {{ $n }} </span>
    @php $n++; @endphp
@endwhile
خروجی نمونهچه می‌بینی؟
دور 1 دور 2 دور 3 تا سه بشمر: 0 تا سه بشمر: 1 تا سه بشمر: 2
برای فهرست‌های دیتابیس

وقتی در بخش ۰۸ با Eloquent کار کنیم، $products یک «کالکشن» می‌شود ولی همین @foreach دقیقاً همان‌طور درست کار می‌کند.

مطالعه‌ی بیشتر (انگلیسی): حلقه‌ها و دستورهای @continue / @break
۵

@forelse وقتی فهرست خالی است

@forelse بهترین دوستِ لیست‌هاست: مثل @foreach تکرار می‌کند، ولی اگر چیزی نبود، خودش بخشِ @empty را نشان می‌دهد — بدون اینکه خودت @if جدا بنویسی:

کدBlade
<div>
@forelse ($products as $p)
    <p>{{ $p['name'] }} — {{ $p['price'] }} تومان</p>
@empty
    <p>هنوز محصولی ثبت نشده است. </p>
@endforelse
</div>
خروجی نمونهوقتی $products خالی است

هنوز محصولی ثبت نشده است.

دقت کن: همین یک بلوک، هم «فهرست» و هم «صفحه‌ی خالی» را پوشش می‌دهد.

قانون طلایی لیست‌ها

تا وقتی که امکانِ «خالی بودن» وجود دارد، به‌جای @foreach از @forelse استفاده کن. توی فروشگاه (دسته‌ای که هنوز محصول ندارد) این دقیقاً همان چیزی است که لازم داری.

۶

متغیر $loop

داخلِ هر حلقه، یک متغیر آماده به نام $loop وجود دارد که اطلاعاتِ خودِ حلقه را نگه می‌دارد — بی‌نیاز از شمارنده‌ی دستی:

کدBlade
@foreach ($products as $p)
    <p>
        <b>{{ $loop->iteration }}.{{ $p['name'] }}</b>
        @if ($loop->first) <small>(اولین)</small> @endif
        @if ($loop->last)  <small>(آخرین  از {{ $loop->count }})</small> @endif
    </p>
@endforeach
خروجی نمونهچه می‌بینی؟

1.کفش (اولین)

2.تی‌شرت

3.کلاه (آخرین از 3)

ابزارهای پرکاربرد $loop: $loop->iteration → شماره‌ی فعلی (شروع از ۱) $loop->index → ایندکس (شروع از ۰) $loop->first → true اگر اولین است $loop->last → true اگر آخرین است $loop->count → تعداد کل آیتم‌ها $loop->even/$loop->odd → زوج/فرد (رنگ‌بندی ردیف‌ها)
کاربرد عملی

با $loop->odd می‌توانی ردیف‌های جدول را یک‌درمیان رنگ کنی، یا با $loop->last ویرگولِ آخرِ فهرست را حذف کنی. حلقه‌های تودرتو هم $loop جدا دارند (یک‌بار در تمرین امتحانش کن).

مطالعه‌ی بیشتر (انگلیسی): همه‌ی متغیرهای $loop (شامل remaining و depth و parent)
۷

@class و @style: کلاس و استایلِ شرطی

خیلی وقت‌ها لازم داری یک کلاس CSS یا یک استایل را «بر اساس شرط» روی عنصر بگذاری — مثلاً دکمهای که وقتی ناموجود است قرمز شود، یا ردیفی که در حالت انتخابِ کاربر برجسته است. دو راهِ دست‌وپاگیر پیش رو داری (رشته‌سازیِ دستی و اپراتور سه‌گانه درهم)، ولی Blade دو دستورِ تمیز برای این‌جور چیزها دارد.

@class — فهرست کلاس‌ها با شرط

@class([...]) یک آرایه می‌گیرد: کلاس‌هایی که «همیشه» باید باشند با کلیدِ عددی، و کلاس‌هایی که «فقط وقتی شرط درست شد» باید اضافه شوند با کلیدِ رشته‌ای و مقدارِ boolean:

کدBlade
@php
    $inStock = false;
@endphp

<div @class([
    'product-card',                 // همیشه
    'card-out' => ! $inStock,        // فقط وقتی ناموجود است
    'card-hot' => $product['price'] > 200000,
])>
    {{ $product['name'] }}
</div>
خروجی نمونهچه چیزی render می‌شود؟

<div class="product-card card-out card-hot">

کلاسِ card-out و card-hot چون شرط‌شان درست است اضافه شده‌اند؛ product-card همیشه هست.

  • کلیدِ عددی = «همیشه اضافه کن».
  • کلیدِ رشته‌ای = «فقط اگر مقدارِ boolean درست بود اضافه کن».
  • خروجی، یک رشته‌ی تمیزِ کلاس است؛ دیگر خبری از if و . درهم نیست.

@style — استایلِ درون‌خطیِ شرطی

دقیقاً همان منطق، ولی برای ویژگیِ style:

کدBlade
<p @style([
    'color: green;' => $inStock,
    'color: red;'   => ! $inStock,
    'font-weight: bold;' => $product['price'] > 200000,
])>
    {{ $inStock ? 'موجود' : 'ناموجود' }}
</p>
خروجی نمونهچه چیزی render می‌شود؟

<p style="color: red; font-weight: bold;">

چون $inStock برابر false است، استایلِ قرمز اجرا شده است.

کی class، کی style؟

تا می‌شود با @class و کلاسِ CSS کار کن (تمیزتر و قابل استفاده‌ی مجدد است)؛ @style برای مقادیرِ داینامیک (مثل عرضِ پیشرفت، رنگِ برگزیده از دیتابیس) است که نمی‌شود از قبل کلاس نوشت.

نمونه‌ی واقعیِ استفاده‌ی تو در فروشگاه: ردیفِ ناموجود را با @class([... 'row-out' => $product->stock <= 0]) خاکستری کنی. همان کاری که در چالشِ ۶ با $loop->odd می‌گفتیم، حالا تمیزتر انجام می‌شود.

مطالعه‌ی بیشتر (انگلیسی): @class و @style؛ کلاس‌ها و استایل‌های شرطی
۸

@switch و حالت‌ها

وقتی یک متغیر را با چند مقدارِ مشخص مقایسه می‌کنی، @switch خواناتر از یک‌رشته @if است. دستورِ @break یعنی «از switch بیرون بیا» (در بلید اتوماتیک هم هست، ولی بگذاریمش برای وضوح):

کدBlade
@php $status = 'shipped'; @endphp

@switch($status)
    @case('pending')
        <p>در انتظار پرداخت</p>
        @break
    @case('shipped')
        <p>ارسال شده </p>
        @break
    @default
        <p>وضعیت نامشخص</p>
@endswitch
خروجی نمونهچه می‌بینی؟

ارسال شده

چون مقدارِ $status برابرِ shipped است.

چه وقتی @if، چه وقتی @switch؟

اگر شرط‌ها «بازه/نسبت» دارند (مثل قیمت) → @if. اگر یک متغیر «مقدارِ دقیق» دارد (مثل وضعیتِ سفارش) → @switch.

مطالعه‌ی بیشتر (انگلیسی): @switch / @case / @default / @break
۹

مقدار پیش‌فرض با {{ $x ?? '...' }}

گاهی مطمئن نیستی متغیری تعریف شده یا مقدار دارد (مثلاً فیلدِ «توضیح» که خالی است). به‌جای نوشتن @if(isset($x))...، از اپراتورِ ?? استفاده کن — اگر متغیر نبود یا null بود، مقدارِ بعدش را نشان می‌دهد:

کدBlade
<p>توضیح محصول: {{ $description ?? 'توضیحی ثبت نشده' }}</p>

# اگر $description = null باشد یا اصلاً تعریف نشده باشد:
خروجی نمونهچه می‌بینی؟

توضیح محصول: توضیحی ثبت نشده

اگر کنترلر همین را هم تعیین کرده باشد (مثلاً $description = 'کفش چرم دست‌دوز')، همین عبارت مقدارِ واقعی را نشان می‌دهد. یعنی یک عبارت، هم «مقدار» را دارد هم «پیش‌فرض» را — بدون خطا و بدون if اضافه.

به‌جای تابعِ isset

در قالب، {{ $x ?? 'پیش‌فرض' }} خوانا و امن است و از @{!! isset($x) ? $x : 'پیش‌فرض' !!} بهتر است. آن را در قالب‌هایت به‌عنوان الگوی همیشگی به‌کار ببر.

۱۰

@php و کامنت {{-- --}}

گاهی داخل قالب به چند خط PHPِ خام نیاز داری (برای آماده‌سازی متغیر و...). با @php ... @endphp می‌توانی PHP بنویسی. اما به‌یاد داشته باش: هرچه منطقِ واقعی کمتر داخل قالب باشد بهتر است — قالب برای «نمایش» است.

کدBlade
@php
    $formatted = number_format($product['price']);
    $discount  = $product['price'] * 0.9;
@endphp

<p>قیمت: {{ $formatted }} تومان</p>

برای «یادداشت» توی قالب هم کامنت‌های مخصوص Blade را استفاده کن. این کامنت‌ها اصلاً به خروجی HTML نمی‌آیند (بازدیدکننده‌ی سایت نمی‌بیندشان) — برخلاف کامنتِ عادیِ HTML:

کدBlade
{{-- این کامنت در خروجیِ نهایی دیده نمی‌شود --}}

<!-- این یک کامنتِ عادی HTML است و کاربرِ سایت می‌تواند با «نمایش سورس» ببیندش -->
جمع‌بندیِ میان‌برها

{{ $x }} چاپِ امن • {{ $x ?? 'p' }} چاپ با پیش‌فرض • @php کدنویسی PHP • {{-- --}} کامنتِ نامرئی.

مطالعه‌ی بیشتر (انگلیسی): کدنویسی PHP داخل قالب (@php و @use) و کامنت‌های Blade
۱۱

گام پروژه: صفحه‌ی فهرست محصولات

این بخش کجای فروشگاه می‌نشیند؟

حالا که Blade را بلدی، می‌توانیم «نما»ی اولین صفحه‌ی واقعی فروشگاه را بسازیم: لیستِ محصولات. هنوز از دیتابیس خبری نیست (بخش ۰۷ و ۰۸)، پس فعلاً با یک آرایه‌ی ساده کار می‌کنیم.

یک ProductController ساده و یک قالب Blade برای فهرست محصولات:

کدProductController (بخشی)
<?php

namespace App\Http\Controllers;

class ProductController extends Controller
{
    public function index()
    {
        $products = [
            ['name' => 'کفش ورزشی', 'price' => 250000],
            ['name' => 'تی‌شرت',    'price' => 120000],
            ['name' => 'کلاه',       'price' => 80000],
        ];

        return view('products.index', compact('products'));
    }
}
کدresources/views/products/index.blade.php
<ul>
    @forelse ($products as $p)
        <li>
            <b>{{ $loop->iteration }}.</b>
            {{ $p['name'] }} —
            {{ number_format($p['price']) }} تومان
        </li>
    @empty
        <li>هنوز محصولی وجود ندارد.</li>
    @endforelse
</ul>
خروجی نمونهچه می‌بینی؟
  • 1. کفش ورزشی — 250,000 تومان
  • 2. تی‌شرت — 120,000 تومان
  • 3. کلاه — 80,000 تومان
حالا خودت امتحان کن

این قالب را بساز، روتِ /products را به ProductController@index وصل کن و در مرورگر ببین. بعد آرایه را خالی کن تا @empty را هم در عمل ببینی.

۱۲

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: کارت محصول
  1. یک آرایه‌ی $product با کلیدهای name، price و stock (موجودی) بساز.
  2. در قالب، اگر stock > 0 متنِ «موجود است » و در غیر این صورت «ناموجود » نشان بده (با @if/@else).
  3. قیمت را با number_format و {{ $x ?? 0 }} نمایش بده.
تمرین ۲: فهرست با وضعیت
  1. یک آرایه‌ی چندمحصوله بساز و با @forelse نمایششان بده.
  2. برای هر ردیف، شماره‌ی آن را با $loop->iteration بگذار.
  3. آخرین آیتم را با $loop->last به رنگِ متفاوت (کلاسِ CSS خودت) نشان بده.
  4. حالا آرایه را خالی کن و مطمئن شو پیامِ @empty ظاهر می‌شود.
تمرین ۳: با @switch
  1. یک متغیر $orderStatus با یکی از مقادیر pending، paid، shipped، cancelled بساز.
  2. با @switch برای هرکدام یک پیامِ فارسی نمایش بده؛ @default هم برای هرچیزِ غیرمنتظره.
  3. مقدار را عوض کن و نتیجه را تست کن.
چالش

با $loop->odd ردیف‌های فهرست را یک‌درمیان رنگ کن (ردیف‌های فرد یک پس‌زمینه‌ی ملایم داشته باشند). نتیجه را در مرورگر ببین — بعداً در جدول‌های مدیریتیِ پروژه‌ی پایانی به دردت می‌خورد.

چیزی که از این بخش توی ذهنت بماند

  1. فایل‌های نمایش، .blade.php در resources/views/ هستند و با view('name', [...]) صدا زده می‌شوند.
  2. {{ $x }} چاپِ امن است؛ {!! !!} ناامن — هرگز برای داده‌ی کاربری.
  3. شرط‌ها: @if/@elseif/@else/@endif و @unless.
  4. حلقه‌ها: @foreach/@for/@while و برای لیستِ ممکن‌الخالی بودن، @forelse/@empty.
  5. $loop اطلاعاتِ حلقه را دارد: iteration، first، last، count.
  6. مقایسه‌ی «مقدارِ دقیق» → @switch؛ مقایسه‌ی «بازه» → @if.
  7. {{ $x ?? 'پیش‌فرض' }} جایگزینِ امن و کوتاهِ isset است.
  8. منطق را تا جای ممکن در کنترلر نگه دار؛ داخل قالب فقط آماده‌سازیِ کوتاه با @php.
  9. کامنتِ {{-- --}} به خروجی نمی‌آید؛ منطقِ حساس را این‌طور کامنت نکن که چاپ شود.
