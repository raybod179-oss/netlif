کنترلرها (Controllers)

مسیر که می‌گوید «کجا»، کنترلر می‌گوید «چه‌کاری». کارهای مرتبط را از روت‌فایل بیرون می‌کشیم و در کلاس‌های تمیز جمع می‌کنیم.

۱

کنترلر چیست؟

در درس قبل، همه‌ی کارها توی routes/web.php نوشته می‌شد. خوب بود؛ اما اگر سایت بزرگ شود، این فایل به‌سرعت شلوغ و غیرقابل‌نگهداری می‌شود. کنترلر راه‌حل این مشکل است.

کنترلر یک کلاس PHP است که کارهای مرتبط را کنار هم جمع می‌کند. مثلاً همه‌ی کارهای «محصولات» — فهرست، نمایش، ساخت، ویرایش و حذف — در یک فایل به نام app/Http/Controllers/ProductController.php قرار می‌گیرد و هر کار یک «متد» است. جریانِ کار را این‌طور ببین:

درخواست کاربر → روت → کنترلر → مدل / ویو → پاسخ
چرا فایل‌ها را جدا کنیم؟
  • تمیزی: فایل روت‌ها فقط «نقشه» است، نه منطق.
  • تکرارِ صفر: متدی که یک‌بار نوشته می‌شود، در چند روت قابل استفاده است.
  • قابل فهم: همین‌که فایلِ ProductController.php را باز کنی، همه‌ی کارهای محصول را یک‌جا می‌بینی.
۲

ساخت و اتصال به روت

لاروال یک فرمان برای ساخت کنترلر دارد. در ترمینالِ پروژه‌ات اجرا کن:

کدTerminal
php artisan make:controller ProductController

فایل ساخته‌شده را می‌توانی توی ادیتورت باز کنی؛ app/Http/Controllers/ProductController.php. اولِ کار فقط قالبِ کلاس است. دو متد به آن اضافه می‌کنیم:

کدPHP
<?php

namespace App\Http\Controllers;

class ProductController extends Controller
{
    public function index()
    {
        return 'فهرست محصولات فروشگاه';
    }

    public function show(string $id)
    {
        return "محصول شماره‌ی $id";
    }
}

حالا در routes/web.php، به‌جای تابعِ تو‌در‌تو، کنترلر را صدا بزن. سه‌گوشه بودنِ [کلاس، 'متد'] را ببین:

کدPHP
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\ProductController;

Route::get('/products', [ProductController::class, 'index']);
Route::get('/products/{id}', [ProductController::class, 'show']);
  • ProductController::class یعنی «نام کامل کلاس»؛ با این کار اگر روزی مسیرِ پوشه عوض شود، نیازی به ویرایشِ همه‌جا نیست.
  • پارامترِ روت ({id}) خودکار به آخرین آرگومانِ متد پاس داده می‌شود: show(string $id).
  • اکنون بازدید از /products متنِ فهرست محصولات فروشگاه و /products/5 متنِ محصول شماره‌ی 5 را نشان می‌دهد؛ دقیقاً مثل قبل، ولی تمیزتر!
قانون ترتیب پارامترها

یک کنترلر می‌تواند چند پارامتر از روت بگیرد: show(string $category, string $id). فقط یادت باشد ترتیبش دقیقاً همان ترتیبِ {...} در آدرسِ روت است.

۳

Resource Controller

تقریباً هر مدلِ واقعی، هفت «کارِ استاندارد» دارد: فهرست، فرمِ ساخت، ذخیره‌سازی، نمایش، فرمِ ویرایش، به‌روزرسانی و حذف — به‌اختصار CRUD (ساخت، خواندن، به‌روزرسانی، حذف). لاروال این الگو را کم‌هزینه کرده است. اول با فرمان زیر، کنترلرِ resource بساز:

کدTerminal
php artisan make:controller CategoryController --resource

این کنترلر با هفت متدِ خالی ساخته می‌شود که نام‌شان دقیقاً با الگوی لاروال همخوان است:

کدPHP
<?php

namespace App\Http\Controllers;

class CategoryController extends Controller
{
    public function index() {}    // فهرست دسته‌ها
    public function create() {}   // فرمِ ساخت دسته
    public function store() {}    // ذخیره‌ی دسته‌ی جدید
    public function show(string $id) {}  // نمایش یک دسته
    public function edit(string $id) {}  // فرمِ ویرایش
    public function update(string $id) {} // به‌روزرسانی
    public function destroy(string $id) {} // حذف
}

حالا فقط با یک خط، همه‌ی این هفت روش، روت می‌شوند:

کدPHP
Route::resource('categories', CategoryController::class);

معنایش این هفت روتِ نامدار است:

کدخروجی route:list
GET|HEAD /categories → categories.index GET|HEAD /categories/create → categories.create POST /categories → categories.store GET|HEAD /categories/{id} → categories.show GET|HEAD /categories/{id}/edit → categories.edit PUT|PATCH /categories/{id} → categories.update DELETE /categories/{id} → categories.destroy
  • چهار روشِ GET صفحه نشان می‌دهند، POST می‌سازد، PUT/PATCH به‌روزرسانی می‌کند و DELETE حذف می‌کند. (ترتیبِ ۱ تا ۷ = چرخه‌ی کامل CRUD)
  • نام هر روت خودِ کار است: categories.store، categories.show و... برای ساخت لینک با route() خیلی به‌درد می‌خورند.
۴

فقط بخشی از resource

همیشه همه‌ی هفت متد لازم نیست. مثلاً مشتری می‌تواند محصول ببیند ولی حقِ ساخت/ویرایش ندارد؛ پس فقط دو روتِ index و show را ثبت کن:

کدPHP
Route::resource('products', ProductController::class)
    ->only(['index', 'show']);

یا برعکس؛ اگر از هفت‌تایی فقط یکی لازم نیست، از except استفاده کن:

کدPHP
Route::resource('categories', CategoryController::class)
    ->except(['create', 'edit']);
چه وقتی فقطِ فقط؟

only را برای «صفحه‌های همگان» و except را برای «هرچه خواننده می‌تواند» به‌کار ببر. هر دو برای بخشِ مدیریت (که بعداً با Auth محافظت می‌شود) جدا می‌شوند.

۵

درخواست و ورودی‌ها (Request)

لاروال هر درخواستِ HTTP را در یک شیء Illuminate\Http\Request به کنترلر می‌دهد. برای دریافتش، فقط تایپ‌هینت می‌کنی و لاروال خودش آن را ساخته و به متد می‌دهد (به این می‌گویند تزریق وابستگی؛ نگرانش نباش، فقط همین الگو را ببین):

کدPHP
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class ProductController extends Controller
{
    public function index(Request $request)
    {
        $search = $request->query('q');

        return $search
            ? "نتیجه‌ی جست‌وجو: $search"
            : 'فهرست محصولات فروشگاه';
    }
}
خروجی نمونهچه می‌بینی؟
بازدید از آدرسِ:
/products?q=کفش ↓ نتیجه‌ی جست‌وجو: کفش ↓ /products ↓ فهرست محصولات فروشگاه
  • $request->query('q') چیزی را که بعد از ? در آدرس آمده می‌خواند (اگر نبود null برمی‌گرداند).
  • $request->input('name', 'پیش‌فرض') هم برای GET هم POST کار می‌کند و می‌تواند مقدارِ پیش‌فرض بدهد.
  • $request->all() همه‌ی ورودی‌ها را آرایه می‌دهد؛ $request->has('q') می‌گوید آیا فیلدی آمده است یا نه.
ترتیب را به‌هم نزن

اگر متد هم Request می‌خواهد هم پارامترِ روت، اول Request و بعد پارامترها: public function show(Request $request, string $id). روت‌پارامترها همیشه بعد از تزریق‌ها می‌آیند.

۶

abort(404) وقتی چیزی پیدا نشد

گاهی باید خودت جلوی ادامه‌ی کار را بگیری؛ مثلاً وقتی محصولِ درخواستی وجود ندارد یا مجاز نیستی. تابعِ abort() همین کار را می‌کند — کدِ خطا را می‌گیری و اجرا قطع می‌شود:

کدPHP
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class ProductController extends Controller
{
    public function show(string $id)
    {
        // فعلاً فقط محصول ۱ و ۲ وجود دارد
        $validIds = ['1', '2'];

        if (! in_array($id, $validIds)) {
            abort(404, 'محصول پیدا نشد');
        }

        return "محصول شماره‌ی $id";
    }
}
خروجی نمونهچه می‌بینی؟
404
محصول پیدا نشد
(Not Found — صفحه‌ی خطا لاروال)
  • abort(404) صفحه‌ی استانداردِ «پیدا نشد» لاروال را نشان می‌دهد.
  • پیامِ دوم اختیاری است؛ در APP_DEBUG=true دیده می‌شود (درس ۱ خواندیم).
  • کدهای مهم دیگر: abort(403) یعنی «مجاز نیستی» و abort(500) یعنی «خطای سرور».

برای «شاید، شاید نه» هم میان‌بری هست: abort_unless(شرط، کد) — اگر شرط درست نبود، همان خطا:

کدPHP
abort_unless(in_array($id, $validIds), 404);
۷

نمونه CRUD مینی: چرخه‌ی کامل تمیز

حالا همه‌ی چیزهایی که یاد گرفتیم را کنار هم بگذاریم. روی یک لیستِ کوچکِ درون‌حافظه‌ای (بدون دیتابیس!) یک CRUD واقعی می‌سازیم تا ببینی هر متدِ resource دقیقاً کجای چرخه می‌نشیند. «محصول» را با یک ProductController و یک آرایه‌ی ساده شبیه‌سازی می‌کنیم:

کدPHP
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;

class ProductController extends Controller
{
    // فعلاً به‌جای دیتابیس، یک آرایه‌ی ساده
    private array $products = [
        1 => 'کفش ورزشی',
        2 => 'هودی نخی',
        3 => 'کوله‌پشتی',
    ];

    // ۱) فهرست — GET /products
    public function index()
    {
        return implode('، ', $this->products);
    }

    // ۲) نمایش تک‌محصول — GET /products/{id}
    public function show(string $id)
    {
        if (! isset($this->products[$id])) {
            abort(404, 'محصولی با این شناسه نیست');
        }

        return $this->products[$id];
    }

    // ۳) ساخت — POST /products (با فرم در بخش ۱۰ مقدار واقعی می‌رسد)
    public function store(Request $request)
    {
        return 'ذخیره شد: ' . $request->input('title', 'بدون عنوان');
    }

    // ۴) به‌روزرسانی — PUT/PATCH /products/{id}
    public function update(Request $request, string $id)
    {
        return "محصول $id ویرایش شد به: " . $request->input('title');
    }

    // ۵) حذف — DELETE /products/{id}
    public function destroy(string $id)
    {
        return "محصول $id حذف شد";
    }
}

و در routes/web.php، همه‌ی این‌ها را با یک خط resource می‌کنیم — یعنی همان هفت روتِ نامدارِ درس ۳:

کدPHP
Route::resource('products', ProductController::class);

حالا این آدرس‌ها را در مرورگر امتحان کن. (فعلاً فقط دو متدِ GET بی‌فرم‌اند؛ سه متدِ دیگر تا بخش ۱۰ به‌جای POST/PUT/DELETE به فرم نیاز دارند.)

خروجی نمونهچه می‌بینی؟
GET /products ↓ کفش ورزشی، هودی نخی، کوله‌پشتی ↓ GET /products/2 ↓ هودی نخی
چرا «درون‌حافظه‌ای»؟

هر بار که صفحه رفرش شود، آرایه از صفر ساخته می‌شود و چیزی روی دست نمی‌ماند — این دقیقاً همان محدودیتی است که «دیتابیس» حل می‌کند. در بخش ۰۸ (Eloquent) همین پنج متد را روی یک جدول واقعی اجرا می‌کنیم و دیگر چیزی از بین نمی‌رود.

  • الگوی کلی همیشه همین است: index فهرست، show تک‌رکورد، store ساخت، update ویرایش، destroy حذف.
  • متدهای تغییردهنده (store/update/destroy) همه‌چیزشان را از Request می‌گیرند؛ پس تا فرم نباشد، فقط الگویشان را ببین.
  • خودِ لاروال هم «محدوده‌بندی» را می‌فهمد: روتِ PUT/DELETE را در مرورگر می‌توان با «روش‌جعل» تست کرد — در بخش ۱۰ (فرم‌ها) آن را هم می‌بینیم.
۸

گام پروژه: کنترلر محصولات

این بخش کجای فروشگاه می‌نشیند؟

توی فروشگاه‌مان، هر چیزی که به «محصول» مربوط است — فهرست و نمایش و بعدها ساخت، ویرایش، حذف — در یک ProductController جمع می‌شود. مسیرهای /products و /products/{id} به متدهای index و showی همین کنترلر اشاره می‌کنند و abort(404) جوابِ محصولِ ناموجود است.

الان همین‌جا کاملش نمی‌کنیم؛ چون هنوز مدل و ویو و فرم را یاد نگرفته‌ایم. کافی است مفهومش را بفهمی:

  • php artisan make:controller ProductController کنترلرِ محصولات را می‌سازد.
  • Route::get('/products', [ProductController::class, 'index']) فهرست را به index() وصل می‌کند.
  • Route::get('/products/{id}', [ProductController::class, 'show']) نمایش را به show() وصل می‌کند.
  • وقتی محصولی وجود ندارد: abort(404).

این‌ها را فقط توی ذهنت نگه دار؛ در بخش ۹۹ (پروژه‌ی پایانی) با کمکِ Eloquent و Blade، همین کنترلر را کامل و واقعی می‌کنیم.

حالا خودت امتحان کن

در یک پروژه‌ی آزمایشی کوچک، یک TestController بساز، دو متد به آن بده و در web.php وصلش کن تا با route:list ببینی چطور کار می‌کند — بعد پاکش کن.

۹

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: کنترلر دسته‌ها
  1. با make:controller یک CategoryController ساده بساز (بدون resource).
  2. دو متد بگذار: index() که «فهرست دسته‌ها» را برمی‌گرداند و show($id) که «دسته شماره‌ی ...» را.
  3. در web.php دو روتِ /categories و /categories/{id} (با whereNumber) به آن‌ها وصل کن.
تمرین ۲: abort در عمل
  1. در متدِ showی دسته‌ها، فقط دسته‌های ۱ تا ۳ مجاز باشند؛ بقیه با abort(404).
  2. برای تمرینِ abort(403)، یک متد secret() درست کن که همیشه «مجاز نیستی» دهد.
  3. روتش را با Route::get('/secret', [CategoryController::class, 'secret']) ثبت و تست کن.
چالش

برای «کوپن‌های تخفیف» یک CouponController با --resource بساز و با Route::resource('coupons', CouponController::class) ثبتش کن. با php artisan route:list هر هفت روت را ببین و نام‌هایشان را بخوان (coupons.index، coupons.store و...). بعد با ->only([...]) فقط روت‌هایی را نگه دار که برای «خواندن» لازم‌اند.

چیزی که از این بخش توی ذهنت بماند

  1. کنترلر یک کلاس است که کارهای یک «منبع» (مثل محصول) را در متدها جمع می‌کند.
  2. ساخت: php artisan make:controller ProductController.
  3. اتصال: Route::get('/x', [ProductController::class, 'metod']).
  4. پارامترهای روت، خودکار به آرگومان آخرِ متد می‌رسند.
  5. --resource هفت متد CRUD می‌سازد و Route::resource() هفت روتِ نامدار ثبت می‌کند.
  6. با ->only() و ->except() فقط روت‌های لازم را ثبت کن.
  7. Request را به متد تزریق کن تا ورودی‌ها را بخوانی؛ قانونِ تزریق اول، پارامترِ دوم.
  8. برای «پیدا نشد» از abort(404) یا abort_unless(...) استفاده کن.
