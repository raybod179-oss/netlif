۱

جریان پرداخت اینترنتی

درگاه‌های ایرانی (زرین‌پال، IDPay، بانک‌ها و ...) همه تقریباً یک الگو دارند:

  1. درخواست پرداخت: سرور تو مبلغ و آدرس بازگشت (callback) را به درگاه می‌فرستد و یک شناسه‌ی پرداخت (Authority/Token) می‌گیرد.
  2. هدایت کاربر: کاربر را به صفحه‌ی درگاه می‌بری و پرداخت را آنجا انجام می‌دهد.
  3. بازگشت: درگاه کاربر را به callback تو برمی‌گرداند (با وضعیت OK یا NOK).
  4. تایید (Verify): سرور تو دوباره از خود درگاه می‌پرسد «واقعاً پرداخت شد؟» و فقط بعد از تایید، سفارش را پرداخت‌شده می‌کند.
قانون طلایی

هرگز فقط به پارامتر بازگشت (Status=OK) اعتماد نکن. هر کسی می‌تواند آدرس callback را دستی با Status=OK باز کند. تنها «Verify» سرور به سرور معتبر است و مبلغ را باید از دیتابیس خودت بخوانی، نه از ورودی کاربر.

۲

طراحی تمیز: Interface + جدول payments

جزئیات هر درگاه (آدرس‌ها، نام فیلدها، واحد مبلغ) را فقط در یک کلاس «Adapter» نگه می‌داریم. بقیه‌ی برنامه فقط با PaymentGateway کار می‌کند؛ اگر درگاه را عوض کنی فقط همان کلاس عوض می‌شود.

پیاده‌سازی نمونه (زرین‌پال)

قبل از استفاده

آدرس‌ها، نام فیلدها و واحد مبلغ (ریال یا تومان) در کد زیر را حتماً با مستندات رسمی نسخه‌ی فعلی درگاه خودت تطبیق بده؛ درگاه‌ها گاهی تغییر می‌کنند. ساختار و الگوی ایمنی مهم‌تر از جزئیات یک درگاه است. همچنین بعضی درگاه‌ها درخواست از سرور خارج ایران را نمی‌پذیرند؛ هنگام انتخاب هاست این را بپرس.

کدphp
<?php

namespace App\Services\Payment;

use App\Models\Payment;
use Illuminate\Support\Facades\Http;
use RuntimeException;

class ZarinpalGateway implements PaymentGateway
{
    private const BASE = 'https://payment.zarinpal.com/pg/v4/payment';

    public function request(Payment $payment, string $callbackUrl): string
    {
        $response = Http::timeout(15)->retry(2, 300)->acceptJson()->post(self::BASE.'/request.json', [
            'merchant_id'  => config('services.zarinpal.merchant_id'),
            'amount'       => $this->amount($payment),
            'callback_url' => $callbackUrl,
            'description'  => 'سفارش شماره‌ی '.$payment->order_id,
        ]);

        $data = $response->json('data');

        if (($data['code'] ?? null) !== 100 || empty($data['authority'])) {
            throw new RuntimeException('Gateway request failed: '.$response->body());
        }

        $payment->update(['authority' => $data['authority'], 'raw' => $response->json()]);

        return 'https://payment.zarinpal.com/pg/StartPay/'.$data['authority'];
    }

    public function verify(Payment $payment): ?string
    {
        $response = Http::timeout(15)->retry(2, 300)->acceptJson()->post(self::BASE.'/verify.json', [
            'merchant_id' => config('services.zarinpal.merchant_id'),
            'amount'      => $this->amount($payment),       // از دیتابیس خودمان، نه از کاربر
            'authority'   => $payment->authority,
        ]);

        $code = $response->json('data.code');

        // ۱۰۰: موفق  ·  ۱۰۱: قبلاً تایید شده
        if (in_array($code, [100, 101], true)) {
            return (string) $response->json('data.ref_id');
        }

        return null;
    }

    private function amount(Payment $payment): int
    {
        // واحد داخلی ما تومان است؛ اگر درگاه ریال می‌خواهد ضرب در ۱۰ (طبق مستندات)
        return $payment->amount * (int) config('services.zarinpal.multiplier', 10);
    }
}

کنترلر: شروع پرداخت و بازگشت امن

کدphp
<?php

namespace App\Http\Controllers;

use App\Events\OrderPaid;
use App\Models\Order;
use App\Models\Payment;
use App\Services\Payment\PaymentGateway;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB;
use Throwable;

class PaymentController extends Controller
{
    public function __construct(private PaymentGateway $gateway) {}

    public function start(Request $request, Order $order): RedirectResponse
    {
        abort_unless($order->user_id === $request->user()->id, 403);
        abort_unless($order->status === 'pending', 422, 'این سفارش قابل پرداخت نیست.');

        // مبلغ همیشه از خود سفارش در دیتابیس می‌آید
        $payment = $order->payments()->create([
            'amount'  => $order->total,
            'gateway' => 'zarinpal',
        ]);

        try {
            $url = $this->gateway->request($payment, route('payment.callback', $payment));
        } catch (Throwable $e) {
            report($e);
            $payment->update(['status' => 'failed']);

            return back()->with('error', 'اتصال به درگاه برقرار نشد؛ کمی بعد دوباره تلاش کن.');
        }

        return redirect()->away($url);
    }

    public function callback(Request $request, Payment $payment): RedirectResponse
    {
        $order = $payment->order;

        // تکراری‌بودن: اگر قبلاً پرداخت شده، فقط نتیجه را نشان بده
        if ($payment->status === 'paid') {
            return redirect()->route('orders.show', $order)->with('success', 'پرداخت قبلاً ثبت شده است.');
        }

        // شناسه‌ی بازگشتی باید دقیقاً همان باشد که ما ثبت کرده بودیم
        $authority = (string) $request->query('Authority');
        if ($request->query('Status') !== 'OK' || ! hash_equals((string) $payment->authority, $authority)) {
            $payment->update(['status' => 'failed']);

            return redirect()->route('orders.show', $order)->with('error', 'پرداخت انجام نشد یا لغو شد.');
        }

        $ref = $this->gateway->verify($payment);

        if (! $ref) {
            $payment->update(['status' => 'failed']);

            return redirect()->route('orders.show', $order)->with('error', 'تایید پرداخت ناموفق بود.');
        }

        $paidNow = DB::transaction(function () use ($payment, $order, $ref) {
            $locked = Payment::whereKey($payment->id)->lockForUpdate()->first();

            if ($locked->status === 'paid') {
                return false;                    // درخواست هم‌زمان دیگری انجامش داده
            }

            $locked->update(['status' => 'paid', 'ref_id' => $ref, 'paid_at' => now()]);
            $order->update(['status' => 'paid']);

            return true;
        });

        if ($paidNow) {
            OrderPaid::dispatch($order);        // ایمیل، پیامک، کم‌کردن موجودی ... (درس Event)
        }

        return redirect()->route('orders.show', $order)
            ->with('success', 'پرداخت موفق بود. شماره‌ی پیگیری: '.$ref);
    }
}

کدphp
<?php

namespace Tests\Feature;

use App\Events\OrderPaid;
use App\Models\Order;
use App\Models\Payment;
use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Support\Facades\Event;
use Illuminate\Support\Facades\Http;
use Tests\TestCase;

class PaymentTest extends TestCase
{
    use RefreshDatabase;

    public function test_successful_callback_marks_order_paid_once(): void
    {
        Event::fake([OrderPaid::class]);
        Http::fake([
            'payment.zarinpal.com/pg/v4/payment/verify.json' =>
                Http::response(['data' => ['code' => 100, 'ref_id' => 123456]]),
        ]);

        $user = User::factory()->create();
        $order = Order::factory()->create(['user_id' => $user->id, 'status' => 'pending', 'total' => 100000]);
        $payment = Payment::create([
            'order_id'  => $order->id,
            'amount'    => 100000,
            'gateway'   => 'zarinpal',
            'authority' => 'A0001',
        ]);

        $url = route('payment.callback', $payment).'?Authority=A0001&Status=OK';

        $this->actingAs($user)->get($url)->assertRedirect();
        $this->assertSame('paid', $order->fresh()->status);

        // بازگشت دوباره (رفرش) نباید دوباره Event بفرستد
        $this->actingAs($user)->get($url);
        Event::assertDispatchedTimes(OrderPaid::class, 1);
    }

    public function test_wrong_authority_is_rejected(): void
    {
        Http::fake();

        $order = Order::factory()->create(['status' => 'pending']);
        $payment = Payment::create(['order_id' => $order->id, 'amount' => 1000, 'gateway' => 'zarinpal', 'authority' => 'REAL']);

        $this->get(route('payment.callback', $payment).'?Authority=FAKE&Status=OK');

        $this->assertSame('pending', $order->fresh()->status);
        Http::assertNothingSent();
    }
}

چک‌لیست قبل از پرداخت واقعی

  • مبلغ همیشه از دیتابیس، هرگز از فرم/URL.
  • Verify سرور به سرور و تطبیق Authority؛ نتیجه‌ی بازگشت را باور نکن.
  • عملیات «پرداخت‌شده» داخل تراکنش و با قفل (جلوی رفرش و درخواست هم‌زمان).
  • جدول payments با پاسخ خام درگاه برای رسیدگی به اختلاف‌ها.
  • کلید/مرچنت‌کد فقط در .env.
  • تست با حالت آزمایشی (Sandbox) درگاه و بعد یک پرداخت کوچک واقعی.
  • صفحه‌ی «پرداخت ناموفق» با پیام روشن و راه پیگیری برای کاربر.
  • پرداخت‌های pending قدیمی را با Scheduler پاک/لغو کن (درس قبل).
  • قوانین فروش، مالیات و بازگشت وجه را مطابق قانون و شرایط درگاه روی سایت بنویس.
۷

اشتباه‌های رایج

  1. اعتماد به Status=OK بدون Verify.
  2. گرفتن مبلغ از ورودی کاربر.
  3. نداشتن جلوگیری از پرداخت دوباره‌ی یک سفارش و ثبت چندباره (idempotency).
  4. اشتباه در واحد مبلغ (ریال/تومان) و دریافت ۱۰ برابر یا یک‌دهم.
  5. نگه‌نداشتن لاگ و شماره‌ی پیگیری.
  6. تست مستقیم روی درگاه واقعی به‌جای Http::fake.

تمرین‌ها

تمرین ۱
  1. مایگریشن و مدل Payment را بساز، رابطه‌ی payments() را به Order اضافه کن.
  2. FakeGateway بنویس که همیشه موفق شود و در محیط local به‌جای درگاه واقعی bind کن.
تمرین ۲
  1. صفحه‌ی «سفارش‌های من» را با دکمه‌ی «پرداخت» برای سفارش‌های pending بساز.
  2. صفحه‌ی نتیجه‌ی پرداخت با پیام موفق/ناموفق و شماره‌ی پیگیری طراحی کن.
تمرین ۳
  1. Scheduler: پرداخت‌های pending بیش از یک ساعت را failed کن.
  2. تست بنویس که کاربر دیگر نتواند سفارش شخص دیگری را پرداخت کند (۴۰۳).
