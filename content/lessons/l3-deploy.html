انتشار روی هاست و VPS

پروژه تا وقتی روی سرور نیست «فقط روی کامپیوتر من» است. این درس تو را قدم‌به‌قدم از صفر تا سایت زنده با HTTPS، صف، Cron و بکاپ می‌برد.

گزینه‌های انتشار

گزینهمزیتمحدودیتمناسب
هاست اشتراکی (cPanel)ارزان، سادهدسترسی محدود (گاهی SSH نیست)، پروسه‌ی دائمی ممکن نیستسایت کوچک، شروع
VPS لینوکسکنترل کامل، صف و WebSocketمدیریت سرور با خودت استفروشگاه واقعی، پروژه‌ی جدی
Docker روی VPSمحیط یکسان با توسعهیادگیری Docker لازم استتیمی، چند سرویس
PaaS (مثل Laravel Cloud، Forge + سرور)دیپلوی سادههزینه؛ برای ایران ممکن است قابل‌دسترس نباشداگر سرور خارج ایران مجاز است
سرور داخل یا خارج ایران؟

اگر سایتت درگاه پرداخت ایرانی دارد، بعضی درگاه‌ها فقط از IP ایران درخواست می‌پذیرند و کاربران ایرانی هم سرعت بهتری از سرور داخلی می‌گیرند. قبل از خرید هاست از پشتیبانی درگاه و هاست بپرس. این‌ها را همیشه با اطلاعات به‌روز خودت چک کن.

۲

انتشار روی هاست اشتراکی (cPanel)

  1. نسخه‌ی PHP را روی ۸٫۲ یا بالاتر بگذار (MultiPHP Manager) و افزونه‌های لازم (mbstring، pdo_mysql، xml، zip، intl، bcmath، fileinfo) را فعال کن.
  2. دیتابیس و کاربر MySQL بساز و به هم وصل کن.
  3. ریشه‌ی دامنه را روی پوشه‌ی public پروژه بگذار (Domains ← Document Root). اگر هاست اجازه نمی‌دهد، کل پروژه را بالاتر از public_html بگذار و فقط محتوای public را داخل public_html بریز و مسیرهای index.php را اصلاح کن. هرگز کل پروژه (با .env) را داخل public_html نگذار.
  4. پروژه را آپلود کن (ZIP + Extract). اگر SSH داری: composer install --no-dev --optimize-autoloader؛ اگر نداری، پوشه‌ی vendor را از سیستم خودت (با --no-dev) آپلود کن.
  5. فایل .env را با مقادیر واقعی بساز و APP_ENV=production، APP_DEBUG=false، APP_URL و اطلاعات دیتابیس را بگذار.
  6. اگر SSH داری: php artisan key:generate، php artisan migrate --force، php artisan storage:link، php artisan optimize.
  7. مجوز نوشتن: پوشه‌های storage و bootstrap/cache قابل‌نوشتن باشند (معمولاً ۷۷۵).
  8. Cron را برای Scheduler اضافه کن (درس Scheduler) و برای صف: php artisan queue:work --stop-when-empty هر دقیقه.
اگر بدون SSH هستی

دستورات artisan را نمی‌توانی بزنی. با یک مسیر موقت و رمزدار می‌شود migrate اجرا کرد ولی این روش خطرناک است؛ ترجیحاً هاستی انتخاب کن که SSH دارد، یا migration را روی سیستم خودت به دیتابیس هاست اجرا کن (اگر دسترسی ریموت دارد) یا خروجی SQL را با phpMyAdmin وارد کن.

راه‌اندازی VPS اوبونتو (Nginx + PHP-FPM + MySQL)

کدbash
# ۱) اتصال و امن‌سازی اولیه
ssh root@SERVER_IP
adduser deploy && usermod -aG sudo deploy
# کلید SSH را برای کاربر deploy بگذار و ورود با رمز و root را در /etc/ssh/sshd_config غیرفعال کن

ufw allow OpenSSH && ufw allow 'Nginx Full' && ufw enable

# ۲) نصب بسته‌ها (اوبونتو ۲۴٫۰۴ با PHP 8.3)
sudo apt update
sudo apt install -y nginx mysql-server git unzip \
  php8.3-fpm php8.3-mysql php8.3-mbstring php8.3-xml php8.3-curl php8.3-zip php8.3-intl php8.3-bcmath
sudo apt install -y composer certbot python3-certbot-nginx supervisor
کدsql
-- ۳) دیتابیس و کاربر اختصاصی (با رمز قوی)
CREATE DATABASE myshop CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'myshop'@'localhost' IDENTIFIED BY 'A-Strong-Random-Password';
GRANT ALL PRIVILEGES ON myshop.* TO 'myshop'@'localhost';
FLUSH PRIVILEGES;
کدnginx
# /etc/nginx/sites-available/myshop
server {
    listen 80;
    server_name example.com www.example.com;
    root /var/www/myshop/public;
    index index.php;
    client_max_body_size 10M;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.3-fpm.sock;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}
کدbash
sudo ln -s /etc/nginx/sites-available/myshop /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# ۴) HTTPS رایگان (دامنه باید از قبل به IP سرور اشاره کند)
sudo certbot --nginx -d example.com -d www.example.com

گذاشتن برنامه روی سرور

کدbash
sudo mkdir -p /var/www/myshop && sudo chown deploy:deploy /var/www/myshop
cd /var/www/myshop
git clone git@github.com:USERNAME/myshop.git .        # از Deploy Key فقط‌خواندنی استفاده کن

composer install --no-dev --optimize-autoloader
cp .env.example .env && nano .env                     # مقادیر پروداکشن
php artisan key:generate
php artisan migrate --force
php artisan storage:link
php artisan optimize

sudo chown -R www-data:www-data storage bootstrap/cache
sudo chmod -R ug+rwX storage bootstrap/cache
کدtext
# /etc/supervisor/conf.d/myshop-worker.conf
[program:myshop-worker]
command=php /var/www/myshop/artisan queue:work --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
user=www-data
numprocs=2
process_name=%(program_name)s_%(process_num)02d
stdout_logfile=/var/www/myshop/storage/logs/worker.log
stopwaitsecs=3600
کدbash
sudo supervisorctl reread && sudo supervisorctl update && sudo supervisorctl start 'myshop-worker:*'

# Cron برای Scheduler: sudo crontab -u www-data -e
* * * * * cd /var/www/myshop && php artisan schedule:run >> /dev/null 2>&1

اسکریپت دیپلوی تکرارپذیر

هر بار دستی دستور زدن یعنی روزی یک مرحله را فراموش می‌کنی. همه را در یک اسکریپت بگذار.

کدbash
#!/usr/bin/env bash
# /var/www/myshop/deploy.sh
set -euo pipefail
cd /var/www/myshop

php artisan down --retry=60          # صفحه‌ی «در حال به‌روزرسانی»

git fetch origin main
git reset --hard origin/main

composer install --no-dev --optimize-autoloader --no-interaction
php artisan migrate --force
php artisan optimize:clear
php artisan optimize

php artisan queue:restart            # Workerها کد جدید را لود کنند
php artisan up

echo "Deployed: $(git rev-parse --short HEAD)"
قبل از migrate بکاپ بگیر

مایگریشن‌هایی که ستون یا جدول را حذف می‌کنند برگشت‌ناپذیرند. قبل از هر دیپلوی مهم از دیتابیس بکاپ بگیر: mysqldump myshop | gzip > backup-$(date +%F).sql.gz. اگر مایگریشن نیاز دارد، کار را در دو دیپلوی تقسیم کن (اول افزودن ستون جدید، بعداً حذف قدیمی).

۶

بعد از انتشار

  • پایش: مسیر /up لاراول برای Health Check است؛ با UptimeRobot یا مشابه آن هر چند دقیقه چک کن و اعلان بگیر.
  • لاگ: storage/logs را مرتب ببین؛ برای سایت جدی از سرویس‌های خطایاب (مثل Sentry) استفاده کن.
  • بکاپ خودکار: Cron شبانه برای دیتابیس + فایل‌های آپلودی، نگهداری روی سرور دیگر، و تست بازیابی ماهانه.
  • صفحه‌های خطا: صفحه‌ی ۴۰۴/۵۰۰ فارسی و دوستانه بساز (resources/views/errors).
  • سئو و پایه‌ها: robots.txt، نقشه‌ی سایت، عنوان و توضیح صفحات، سرعت موبایل.
  • بازگشت (Rollback): نسخه‌ی قبل را با git reset --hard <commit> و اجرای دوباره‌ی اسکریپت برگردان؛ مایگریشن‌های مخرب را از قبل برنامه‌ریزی کن.

اشتباه‌های رایج

  1. گذاشتن کل پروژه (با .env) داخل public_html و دسترسی عمومی به اسرار.
  2. APP_DEBUG=true در پروداکشن.
  3. اجرای composer install بدون --no-dev و نصب ابزارهای توسعه روی سرور.
  4. فراموش‌کردن queue:restart و اجرای کد قدیمی در Worker.
  5. دسترسی ۷۷۷ برای همه‌چیز برای «رفع خطا».
  6. بدون بکاپ قبل از migrate.
  7. نداشتن راه بازگشت و دیپلوی مستقیم روی سرور بدون تست.
★

تمرین‌ها

تمرین ۱
  1. یک VPS آزمایشی (یا یک ماشین مجازی لوکال) بگیر، Nginx و PHP را نصب کن و پروژه‌ات را با یک دامنه‌ی تست بالا بیاور.
تمرین ۲
  1. اسکریپت deploy.sh را بنویس و تغییری کوچک را با آن منتشر کن.
  2. Supervisor و Cron را برای صف و Scheduler راه بینداز و یک Job را تست کن.
تمرین ۳
  1. بکاپ خودکار شبانه بنویس و یک‌بار آن را روی دیتابیس دیگر بازیابی کن تا مطمئن شوی کار می‌کند.
