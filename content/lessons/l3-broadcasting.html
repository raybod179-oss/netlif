Real-time چیست؟

در حالت عادی مرورگر باید مدام از سرور بپرسد «خبر جدیدی هست؟» (Polling). با WebSocket یک اتصال دائمی باز می‌ماند و سرور خودش خبر را می‌فرستد: وضعیت سفارش، پیام چت، اعلان فروش، تعداد کاربران آنلاین. لاراول این کار را با «Broadcasting» انجام می‌دهد: Eventهای سمت سرور را به‌صورت زنده به مرورگر می‌رساند.

روشتوضیح
Laravel Reverbسرور WebSocket رسمی لاراول؛ روی سرور خودت اجرا می‌شود (پیشنهاد این دوره)
Pusher / Ablyسرویس ابری آماده؛ بدون مدیریت سرور (بررسی دسترسی و هزینه از ایران با خودت)
Pollingساده‌ترین؛ هر چند ثانیه درخواست. برای نیاز کم کافی است
کدbash
php artisan install:broadcasting   # Reverb و Echo را (با سؤال‌های تعاملی) نصب می‌کند
php artisan reverb:start          # اجرای سرور WebSocket (در توسعه)
ایمن‌ترین شروع

اگر فقط وضعیت سفارش یا چند اعلان لازم داری و سرور مناسب نداری، Polling با wire:poll در Livewire هم کار را راه می‌اندازد؛ WebSocket وقتی لازم می‌شود که ترافیک و تعامل زنده زیاد باشد.

۳

Event قابل‌پخش

کدphp
<?php

namespace App\Events;

use App\Models\Order;
use Illuminate\Broadcasting\InteractsWithSockets;
use Illuminate\Broadcasting\PrivateChannel;
use Illuminate\Contracts\Broadcasting\ShouldBroadcast;
use Illuminate\Foundation\Events\Dispatchable;
use Illuminate\Queue\SerializesModels;

class OrderStatusChanged implements ShouldBroadcast
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(public Order $order) {}

    // کانال خصوصی مخصوص همین سفارش
    public function broadcastOn(): array
    {
        return [new PrivateChannel('orders.'.$this->order->id)];
    }

    public function broadcastAs(): string
    {
        return 'order.status';
    }

    // فقط داده‌ی لازم را بفرست (نه کل مدل)
    public function broadcastWith(): array
    {
        return [
            'id'     => $this->order->id,
            'status' => $this->order->status,
        ];
    }
}
کدphp
<?php

use App\Events\OrderStatusChanged;

// هر جا وضعیت عوض شد:
OrderStatusChanged::dispatch($order);
صف

ShouldBroadcast رویداد را از طریق صف می‌فرستد؛ پس Worker باید روشن باشد (php artisan queue:work). اگر می‌خواهی بلافاصله و بدون صف ارسال شود، ShouldBroadcastNow را پیاده کن.

مجوز کانال خصوصی

هر کسی که بتواند به کانال private-orders.15 وصل شود، رویدادهای آن سفارش را می‌شنود. مجوز را در routes/channels.php تعریف می‌کنیم؛ همان اصل Policy که در درس قبل دیدی.

کدphp
<?php

// routes/channels.php
use App\Models\Order;
use App\Models\User;
use Illuminate\Support\Facades\Broadcast;

Broadcast::channel('orders.{orderId}', function (User $user, int $orderId) {
    $order = Order::find($orderId);

    return $order && ($user->id === $order->user_id || $user->role === 'admin');
});
کانال عمومی فقط برای داده‌ی عمومی

برای هر چیز مربوط به کاربر یا پول از PrivateChannel و مجوز استفاده کن. Channel عمومی را هر کسی می‌شنود.

دریافت در مرورگر با Echo

کدjs
// resources/js/echo.js (install:broadcasting معمولاً می‌سازد)
import Echo from 'laravel-echo';
import Pusher from 'pusher-js';
window.Pusher = Pusher;

window.Echo = new Echo({
    broadcaster: 'reverb',
    key: import.meta.env.VITE_REVERB_APP_KEY,
    wsHost: import.meta.env.VITE_REVERB_HOST,
    wsPort: import.meta.env.VITE_REVERB_PORT ?? 80,
    wssPort: import.meta.env.VITE_REVERB_PORT ?? 443,
    forceTLS: (import.meta.env.VITE_REVERB_SCHEME ?? 'https') === 'https',
    enabledTransports: ['ws', 'wss'],
});
کدhtml
<span id="status">{{ $order->status }}</span>

<script type="module">
    // نقطه‌ی اول چون با broadcastAs اسم دلخواه داده‌ایم
    window.Echo.private('orders.{{ $order->id }}')
        .listen('.order.status', (e) => {
            document.getElementById('status').textContent = e.status;
        });
</script>
حضور آنلاین

با Echo.join('room') کانال Presence می‌سازی تا لیست کاربران آنلاین یا «در حال تایپ» را نشان بدهی؛ مجوزش هم در channels.php است و اطلاعات کاربر را برمی‌گرداند.

۶

روی سرور واقعی

  • Reverb باید همیشه روشن باشد؛ با Supervisor اجرایش کن (مثل Worker صف).
  • پشت Nginx با HTTPS: درخواست‌های WebSocket را پراکسی کن و از wss:// استفاده کن.
  • روی هاست اشتراکی معمولاً پروسه‌ی دائمی ممکن نیست؛ VPS لازم است.
  • پورت و فایروال را درست باز کن و کلیدها را عوض کن.
  • برای ترافیک بالا چند سرور: Redis برای مقیاس‌پذیری Reverb.

تست

کدphp
<?php

namespace Tests\Feature;

use App\Events\OrderStatusChanged;
use App\Models\Order;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Support\Facades\Event;
use Tests\TestCase;

class BroadcastTest extends TestCase
{
    use RefreshDatabase;

    public function test_status_change_event_is_dispatched(): void
    {
        Event::fake([OrderStatusChanged::class]);
        $order = Order::factory()->create();

        OrderStatusChanged::dispatch($order);

        Event::assertDispatched(OrderStatusChanged::class, fn ($e) => $e->order->is($order));
    }

    public function test_broadcast_payload_is_minimal(): void
    {
        $order = Order::factory()->create(['status' => 'paid']);

        $this->assertSame(
            ['id' => $order->id, 'status' => 'paid'],
            (new OrderStatusChanged($order))->broadcastWith()
        );
    }
}

کانال خصوصی کاربر، Presence و «در حال تایپ»

سه نوع کانال داریم: Public (همه)، Private (فقط کاربر مجاز) و Presence (خصوصی + معلوم‌بودن چه کسانی آنلاین‌اند).

کدphp
// routes/channels.php
use App\Models\User;
use Illuminate\Support\Facades\Broadcast;

// اعلان‌های هر کاربر فقط برای خودش
Broadcast::channel('App.Models.User.{id}', fn (User $user, int $id) => $user->id === $id);

// چت اتاق پشتیبانی: فقط اعضا؛ اطلاعات نمایشی کاربر را برگردان
Broadcast::channel('support.{ticketId}', function (User $user, int $ticketId) {
    return $user->canAccessTicket($ticketId)
        ? ['id' => $user->id, 'name' => $user->name]
        : false;
});
کدjs
// resources/js/echo.js: کانال Presence و «در حال تایپ»
const channel = Echo.join(`support.${ticketId}`);

channel
  .here(users => setOnline(users))
  .joining(user => addOnline(user))
  .leaving(user => removeOnline(user))
  .listen('MessageSent', e => addMessage(e.message))
  .listenForWhisper('typing', e => showTyping(e.name));

input.addEventListener('input', () => {
  channel.whisper('typing', { name: currentUser.name });   // مستقیم بین کلاینت‌ها؛ از Event سرور نمی‌گذرد
});

// اعلان‌های Notification (کانال database + broadcast)
Echo.private(`App.Models.User.${userId}`).notification(n => showToast(n.text));
Whisper

Whisper پیام را فقط بین مرورگرها می‌فرستد و در دیتابیس ذخیره نمی‌شود؛ مناسب «در حال تایپ…» و نشانگرهای لحظه‌ای است، نه داده‌ی مهم.

جزئیات Event: صف، فیلتر و جلوگیری از دوباره‌دیدن

کدphp
class MessageSent implements ShouldBroadcast   // ShouldBroadcastNow = بدون صف، فوری
{
    use Dispatchable, InteractsWithSockets, SerializesModels;

    public function __construct(public Message $message) {}

    public function broadcastOn(): array
    {
        return [new PresenceChannel('support.' . $this->message->ticket_id)];
    }

    public function broadcastAs(): string { return 'MessageSent'; }          // نام کوتاه در سمت JS

    public function broadcastWith(): array                                    // فقط داده‌ی لازم (نه کل مدل)
    {
        return [
            'message' => [
                'id'   => $this->message->id,
                'body' => $this->message->body,
                'user' => $this->message->user->only('id', 'name'),
                'at'   => $this->message->created_at->toIso8601String(),
            ],
        ];
    }

    public function broadcastWhen(): bool { return ! $this->message->is_internal; }   // یادداشت داخلی پخش نشود
}

// فرستنده‌ی پیام خودش دوباره آن را نمی‌بیند
broadcast(new MessageSent($message))->toOthers();
  • ShouldBroadcast رویداد را به صف می‌فرستد؛ پس Worker باید روشن باشد. در توسعه می‌توانی ShouldBroadcastNow بگذاری.
  • هرگز داده‌ی حساس (ایمیل، شماره، توکن) را در broadcastWith نگذار؛ هر که به کانال دسترسی دارد می‌بیند.
  • toOthers() هدر X-Socket-ID را می‌خواند؛ Echo آن را به‌صورت خودکار با درخواست‌های Axios می‌فرستد.
  • ساده‌ترین راه نصب در لاراول ۱۲: php artisan install:broadcasting که Reverb و Echo را آماده می‌کند.

Reverb در پروداکشن

کدbash
# اجرای دائمی با Supervisor
php artisan reverb:start --host=0.0.0.0 --port=8080

# بعد از هر استقرار
php artisan reverb:restart
کدnginx
# پراکسی WebSocket پشت Nginx (TLS روی Nginx تمام می‌شود)
location /app {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 120s;
}
location /apps {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
}
کدenv
BROADCAST_CONNECTION=reverb
REVERB_APP_ID=...        # با install:broadcasting ساخته می‌شود؛ حتماً مقدار تصادفی قوی
REVERB_APP_KEY=...
REVERB_APP_SECRET=...
REVERB_HOST=ws.example.com
REVERB_PORT=443
REVERB_SCHEME=https
REVERB_SERVER_HOST=0.0.0.0
REVERB_SERVER_PORT=8080
REVERB_SCALING_ENABLED=true   # فقط اگر چند سرور Reverb پشت Load Balancer داری (نیاز به Redis)
  • محدودیت تعداد فایل باز لینوکس (ulimit -n) برای هزاران اتصال هم‌زمان باید بالا باشد.
  • اگر WebSocket وصل نمی‌شود: پورت فایروال، Upgrade در Nginx و تطابق REVERB_* سمت سرور با VITE_REVERB_* سمت مرورگر را چک کن؛ بعد از تغییر env، npm run build را دوباره بزن.
  • پیش‌نیاز مهم: Worker صف و Reverb هر دو باید زنده باشند. بدون Worker رویدادها هیچ‌وقت پخش نمی‌شوند.
  • اگر نمی‌خواهی سرور WebSocket خودت را مدیریت کنی، سرویس‌های میزبانی‌شده (Pusher-سازگار) هم هست؛ فقط BROADCAST_CONNECTION و کلیدها عوض می‌شود.
۱۱

اشتباه‌های رایج

  1. فراموش‌کردن queue:work و تعجب از اینکه رویداد نمی‌رسد.
  2. کانال عمومی برای داده‌ی خصوصی.
  3. فرستادن کل مدل در broadcastWith و نشت ستون‌های حساس.
  4. فراموش‌کردن نقطه‌ی ابتدای نام در .listen('.order.status') وقتی از broadcastAs استفاده کرده‌ای.
  5. افشای REVERB_APP_SECRET در فرانت‌اند.
  6. اجرا نکردن Reverb روی سرور (یا بدون Supervisor).
  7. فراموشی Worker صف؛ رویداد ShouldBroadcast هرگز پخش نمی‌شود.
  8. ریختن کل مدل (با فیلدهای حساس) در Event به‌جای broadcastWith.
  9. فراموش‌کردن احراز هویت کانال در routes/channels.php و باز گذاشتن کانال خصوصی برای همه.
★

تمرین‌ها

تمرین ۱
  1. وضعیت سفارش را زنده کن: وقتی ادمین وضعیت را عوض می‌کند، صفحه‌ی مشتری بدون رفرش به‌روز شود.
تمرین ۲
  1. مجوز کانال را تست کن: کاربر دیگر نتواند به کانال سفارش غریبه گوش دهد.
  2. یک اعلان زنده‌ی «سفارش جدید» برای پنل ادمین (کانال خصوصی ادمین‌ها) بساز.
تمرین ۳
  1. اگر Reverb برایت سخت بود، همان صفحه را با wire:poll.5s پیاده کن و تفاوت پیچیدگی را مقایسه کن.
تمرین ۴
  1. یک اتاق پشتیبانی بساز که با کانال Presence نشان دهد چه کسانی آنلاین‌اند و با Whisper «در حال تایپ…» نمایش دهد.
  2. یک Notification را با کانال database و broadcast بفرست و در UI زنگوله‌ی بدون رفرش بساز.
تمرین ۵
  1. Reverb را پشت Nginx با TLS روی یک VPS آزمایشی راه بینداز و با ابزار Network مرورگر وضعیت اتصال WebSocket (کد ۱۰۱) را ببین.
