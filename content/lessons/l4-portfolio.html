پورتفولیو چه کاری باید بکند؟

کارفرما یا مصاحبه‌کننده در چند دقیقه می‌خواهد بفهمد: «این آدم واقعاً می‌تواند کار کند؟». رزومه ادعاست؛ پورتفولیو مدرک است. پورتفولیوی خوب سه چیز را ثابت می‌کند: می‌توانی چیزی بسازی، کدت تمیز است و می‌توانی آن را منتشر و توضیح بدهی.

۲

کدام پروژه‌ها؟

سه تا چهار پروژه‌ی خوب از ده پروژه‌ی نصفه بهتر است. پیشنهاد:

  1. فروشگاه کامل: محصول، سبد، سفارش، پرداخت (حالت آزمایشی)، پنل ادمین.
  2. یک پروژه‌ی API: با Sanctum، Resource و مستندات (برای نشان‌دادن توان بک‌اند).
  3. پروژه‌ی خودت: چیزی که از ایده‌ی خودت درآمده (حتی کوچک)؛ بیشترین اثر را روی مصاحبه‌کننده دارد.
  4. یک پکیج کوچک در Packagist (درس قبل) یا مشارکت در پروژه‌ی متن‌باز.
صادق باش

پروژه‌های دوره را می‌توانی در پورتفولیو بگذاری، ولی همان‌طور که هست نگذار. حداقل چند قابلیت واقعی خودت اضافه کن، طراحی را شخصی کن و در README دقیق بنویس چه چیزی از دوره بود و چه چیزی را خودت ساختی. ادعای «پروژه‌ی مشتری» برای کار آموزشی دروغ است و در مصاحبه با یک سؤال لو می‌رود.

README: ویترین هر پروژه

مصاحبه‌کننده معمولاً فقط README را می‌خواند. این قالب را شخصی کن:

کدmarkdown
# نام پروژه

یک جمله: این پروژه چیست و چه مشکلی را حل می‌کند.

[دمو زنده](https://...) · ![CI](badge-url)

## تصاویر
(۲ تا ۳ اسکرین‌شات یا یک GIF کوتاه)

## قابلیت‌ها
- سبد خرید و ثبت سفارش با کنترل موجودی (تراکنش + قفل)
- پرداخت آنلاین با Verify سرور به سرور
- پنل ادمین با نقش‌ها و Policy
- API با Sanctum

## تکنولوژی‌ها
Laravel 12، MySQL، Livewire، Tailwind، Pest/PHPUnit، GitHub Actions

## چالش‌ها و تصمیم‌ها
- چرا از Action به‌جای کنترلر چاق استفاده کردم
- چطور N+1 را پیدا و رفع کردم (۵۰ کوئری ← ۳ کوئری)

## اجرا روی سیستم خودت
```bash
git clone ...
composer install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed
php artisan serve
```

## تست
`php artisan test`

## ورود آزمایشی
ادمین: admin@example.com / password (فقط در حالت دمو)
  • بخش «چالش‌ها و تصمیم‌ها» مهم‌ترین قسمت است؛ نشان می‌دهد فکر می‌کنی، نه فقط کد کپی می‌کنی.
  • فقط عددهایی را بنویس که واقعاً اندازه گرفته‌ای.
  • .env.example و Seeder بگذار تا کسی بتواند با دو دستور پروژه را اجرا کند.
  • هرگز .env واقعی، کلید API یا داده‌ی مشتری واقعی در ریپو نباشد.

پروفایل GitHub و لینکدین

  • README پروفایل: ریپوی هم‌نام کاربری بساز و در آن خودت، مهارت‌ها و پروژه‌های برتر را معرفی کن.
  • پروژه‌های اصلی را در GitHub Pin کن و بقیه‌ی ریپوهای نیمه‌کاره را Private یا Archive کن.
  • عکس و عنوان روشن: «Laravel Developer»؛ ۲ تا ۳ جمله‌ی خلاصه با تمرکز بر نتیجه.
  • در لینکدین هر پروژه را با لینک و یک خط نتیجه بنویس؛ پست کوتاه از آنچه یاد گرفته‌ای (مثلاً «چطور N+1 را رفع کردم») اعتبار می‌سازد.
سایت شخصی

یک صفحه‌ی ساده با معرفی، سه پروژه (عکس + لینک دمو + لینک GitHub) و راه تماس کافی است. می‌توانی آن را با Laravel یا یک صفحه‌ی ایستا بسازی و روی دامنه‌ی خودت منتشر کنی (درس انتشار).
