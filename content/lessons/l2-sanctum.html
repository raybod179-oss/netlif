Sanctum چیست و کجا به کار می‌آید؟

وقتی اپ موبایل یا یک فرانت جدا به API وصل می‌شود، کوکی و Session مرورگر در کار نیست. Sanctum سبک‌ترین راه رسمی لاراول برای این کار است: کاربر با ایمیل و رمز وارد می‌شود و یک توکن می‌گیرد؛ در هر درخواست بعدی توکن را در هدر می‌فرستد.

حالتمناسب برایروش
توکن شخصیاپ موبایل، سرویس‌های دیگرهدر Authorization: Bearer ...
SPA با کوکیفرانت React/Vue روی دامنه‌ی هم‌خانوادهکوکی Session و CSRF (در همین درس مرور می‌شود)
کدbash
php artisan install:api      # Sanctum را نصب و migration توکن‌ها را آماده می‌کند
php artisan migrate

ثبت‌نام، ورود و خروج با توکن

کدphp
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

class AuthController extends Controller
{
    public function register(Request $request): JsonResponse
    {
        $data = $request->validate([
            'name'     => ['required', 'string', 'max:100'],
            'email'    => ['required', 'email', 'unique:users,email'],
            'password' => ['required', 'string', 'min:8', 'confirmed'],
        ]);

        $user = User::create($data);   // اگر cast 'hashed' روی password هست، خودکار هش می‌شود

        return response()->json([
            'user'  => $user->only('id', 'name', 'email'),
            'token' => $user->createToken('mobile')->plainTextToken,
        ], 201);
    }

    public function login(Request $request): JsonResponse
    {
        $request->validate([
            'email'       => ['required', 'email'],
            'password'    => ['required'],
            'device_name' => ['nullable', 'string', 'max:60'],
        ]);

        $user = User::where('email', $request->email)->first();

        if (! $user || ! Hash::check($request->password, $user->password)) {
            // پیام یکسان برای «کاربر نیست» و «رمز غلط»: به مهاجم سرنخ نمی‌دهد
            throw ValidationException::withMessages(['email' => ['ایمیل یا رمز عبور درست نیست.']]);
        }

        return response()->json([
            'token' => $user->createToken($request->device_name ?? 'api')->plainTextToken,
        ]);
    }

    public function logout(Request $request): JsonResponse
    {
        $request->user()->currentAccessToken()->delete();   // فقط توکن همین دستگاه

        return response()->json(['message' => 'خارج شدی']);
    }

    public function logoutAll(Request $request): JsonResponse
    {
        $request->user()->tokens()->delete();               // همه‌ی دستگاه‌ها

        return response()->json(['message' => 'از همه‌ی دستگاه‌ها خارج شدی']);
    }
}
کدphp
<?php

// routes/api.php
use App\Http\Controllers\Api\AuthController;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;

Route::post('/register', [AuthController::class, 'register'])->middleware('throttle:10,1');
Route::post('/login', [AuthController::class, 'login'])->middleware('throttle:10,1');

Route::middleware('auth:sanctum')->group(function () {
    Route::get('/user', fn (Request $request) => $request->user());
    Route::post('/logout', [AuthController::class, 'logout']);
    Route::post('/logout-all', [AuthController::class, 'logoutAll']);
});
توکن فقط یک‌بار دیده می‌شود

plainTextToken فقط همان لحظه‌ی ساخت قابل مشاهده است؛ در دیتابیس فقط هش آن ذخیره می‌شود. کلاینت باید آن را امن نگه دارد (در اپ موبایل Keychain/Keystore، نه جایی ساده). حتماً سایت را روی HTTPS ببری؛ توکن روی HTTP قابل شنود است.

کدbash
curl -X POST http://localhost:8000/api/login \
  -H "Accept: application/json" -H "Content-Type: application/json" \
  -d '{"email":"ali@example.com","password":"secret1234"}'
# ← {"token":"1|AbCdEf..."}

curl http://localhost:8000/api/user \
  -H "Accept: application/json" \
  -H "Authorization: Bearer 1|AbCdEf..."

اگر توکن نباشد یا نامعتبر باشد، پاسخ 401 Unauthenticated می‌گیری (به شرطی که هدر Accept: application/json را فرستاده باشی).

Ability: توکن با دسترسی محدود

می‌توانی هنگام ساخت توکن مشخص کنی چه کارهایی را اجازه دارد؛ مثلاً توکنی که فقط سفارش‌ها را بخواند.

کدphp
<?php

$token = $user->createToken('report-bot', ['orders:read'])->plainTextToken;

// داخل کنترلر
if (! $request->user()->tokenCan('orders:read')) {
    abort(403);
}

// یا با middleware (alias آن‌ها را در bootstrap/app.php ثبت کن)
// Route::get('/orders', ...)->middleware(['auth:sanctum', 'abilities:orders:read']);
کدphp
<?php

// bootstrap/app.php  (فقط بخش alias را به فایل خودت اضافه کن)
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Laravel\Sanctum\Http\Middleware\CheckAbilities;
use Laravel\Sanctum\Http\Middleware\CheckForAnyAbility;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        $middleware->alias([
            'abilities' => CheckAbilities::class,      // همه‌ی abilityها لازم است
            'ability'   => CheckForAnyAbility::class,  // یکی کافی است
        ]);
    })
    ->withExceptions(function (Exceptions $exceptions) {
        //
    })->create();
انقضا

در config/sanctum.php مقدار expiration را (به دقیقه) تنظیم کن تا توکن‌ها خودکار باطل شوند؛ یا هنگام ساخت، تاریخ انقضا بده: createToken('x', ['*'], now()->addDays(30)). برای اپ‌های حساس (پرداخت) توکن کوتاه‌مدت بهتر است.

حالت SPA با کوکی (مرور)

اگر فرانت‌اند (React/Vue) روی همان دامنه‌ی اصلی یا زیردامنه‌اش است، به‌جای توکن می‌توان از کوکی Session استفاده کرد: ابتدا GET /sanctum/csrf-cookie سپس ورود. تنظیمات مهم: SANCTUM_STATEFUL_DOMAINS و SESSION_DOMAIN در .env و supports_credentials در CORS. چون این مسیر به فرانت‌اند وابسته است، پیکربندی دقیق را از مستندات رسمی دنبال کن.

تست API احراز هویت‌شده

کدphp
<?php

namespace Tests\Feature;

use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Laravel\Sanctum\Sanctum;
use Tests\TestCase;

class AuthApiTest extends TestCase
{
    use RefreshDatabase;

    public function test_guest_gets_401(): void
    {
        $this->getJson('/api/user')->assertUnauthorized();
    }

    public function test_user_can_login_and_get_token(): void
    {
        User::factory()->create(['email' => 'a@b.com', 'password' => 'secret1234']);

        $this->postJson('/api/login', ['email' => 'a@b.com', 'password' => 'secret1234'])
             ->assertOk()
             ->assertJsonStructure(['token']);
    }

    public function test_authenticated_user_sees_profile(): void
    {
        Sanctum::actingAs(User::factory()->create(), ['*']);

        $this->getJson('/api/user')->assertOk();
    }
}

کدphp
// ساخت توکن برای هر دستگاه با نام و Ability مشخص
$token = $user->createToken($request->input('device_name', 'mobile'), ['orders:read', 'orders:create'], now()->addDays(30));
return ['token' => $token->plainTextToken];

$request->user()->currentAccessToken()->delete();

$request->user()->tokens()->delete();

// فهرست دستگاه‌ها برای صفحه‌ی «نشست‌های من»
$request->user()->tokens()->get(['id', 'name', 'last_used_at', 'created_at']);

کدphp
// routes/console.php: پاک‌کردن توکن‌های منقضی‌شده

سخت‌کردن ورود و جلوگیری از حمله‌ی حدس رمز

کدphp
// محدودیت نرخ ورود بر اساس ایمیل + IP
RateLimiter::for('login', function (Request $request) {
    return Limit::perMinute(5)->by(strtolower($request->input('email')) . '|' . $request->ip());
});

Route::post('/login', [AuthController::class, 'login'])->middleware('throttle:login');

public function login(Request $request)
{
    $credentials = $request->validate(['email' => 'required|email', 'password' => 'required']);

    if (! Auth::attempt($credentials)) {
        // پیام یکسان؛ نگو «ایمیل وجود ندارد»
        return response()->json(['message' => 'اطلاعات ورود نادرست است'], 422);
    }

    $user = $request->user();
    $user->tokens()->where('name', $request->input('device_name', 'mobile'))->delete();   // توکن قبلی همان دستگاه
    return ['token' => $user->createToken($request->input('device_name', 'mobile'))->plainTextToken];
}
  • پیام خطا نباید فرق «کاربر نیست» و «رمز غلط است» را لو بدهد.
  • همه‌چیز فقط روی HTTPS؛ توکن روی HTTP قابل‌شنود است.
  • توکن را در لاگ نریز: هدر Authorization را در لاگ‌ها ماسک کن.
  • برای ورود با OTP موبایل هم همین الگو را با محدودیت نرخ شدیدتر (مثلاً ۳ درخواست در ۱۰ دقیقه) بساز.

تنظیمات SPA و خطاهای معمول ۴۱۹ و ۴۰۱

علامتعلت معمولراه‌حل
419 CSRF token mismatchاول /sanctum/csrf-cookie صدا زده نشده یا کوکی روی دامنه‌ی دیگر استاول GET /sanctum/csrf-cookie؛ withCredentials: true در Axios

SPA یا موبایل؟

برای SPA هم‌دامنه از حالت کوکی/نشست Sanctum استفاده کن؛ توکن را در localStorage نگه نداری (با XSS قابل سرقت است). حالت Token برای اپ‌های موبایل و کلاینت‌های بیرونی است.

۱۱

اشتباه‌های رایج

  1. فرستادن توکن بدون کلمه‌ی Bearer (با فاصله).
  2. فراموش‌کردن HasApiTokens و خطای «createToken undefined».
  3. پیام‌های خطای متفاوت برای ایمیل نامعتبر و رمز اشتباه (کمک به حمله).
  4. ذخیره‌ی توکن در جای ناامن کلاینت و HTTP بدون TLS.
  5. نداشتن throttle روی login (حمله‌ی حدس رمز).
  6. ندادن انقضا به توکن‌ها و باقی‌ماندن توکن‌های قدیمی.
  7. توکن بدون انقضا و بدون ماژول لغو بعد از تغییر رمز.
  8. قراردادن توکن در localStorage در SPA.
  9. supports_credentials=false و ندیدن علت خطای CORS/۴۱۹.
★

تمرین‌ها

تمرین ۱
  1. مسیرهای register، login، logout و /user را با Postman تست کن و توکن را در هدر بفرست.
  2. تستی بنویس که پس از logout، همان توکن ۴۰۱ بدهد.
تمرین ۲
  1. مسیر GET /api/my-orders بساز که فقط سفارش‌های کاربر فعلی را برگرداند (با Resource).
  2. یک توکن با ability فقط‌خواندنی بساز و مطمئن شو نمی‌تواند سفارش بسازد.
تمرین ۳
  1. صفحه‌ی «دستگاه‌های من» بساز که $user->tokens را (نام و آخرین استفاده) نشان بدهد و امکان حذف هر توکن.
تمرین ۴
  1. صفحه‌ی «دستگاه‌های من» بساز که توکن‌ها را فهرست کند و دکمه‌ی «خروج از این دستگاه» داشته باشد.
  2. انقضای ۷ روزه برای توکن‌ها بگذار و یک تست بنویس که توکن منقضی ۴۰۱ می‌دهد.
تمرین ۵
  1. محدودیت نرخ ورود (۵ بار در دقیقه) را اضافه کن و با یک تست ثابت کن بار ششم ۴۲۹ می‌دهد.
