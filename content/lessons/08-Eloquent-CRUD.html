۱

Eloquent چیست؟ ORM یعنی چه؟

ORM یعنی «نقشه‌گر شیء-رابطه». به‌زبانِ ساده: هر جدولِ دیتابیس یک کلاسِ PHP دارد (به آن مدل می‌گوییم) و هر ردیفِ آن جدول، یک نمونه‌ی (instance) از همان کلاس است. به‌جای نوشتن SQL:

جدول products ⇄ مدل Product ⇄ کدِ PHP ما
کدEloquent در برابر SQL
# SQL
SELECT * FROM products WHERE is_active = 1 ORDER BY price DESC;

# Eloquent — همان کار
$products = Product::where('is_active', true)->orderByDesc('price')->get();
  • متدها روی خودِ کلاس مدل صدا زده می‌شوند: Product::all()، Product::where(...).
  • نتیجه‌ی چندردیفی یک Collection است (مثل آرایه، ولی با ابزارهای بیشتر)؛ با foreach می‌چرخد.
  • نتیجه‌ی تکی، یک «مدل» است؛ ستون‌ها به‌صورت $product->name در می‌آیند.
ارکانِ تا این‌جا

درس ۰۷ «جدول» را می‌سازد (migration) و درس ۰۸ «کلاسِ» آن را (model). اینکه از مدل چطور پرس‌وجو کنیم همین همین‌جا یاد می‌گیری؛ درس ۰۹ روابطِ جدول‌ها را (category ⇄ product) کامل می‌کند.

۲

ساخت مدل: make:model -m

$ php artisan make:model Product CREATED app/Models/Product.php

و اگر بخواهی مایگریشنش هم ساخته شود (در همان لحظه):

$ php artisan make:model Product -m CREATED app/Models/Product.php CREATED database/migrations/2026_09_07_123456_create_products_table.php
کدapp/Models/Product.php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;

class Product extends Model
{
    // می‌بینی؟ همین. Eloquent بقیه‌اش را بر عهده می‌گیرد.
}
  • مدل‌ها در app/Models/ می‌نشینند و از Model ارث می‌برند.
  • -m (= --migration) هم فایل مایگریشنِ مربوطه را می‌سازد. در پروژه‌ی ما مایگریشنِ products را در درس ۰۷ ساخته‌ایم؛ پس فقط make:model Product کافی است.
  • ترفند ترکیبی: make:model Product -m یا حتی -mfc (مدل + مایگریشن + کنترلر).
۳

قراردادهای Eloquent

Eloquent «رایگان» چیزها را از نامِ کلاس حدس می‌زند. این سه قرارداد را حفظ کن تا معجزه‌اش را ببینی:

حدس زده می‌شودمثالتوضیح
نام جدولProduct → جدولِ productsاسمِ جمعِ snake_case از اسمِ کلاس
کلید اصلیidستونِ id، خودافزایش
زمان‌هاcreated_at/updated_atخودکار پر می‌شود (timestamps())

اگر جدولی از این قرارداد خارج بود، در لاراول ۱۳ با PHP Attribute صریحش کن (همان‌ها که در درس ۰۱ دیدی):

کدمثالِ تعیینِ صریح
use Illuminate\Database\Eloquent\Attributes\Table;

#[Table('store_products', key: 'product_id')]
class Product extends Model
{
    // ...
}
چرا خوب است؟

چون مدل «بی‌دردسر» می‌ماند. با همان قراردادِ پیش‌فرض، جدولِ products از درس ۰۷ دقیقاً با مدلِ Product جفت می‌شود — بدون هیچ کد اضافه.

۴

خواندن: all / find / findOrFail / first

کدPHP
use App\Models\Product;

// همه‌ی ردیف‌ها (بازگشت: Collection)
$all = Product::all();

// یک ردیفِ مشخص با کلید اصلی (بازگشت: مدل یا null)
$found = Product::find(7);

$only   = Product::find([3, 5]);   // چندتا با هم (Collection)
$first  = Product::first();        // اولینِ ردیفِ جدول
$byName = Product::where('name', 'کفش')->first(); // اولینِ منطبق
  • find(n) اگر نباشد null برمی‌گرداند؛ first() هم همین‌طور.
  • findOrFail(n) اگر پیدا نشود، خطای ۴۰۴ می‌دهد — برای روت‌ها عالی است (درس ۰۸ هم هست).
  • هر «مدل» ستون‌ها را با $product->price در اختیارت می‌گذارد.

برای تستِ سریعِ همه‌چیز، Tinker قلابِ شماست — یک «خطِ فرمانِ تعاملی» برای کدِ لاراول:

$ php artisan tinker >>> $p = App\Models\Product::find(1); => App\Models\Product {#1234 id: 1, name: "کفش ورزشی", price: 250000, category_id: 1, } >>> $p->name; => "کفش ورزشی" >>> $p->created_at; => Illuminate\Support\Carbon @... "2026-09-07 14:33:00"
Tinker کجای کار است؟

هر چیزی که قرار است در کنترلر بنویسی، اول در Tinker امتحان کن؛ بدون ساختِ صفحه، بدون فرم، فقط درست بودنِ منطق. این عادت خیلی از خطاهای توسعه را می‌خورد.

۵

فیلتر و ترتیب: where / orderBy / limit

مدل در واقع یک «کوئری‌بیلدرِ توانمند» است؛ روش‌های شرط، ترتیب و محدودیت را به‌صورتِ زنجیره‌ای می‌بندی و آخرش با get() اجرا می‌کنی:

کدPHP
// فقط فعال‌ها، ارزان‌ترین اول
$products = Product::where('is_active', true)
    ->orderBy('price')
    ->get();

// دسته‌های ۱ و ۲، گران‌ترین ها با برش به ۱۰
$tops = Product::whereIn('category_id', [1, 2])
    ->orderByDesc('price')
    ->limit(10)
    ->get();

// فقط اسم و قیمت بیایند (به‌جای همه‌ی ستون‌ها)
$light = Product::where('is_active', true)
    ->select('id', 'name', 'price')
    ->get();

// شمارش ساده
$count = Product::where('category_id', 1)->count();
متدکار
where('col', $value)مساوی؛ با عملگر: where('price', '>', 100)
whereIn('col', [آرایه])عضوِ لیست‌ بودن
orderBy('col', 'desc')ترتیب؛ با میان‌برِ orderByDesc
limit(n)برشِ نتیجه
get()اجرا و گرفتنِ Collection
جرئی مهم

زنجیره‌ها اجرا نمی‌شوند مگر با get() (یا first() و...). یادت باشد: «ساختِ کوئری» با «اجرای کوئری» دو چیز است؛ بدون get() فقط مدلِ کوئری‌بیلدر را ساخته‌ای.

۶

ساخت: save() و create() و Mass Assignment

راه اول — قدم‌به‌قدم: نمونه بساز، فیلدها را بده، save() کن:

کدPHP
$product = new Product;

$product->name        = 'کتاب لاراول';
$product->description = 'مرجع کامل';
$product->price       = 350000;
$product->category_id = 1;

$product->save();   // INSERT انجام می‌شود و timestamps پر می‌شوند

راه دوم — یک‌خطی: با create() و یک آرایه:

کدPHP
$product = Product::create([
    'name'        => 'کتاب لاراول',
    'description' => 'مرجع کامل',
    'price'       => 350000,
    'category_id' => 1,
]);

create() آرایه‌ی ورودی را در یک‌جا به مدل می‌ریزد — به این «پرکردنِ گروهی» (Mass Assignment) می‌گویند. و چون همه‌چیز را یکجا می‌پذیرد، لاراول به‌صورتِ پیش‌فرض فقط فیلدهایی را می‌پذیرد که تو اجازه داده‌ای. در لاراول ۱۳ این اجازه با PHP Attribute است:

کدapp/Models/Product.php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Model;

#[Fillable(['name', 'description', 'price', 'category_id', 'is_active'])]
class Product extends Model
{
    // هر فیلدی این‌جا نباشد، از create()/fill() پذیرفته نمی‌شود.
}
چرا لازم است؟ امنیت

معکوسش را تصور کن: یک کاربرِ بدجنس created_at یا is_active را از داخلِ فرم تزریق کند. با #[Fillable] فقط فیلدهای سفیدِ تو پذیرفته می‌شوند؛ بقیه بی‌صدا دور ریخته می‌شوند. (جایگزین: #[Guarded([...])] برای «همه‌چیز جز این چندتا».)

نسخه‌های قدیمی‌تر

در آموزش‌های قدیمی می‌بینی: protected $fillable = ['name', ...]; (خاصیتِ PHP). در لاراول ۱۳ استانداردِ داک، همان Attribute بالاست؛ ولی جفت‌باره کار می‌کند.

۷

ویرایش و حذف: update() / delete()

ویرایش: اول مدلِ موردنظر را بگیر، بعد مقدار بده و ذخیره کن — یا یک‌جا با update():

کدPHP
$product = Product::find(2);

$product->price = 390000;
$product->save();                       // UPDATE انجام می‌شود

// یا یک‌لوپ:
Product::find(2)->update(['price' => 390000]);

حذف:

کدPHP
$product = Product::find(2);
$product->delete();                    // حذفِ تکی

Product::destroy(3);                    // حذف با کلید/کلیدها
Product::destroy([4, 5]);

Product::where('category_id', 2)->delete(); // حذفِ دسته‌ایِ شرطی
  • مثلِ create()، update() هم فقط فیلدهای #[Fillable] را می‌پذیرد.
  • حذفِ یک محصول، چون در مایگریشنِ درس ۰۷ cascadeOnDelete برای کلیدِ category_id گذاشتیم، فقط رویِ دسته‌بندی اثر می‌گذارد؛ اگر reviews هم با cascade ساخته باشی، آنها هم حذف می‌شوند.
۸

Route Model Binding با {product}

در درس ۰۳ یاد گرفتی پارامترِ روت را به‌صورتِ {id} بگیر و خودت findOrFail بزنی. لاراول ۱۳ استانداردِ بهتر دارد: Route Model Binding. کافی است در متدِ کنترلر، پارامتری به نامِ {product} با همین نامِ Product $product type-hint کنی:

کدroutes/web.php
Route::get('/products/{product}', [ProductController::class, 'show'])
    ->name('products.show');
کدProductController.php
<?php

namespace App\Http\Controllers;

use App\Models\Product;
use Illuminate\Contracts\View\View;

class ProductController extends Controller
{
    public function show(Product $product): View
    {
        return view('products.show', ['product' => $product]);
    }
}
  • لاراول خودش Product::findOrFail را با مقدارِ {product} در مسیر انجام می‌دهد؛ اگر نبود، ۴۰۴ می‌دهد.
  • اسمِ پارامترِ مسیر ({product}) باید دقیقاً با نامِ آرگومانِ متد ($product) یکی باشد.
  • این الگو برای «متدهایی که یک رکورد می‌گیرند» است: show، update، destroy — همان که در doc می‌خوانی.
  • اگر کلیدِ دیگری می‌خواهی (مثلاً slug) یا با ->withTrashed() بخواهی جست‌وجو کنی، روش‌های سفارشی‌سازی در داک هست.
چرا استاندارد؟

دیگر در هیچ‌جا «id را بگیر و find کن» نمی‌نویسی؛ ماشینِ ۴۰۴، تزریقِ مدل و تمیزیِ کد همه یکجا هدیه‌ گرفته می‌شوند. در درس ۰۹ وقتی رابطه‌ها آمد، به همین $product می‌گویی «دسته‌بندی‌ات را بده».

۹

گام پروژه: کنترلرِ واقعی محصول

نمونه‌ی CRUDِ درس ۰۳ حالا واقعی می‌شود

در درس ۰۳ یک «نمونه CRUD مینی» با آرایه داشتیم. حالا همان را با Eloquent و Route Model Binding بازنویسی می‌کنیم.

  1. مدل: php artisan make:model Product (مایگریشن را قبلاً داریم) و روی مدل #[Fillable([...])] را برای فیلدها بگذار.
  2. روت‌ها در web.php: products.index و products.show با /products و /products/{product}.
  3. در index(): $products = Product::where('is_active', true)->latest()->get(); و همان بلیدِ فهرستِ درس ۰۶؛ این‌بار <x-product-card :product="$product"/> داده‌ی واقعی می‌گیرد.
  4. در show(): با Product $product (Binding) صفحه‌ی جزئیات محصول.
  5. تست: با tinker سه محصول بساز، صفحه را رفرش کن — بدونِ حتی یک خط SQLِ دستی.
ادامه‌اش کجا؟

«ساخت/ویرایش/حذفِ واقعی» در درس ۱۰ (فرم‌ها و Validation) کامل می‌شود؛ «رابطه‌ی دسته‌بندی ⇄ محصول» و «لودِ رابطه‌ها» در درس ۰۹ است. الان اصالتِ Eloquent را بچش.

۱۰

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: مدلِ دسته‌بندی
  1. php artisan make:model Category بساز (مایگریشنِ جدولِ categories از درس ۰۷ موجود است).
  2. در Tinker دو دسته‌بندی بساز و با Category::all() آن‌ها را ببین.
  3. دستورِ Category::where('name', '...')->first() را امتحان کن.
تمرین ۲: پرس‌وجوی فیلترشده
  1. پنج محصول بساز (قیمت‌های متفاوت)، بعد با Product::whereIn('category_id', [1, 2]) فهرست بگیر.
  2. گران‌ترینِ فعال: Product::where('is_active', true)->orderByDesc('price')->first().
  3. برترین‌ها: همان با ->take(3)->get().
تمرین ۳: Binding را بچش
  1. روتِ /products/{product} با show(Product $product) بساز.
  2. به /products/99999 برو — باید صفحه‌ی ۴۰۴ ببینی، بی‌آنکه تو کدی نوشته باشی.
  3. در show، نامِ محصول و قیمتش را چاپ کن.
چالش

با Product::select('id','name','price') فقط سه ستون را بکش، در بلید با @foreach فهرست بده و از خودت بپرس: «حداقلِ کوئری» یعنی چه؟

چیزی که از این بخش توی ذهنت بماند

  1. هر جدول یک مدل است: make:model (با -m اگر مایگریشن هم لازم است).
  2. قراردادها: نامِ جدول = جمعِ snake_case کلاس؛ کلید = id؛ timestamps خودکار.
  3. خواندن: all()، find(n)، findOrFail(n)، first()؛ چندتا = Collection.
  4. فیلتر و ترتیب: where()، whereIn()، orderBy()، limit() — با get() اجرا کن.
  5. ساخت: new + save()، یا create([...])؛ فقط فیلدهای #[Fillable].
  6. ویرایش: update([...])؛ حذف: delete() / destroy(n).
  7. Route Model Binding: {product} + Product $product — ۴۰۴ خودکار و مدلِ آماده.
  8. Tinker را برای تستِ سریع نگه دار؛ یک خطا قبل از صفحه، ده‌برابر ارزان‌تر است.
