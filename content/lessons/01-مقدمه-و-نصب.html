۱

Laravel چیست؟

توی دوره‌ی HTML/CSS دیدی که مرورگر، صفحه را از یک سرور می‌گیرد. آن سرور با کدهایی که روی آن اجرا می‌شود، صفحه را می‌سازد. PHP یکی از زبان‌های همین «سمتِ سرور» است؛ ولی نوشتن همه‌چیز با PHPِ خام، طولانی و تکراری می‌شود. Laravel یک فریمورک PHP است؛ یعنی یک بسته‌ی آماده که خیلی از کارهای تکراری (مسیریابی، اتصال به دیتابیس، لاگین، قالب و...) را برایت پیاده کرده؛ تو فقط کدِ کارِ خودت را می‌نویسی.

تو (مرورگر)
کلاینت
⟵ درخواست
⟶ پاسخ
سرور PHP + Laravel
این‌جا صفحه ساخته می‌شود

چرا Laravel؟ چند تا از چیزهایی که از جعبه و بدون کدِ اضافه به تو می‌دهد:

  • مسیریابی تمیز (Routing) و کنترلرها
  • موتور قالب Blade برای ساخت ویو
  • Eloquent برای کار با دیتابیس، همراه با Migration و Seeder
  • احراز هویت (Auth) و کنترل دسترسی
  • دستیار خط‌فرمان Artisan

الگوی MVC؛ زبانِ مشترکِ همه‌ی فریمورک‌ها

تقریباً هر سایت لاراولی یک سفرِ درخواست را طی می‌کند: این‌که درخواستِ کاربر کجا می‌آید، چه کسی تصمیم می‌گیرد چه کاری انجام شود، از کجا داده بیاید و با کدام قالب نمایش داده شود. ترتیبِ این کارها در الگوی MVC خلاصه می‌شود که حرف اولِ سه کلمه است: Model (مدل)، View (ویو) و Controller (کنترلر).

چرا مهم است؟

مهم‌ترین فایده‌ی MVC این است که «کارها از هم جدا می‌مانند»: منطقِ دیتابیس، تصمیم‌گیری و ظاهرِ قالب هرکدام خانه‌ی خودشان را دارند. این یعنی وقتی ظاهرت را عوض می‌کنی، به کدِ دیتابیس دست نمی‌زنی. بقیه‌ی این دوره همین سه تا را یکی‌یکی یاد می‌گیریم.

فقط یک اشاره

نسخه‌های جدید Laravel (مثل ۱۳) هر سال چند قابلیت تازه هم اضافه می‌کنند؛ مثلاً SDK هوش مصنوعی یا پیکربندی مدل‌ها با PHP Attributes. این‌ها برای مرحله‌های بعدی است؛ فعلاً همین پایه‌ها را درست یاد بگیر.

۲

پیش‌نیازها و ابزارها

قبل از نصب، مطمئن شو این ابزارها روی سیستم‌ت هست. نسخه‌ی Laravel 13 به PHP 8.3 یا بالاتر نیاز دارد.

ابزار فرمانِ چک کردن چه‌کاری انجام می‌دهد؟
PHP 8.3+ php -v زبانِ اصلی برنامه؛ قائدتاً آن را بلدی
Composer composer -V مدیر پکیجِ PHP؛ با آن پروژه‌ی Laravel می‌سازی
دیتابیس (SQLite یا MySQL) — ذخیره‌ی داده‌ها؛ پیش‌فرض نسخه‌های جدید SQLite است
ادیتور کد — VS Code یا PHPStorm؛ برای نوشتن کد
نکته
  • اگر Composer را نداری، از getcomposer.org نصبش کن. اگر PHP را نداری، ساده‌ترین راه، نصب رسمی از php.new است.
  • دستور composer -V و php -v را توی ترمینال اجرا کن؛ اگر نسخه چاپ شد یعنی آماده‌ای. اگر خطای «شناخته نشد» گرفتی، مسیر نصب را به متغیر PATH سیستم اضافه کن.
۳

نصب Composer و ساخت اولین پروژه

با یک فرمان ساده می‌توانی یک پروژه‌ی کاملاً جدید Laravel با اسم دلخواهت بسازی. این فرمان یعنی: «یک پروژه‌ی Laravel از قالب رسمی laravel/laravel بساز و بگذار توی پوشه‌ی blog».

کدترمینال
composer create-project laravel/laravel blog
خروجی نمونهخلاصه
Creating a "laravel/laravel" project at "./blog" Installing laravel/laravel (v13.10.1) - Downloading laravel/laravel - Installing laravel/laravel ... > @php artisan key:generate --ansi Application key set successfully. ... (انتهای اجرا، چند خط دیگر؛ فقط با «...» خلاصه شده)

حالا وارد پوشه‌ی پروژه شو:

کدترمینال
cd blog
نکته
  • در زمان نصب، لاراول فایل .env را از روی .env.example می‌سازد و کلید امنیتی (APP_KEY) را هم خودش تولید می‌کند؛ دستی دست به این‌ها نزن.
  • ولی اگر بعداً بخواهی کلید را دوباره بسازی: php artisan key:generate.
  • جزئیات بیشتر در داکیومنت نصب لاراول.
۴

اجرای پروژه با php artisan serve

Artisan دستیارِ خط‌فرمانِ لاراول است (با همین php artisan شروع می‌شود). برای دیدن پروژه در مرورگر، کافی است سرورِ محلی را با serve روشن کنی:

کدترمینال
php artisan serve
خروجی نمونهخلاصه
INFO Server running on [http://127.0.0.1:8000]. Press Ctrl+C to stop the server

حالا مرورگر را باز کن و آدرس http://127.0.0.1:8000 را بزن. صفحه‌ی خوش‌آمدِ Laravel را می‌بینی؛ یعنی پروژه‌ات زنده است!

خروجی نمونهچه می‌بینی؟
Laravel
نوبتِ ساختنِ اولین پروژه‌ی تو رسیده
Laravel 13
دقت کن

این صفحه‌ی خوش‌آمد فقط «پیش‌فرض» پروژه است و ربطی به کارِ تو ندارد؛ آدرس ریشه (/) به یک قالبِ خوش‌آمد اشاره می‌کند. از بخش بعدی، خودمان روت‌های واقعی می‌سازیم و این صفحه را کنار می‌زنیم. برای خاموش کردن سرور، Ctrl + C را توی همان ترمینال بزن.

۵

ساختار پوشه‌ها

یک پروژه‌ی تازه‌ی Laravel یک ساختار مشخص دارد. لازم نیست همه‌چیز را حفظ کنی؛ فقط یادت باشد «هر چیزی کجاست» تا در درس‌های بعد، مسیرها را گم نکنی:

ساختارپوشه‌ها
blog/
├── app/          ← کدِ اصلی: کنترلرها، مدل‌ها، Middleware
├── bootstrap/    ← راه‌اندازی فریمورک + کش
├── config/       ← تنظیمات (app، database، mail و...)
├── database/     ← Migrationها، Seederها، Factoryها
├── public/       ← نقطه‌ی ورود index.php و فایل‌های عمومی
├── resources/    ← ویوهای Blade و دارایی‌های خام
├── routes/       ← مسیرها: web.php و console.php
├── storage/      ← لاگ، کش و فایل‌های تولیدشده
├── tests/        ← تست‌ها
└── vendor/       ← کتابخانه‌های نصب‌شده با Composer

چهار تایی که بقیه‌ی دوره خیلی سراغشان می‌رویم:

  • routes/web.php — مسیرهای سایت‌ت؛ بیا که همه‌چیز از این‌جا شروع می‌شود.
  • app/Http/Controllers — کنترلرها؛ منطقِ درخواست‌ها اینجا می‌نشیند.
  • resources/views — قالب‌های Blade؛ صفحه‌هایی که کاربر می‌بیند.
  • database/migrations — ساختار جدول‌های دیتابیس، در قالبِ کد.
  • public — فقط محتوای این پوشه روی سرور در دسترس عموم است (مثل عکس‌ها).
چرا این ساختار؟

این نظمِ قراردادِ لاراول است؛ کتابخانه‌ها، ابزارها و حتی تیم‌های دیگر می‌دانند هر چیزی کجاست. می‌توانی سازمان‌دهی را تغییر دهی ولی «کار» نکن؛ توی کورس اول‌پایه، طبق همین ساختار پیش می‌رویم. جزئیات در داکیومنت ساختار پوشه‌ها.

۶

فایل .env

تنظیماتی که بین «محیط‌ها» فرق می‌کند (محیطِ توسعه‌ی خودت، سرورِ عملیاتی و...) در کدِ برنامه قرار نمی‌گیرد؛ بلکه در فایل .env در ریشه‌ی پروژه نوشته می‌شود. به همین دلیل این فایل هرگز در گیت کامیت نمی‌شود — چون ممکن است رمزِ دیتابیس و تنظیماتِ حساس داشته باشد.

کد.env
APP_NAME=blog
APP_ENV=local
APP_KEY=base64:... (خودکار ساخته می‌شود)
APP_DEBUG=true
APP_URL=http://localhost

DB_CONNECTION=sqlite
# یا اگر با MySQL کار می‌کنی:
# DB_CONNECTION=mysql
# DB_HOST=127.0.0.1
# DB_PORT=3306
# DB_DATABASE=blog
# DB_USERNAME=root
# DB_PASSWORD=
متغیر چه‌کاری انجام می‌دهد؟
APP_DEBUG اگر خطایی رخ دهد جزئیاتش را نشان می‌دهد. در توسعه true، در عملیات حتماً false
APP_URL آدرس اصلی سایت‌ت (برای لینک‌هایی که بعداً می‌سازی)
DB_* تنظیمات اتصال دیتابیس؛ پیش‌فرضِ نسخه‌های جدید SQLite است
دقت کن

اگر APP_DEBUG=true روی سرورِ عملیاتی بماند، هر خطا تمام تنظیمات و رمزها را به کاربر نشان می‌دهد؛ این بزرگ‌ترین درس امنیتی این بخش است. جزئیات در داکیومنت تنظیمات.

۷

فرمان‌های پرکاربرد

Artisan مغزِ فرمان‌های لاراول است. با php artisan list می‌بینی چه فرمان‌هایی در دسترس است و با php artisan about یک نگاه کلی به وضعیت برنامه‌ات می‌اندازی:

کدترمینال
php artisan list

php artisan about
خروجی نمونهخلاصه
Environment ................................... local Application Name ................................. blog Application Version .............................. 13.10.1 PHP Version ...................................... 8.4.4 Composer Version ................................. 2.8.4 Database ......................................... sqlite Debug Mode ...................................... ON URL ............................................. http://localhost

اگر فقط یک بخش از این گزارش را بخواهی، می‌توانی فیلترش کنی:

کدترمینال
php artisan about --only=environment
نکته
  • خروجیِ about بسته به سیستم تو ممکن است اعداد دیگری نشان دهد؛ به همین شکل، «خلاصه» همین است و مشکلی نیست.
  • اشتباه تایپی و پیام خطا بخشی از کارِ برنامه‌نویسی است؛ بعداً با همین خطاها آشنا می‌شوی.
۸

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: اولین پروژه‌ات را بساز
  1. توی ترمینال فرمان composer create-project laravel/laravel blog را اجرا کن.
  2. وارد پوشه‌ی blog شو و php artisan serve را بزن.
  3. در مرورگر آدرس http://127.0.0.1:8000 را باز کن و صفحه‌ی خوش‌آمدِ Laravel را ببین.
  4. برای اطمینان php artisan about را هم اجرا کن.
تمرین ۲: ساختار را بشناس
  1. فایل routes/web.php را باز کن و اولین سطرهایش را بخوان؛ حدس بزن هر خط چه می‌گوید.
  2. فایل .env را باز کن و مقدار APP_DEBUG و DB_CONNECTION را پیدا کن.
  3. توی resources/views/ جستجو کن و ببین صفحه‌ای که همین حالا در مرورگر دیدی کدام فایل است.
چالش

در فایل .env مقدار APP_NAME را به چیزی مثل My First App تغییر بده و صفحه را رفرش کن؛ عنوانِ صفحه در تب مرورگر عوض می‌شود! (این یعنی .env واقعاً تنظیمات را مدیریت می‌کند.) بعد از آزمایش، مقدار قبل را برگردان.

پروژه‌ی این دوره: یک فروشگاه کوچک

از این به بعد، هر درس یک «گام پروژه» دارد تا دقیقاً همان چیزی را که یاد می‌گیری، روی یک پروژه‌ی واقعی پیاده کنی. پروژه‌ی ما در پایان دوره یک فروشگاه کوچک است: ثبت‌نام و ورود، محصول‌ها و دسته‌بندی، آپلود تصویر محصول و یک سبد خریدِ ساده (بدون پرداخت واقعی).

گامِ این درس فقط این است که بفهمی قرار است کجا برویم؛ از درسِ بعد (روتینگ) ساختِ واقعی شروع می‌شود.

چیزی که از این بخش توی ذهنت بماند

  1. Laravel یک فریمورک PHP برای سمتِ سرور است؛ پایه‌های آماده را به تو می‌دهد و تو فقط کارِ خودت را می‌نویسی.
  2. پروژه‌ی جدید = composer create-project laravel/laravel blog.
  3. اجرا با php artisan serve در آدرس http://127.0.0.1:8000؛ خاموشی با Ctrl+C.
  4. مسیرهای مهم: routes/web.php، app/Http/Controllers، resources/views و database/migrations.
  5. .env خانه‌ی تنظیمات محیطی است؛ هرگز در گیت کامیت نمی‌شود و APP_DEBUG در عملیات false است.
  6. همیشه مرجعِ رسمی و به‌روز: laravel.com/docs.
