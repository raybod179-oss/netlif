مبانی PHP ۳: شی‌گرایی (OOP)

اگر فقط یک درس PHP را جدی بخوانی باید همین باشد؛ چون لاراول از اول تا آخر شی‌گراست. آرام و قدم‌به‌قدم جلو می‌رویم و هر مفهوم را به یک تکه از لاراول وصل می‌کنیم.

۱

چرا شی‌گرایی؟

تا اینجا کد را به‌صورت «تابع و آرایه» نوشتیم. در پروژه‌های واقعی، داده و رفتارِ مرتبط را در یک بسته به نام کلاس کنار هم می‌گذاریم. شیء (Object) یک نمونه‌ی ساخته‌شده از آن کلاس است.

نکته‌ی مهم برای این دوره: در لاراول هر چیزی کلاس است؛ کنترلر، مدل، Middleware، ایمیل، Job. اگر این درس را خوب بفهمی، بقیه‌ی دوره بدون ترس جلو می‌رود.

مثال زندگی

کلاس مثل «نقشه‌ی ساختمان» است و شیء مثل «ساختمان ساخته‌شده». از یک نقشه می‌شود ده ساختمان ساخت که هرکدام رنگ و طبقه‌ی خودشان را دارند.

۲

کلاس، ویژگی و متد

کدphp
<?php
class Product
{
    public string $title;
    public int $price;

    // سازنده: هنگام ساخت شیء اجرا می‌شود
    public function __construct(string $title, int $price)
    {
        $this->title = $title;
        $this->price = $price;
    }

    public function priceWithTax(float $rate = 0.09): int
    {
        return (int) round($this->price * (1 + $rate));
    }
}

$a = new Product("کیبورد", 850000);
$b = new Product("ماوس", 420000);

echo $a->title, ": ", $a->priceWithTax(), "\n";
echo $b->title, ": ", $b->priceWithTax(0.2);
خروجیخروجی
کیبورد: 926500
ماوس: 504000

$this یعنی «همین شیء». فلش -> برای دسترسی به ویژگی یا متد است (در لاراول هزاران بار می‌بینی‌اش).

۳

سازنده‌ی کوتاه (Constructor Promotion) و readonly

کدphp
<?php
class Product
{
    public function __construct(
        public readonly string $title,
        public readonly int $price,
    ) {}
}

$p = new Product("هدفون", 1200000);
echo $p->title, "\n";

try {
    $p->price = 1;           // readonly است؛ خطا می‌دهد
} catch (Error $e) {
    echo "خطا: ", $e->getMessage();
}
خروجیخروجی
هدفون
خطا: Cannot modify readonly property Product::$price
readonly

برای داده‌هایی که بعد از ساخت نباید عوض شوند (مثل مبلغ یک سفارش) readonly جلوی باگ‌های ریز را می‌گیرد. کد لاراول مدرن زیاد از این سبک استفاده می‌کند.

سطح دسترسی: public، protected، private

کلمهاز کجا قابل دسترسی است؟
publicاز هرجا
protectedفقط خود کلاس و کلاس‌های فرزند
privateفقط خود کلاس
کدphp
<?php
class Wallet
{
    private int $balance = 0;       // بیرون نمی‌شود مستقیم تغییرش داد

    public function deposit(int $amount): void
    {
        if ($amount <= 0) {
            throw new InvalidArgumentException("مبلغ باید مثبت باشد");
        }
        $this->balance += $amount;
    }

    public function balance(): int
    {
        return $this->balance;
    }
}

$w = new Wallet();
$w->deposit(50000);
echo $w->balance();          // 50000
// $w->balance = 999;       // خطا! private است
خروجیخروجی
50000

به این کار می‌گویند «کپسوله‌سازی»: داده را پشت متدها پنهان می‌کنیم تا همیشه قوانین (مثل مثبت‌بودن مبلغ) رعایت شود. در پروژه‌ی مارکت‌پلیس همین الگو را برای کیف پول استفاده می‌کنیم.

۵

static و const

کدphp
<?php
class Order
{
    public const STATUS_PENDING = "pending";
    public const STATUS_PAID    = "paid";

    public static function statuses(): array
    {
        return [self::STATUS_PENDING, self::STATUS_PAID];
    }
}

echo Order::STATUS_PAID, "\n";
print_r(Order::statuses());

با :: بدون ساختن شیء به ثابت‌ها و متدهای static دسترسی داریم. وقتی در لاراول Route::get() یا User::where() می‌نویسی، همین :: است.

ارث‌بری، abstract و interface

کدphp
<?php
interface Payable
{
    public function pay(int $amount): bool;
}

abstract class Notifier
{
    abstract protected function send(string $to, string $text): void;

    public function welcome(string $to): void
    {
        $this->send($to, "به Rayvo خوش آمدید");
    }
}

class SmsNotifier extends Notifier
{
    protected function send(string $to, string $text): void
    {
        echo "SMS به $to: $text\n";
    }
}

class ZarinpalGateway implements Payable
{
    public function pay(int $amount): bool
    {
        echo "پرداخت $amount تومان\n";
        return true;
    }
}

(new SmsNotifier())->welcome("09120000000");
(new ZarinpalGateway())->pay(50000);
خروجیخروجی
SMS به 09120000000: به Rayvo خوش آمدید
پرداخت 50000 تومان
interface یعنی قرارداد

Payable می‌گوید «هر درگاهی باید متد pay داشته باشد». بعداً می‌توانی درگاه را عوض کنی بدون اینکه بقیه‌ی برنامه عوض شود؛ این مفهوم در درس‌های سطح ۲ و ۳ (درگاه پرداخت، Service) خیلی به کار می‌آید.

۷

Namespace، Trait و Enum

کدphp
<?php
namespace App\Models;

use InvalidArgumentException;

trait HasSlug
{
    public function slug(): string
    {
        return strtolower(str_replace(" ", "-", $this->title));
    }
}

enum Role: string
{
    case Admin = "admin";
    case Student = "student";

    public function label(): string
    {
        return match ($this) {
            self::Admin   => "مدیر",
            self::Student => "دانشجو",
        };
    }
}

class Post
{
    use HasSlug;
    public function __construct(public string $title) {}
}

echo (new Post("Hello World"))->slug(), "\n";
echo Role::from("admin")->label();
خروجیخروجی
hello-world
مدیر
  • Namespace: «پوشه‌بندی منطقی» اسم کلاس‌ها تا تداخل نکنند (مثل App\Models\User).
  • Trait: مجموعه‌ای از متدها برای استفاده‌ی مجدد داخل چند کلاس (در مدل‌های لاراول زیاد: HasFactory).
  • Enum: مجموعه‌ی محدود مقادیر ثابت، مثل نقش‌ها و وضعیت‌ها؛ از دست "paid" و "payed" و غلط املایی راحت می‌شوی.

گام پروژه: Product و Cart شی‌گرا

کدphp
<?php
declare(strict_types=1);

final class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $title,
        public readonly int $price,
    ) {}
}

final class Cart
{
    /** @var array<int, array{product: Product, qty: int}> */
    private array $items = [];

    public function add(Product $p, int $qty = 1): void
    {
        if ($qty < 1) throw new InvalidArgumentException("تعداد نامعتبر");
        $this->items[$p->id] ??= ["product" => $p, "qty" => 0];
        $this->items[$p->id]["qty"] += $qty;
    }

    public function total(): int
    {
        return array_sum(array_map(
            fn($i) => $i["product"]->price * $i["qty"],
            $this->items
        ));
    }

    public function count(): int
    {
        return array_sum(array_column($this->items, "qty"));
    }
}

$cart = new Cart();
$cart->add(new Product(1, "کیبورد", 850000));
$cart->add(new Product(2, "ماوس", 420000), 2);
$cart->add(new Product(2, "ماوس", 420000));   // یک عدد دیگر

echo "تعداد: ", $cart->count(), "\n";
echo "جمع: ", number_format($cart->total());
خروجیخروجی
تعداد: 4
جمع: 2,110,000
مقایسه با درس قبل

همان سبد خرید درس ۲ است، اما حالا قوانینش (حداقل تعداد، جمع‌زدن مشتری‌های تکراری) داخل خود کلاس نگه‌داری می‌شود و بقیه‌ی کد فقط add و total را صدا می‌زند.

۹

اشتباه‌های رایج

  1. فراموش کردن new و صدا زدن مستقیم کلاس.
  2. استفاده از . به‌جای -> برای دسترسی به ویژگی ($p.title غلط است).
  3. فراموش کردن $this-> داخل متد و ساخت متغیر محلی ناخواسته.
  4. همه‌چیز را public گذاشتن؛ از private شروع کن و فقط در صورت نیاز باز کن.
  5. کلاس‌های خیلی بزرگ که همه‌کاره‌اند؛ هر کلاس یک مسئولیت.
★

تمرین‌ها

تمرین ۱: کلاس User
  1. کلاس User با ویژگی‌های name و email بساز (سازنده‌ی کوتاه).
  2. متد initials() بنویس که حرف اول نام را برگرداند (با mb_substr).
تمرین ۲: Wallet
  1. به کلاس Wallet متد withdraw اضافه کن که اگر موجودی کافی نبود استثنا بدهد.
  2. خطا را با try/catch بگیر و پیام مناسب چاپ کن.
تمرین ۳: Enum وضعیت سفارش
  1. Enum به نام OrderStatus با سه حالت pending، paid، shipped بساز.
  2. متد label() برای نمایش فارسی هر وضعیت بنویس.
تمرین ۴: Interface
  1. اینترفیس Logger با متد log(string $m) بساز و دو پیاده‌سازی بنویس: یکی با echo و یکی که در فایل بنویسد.
