مصاحبه چطور است؟

مصاحبه‌ی فنی لاراول معمولاً چهار بخش دارد: سؤال‌های مفهومی (PHP/لاراول/دیتابیس)، تمرین کدنویسی کوتاه یا تکلیف خانگی، بحث درباره‌ی پروژه‌های خودت و سؤال‌های رفتاری. هدف مصاحبه‌کننده فقط «جواب درست» نیست؛ می‌خواهد ببیند چطور فکر می‌کنی، صادقی و می‌توانی یاد بگیری.

اگر نمی‌دانی

جمله‌ی «دقیق نمی‌دانم، ولی فکر می‌کنم اینطور باشد چون ...؛ مستندات را چک می‌کنم» بهتر از حدس با اعتمادبه‌نفس غلط است. صادقانه استدلال کن.

سؤال‌های PHP

سؤالجواب کوتاه و کافی
== با === چه فرقی دارد؟== بعد از تبدیل نوع مقایسه می‌کند، === مقدار و نوع را؛ در کد جدی از === استفاده می‌کنیم.
Interface و Abstract Class؟Interface فقط قرارداد (متدهای بدون بدنه) و یک کلاس چند Interface می‌تواند داشته باشد؛ Abstract می‌تواند پیاده‌سازی و حالت (property) داشته باشد و فقط یک‌بار ارث می‌برد.
Trait چیست؟راهی برای استفاده‌ی مجدد از متدها در چند کلاس بدون ارث‌بری؛ مثل HasFactory.
public/protected/private؟سطح دسترسی: از هرجا / کلاس و فرزندان / فقط خود کلاس.
static و self؟self به همان کلاس اشاره می‌کند، static به کلاس واقعیِ فراخوانی‌شده (Late Static Binding).
چرا type hint و declare(strict_types=1)؟خطاهای نوع را زود نشان می‌دهد و کد قابل‌فهم‌تر و ایمن‌تر می‌شود.
Enum و readonly؟Enum برای مجموعه‌ی محدود ثابت؛ readonly برای ویژگی‌ای که بعد از مقداردهی تغییر نمی‌کند.
Namespace و Autoload؟Namespace از تداخل نام جلوگیری می‌کند؛ Composer با PSR-4 مسیر فایل را از نام کلاس می‌سازد و خودکار لود می‌کند.

سؤال‌های لاراول

سؤالجواب کوتاه و کافی
چرخه‌ی عمر یک درخواست؟public/index.php ← بوت برنامه و Service Providerها ← Middleware ← Router ← کنترلر ← پاسخ برمی‌گردد از Middlewareها ← ارسال به مرورگر.
Service Container چیست؟ظرفی که وابستگی‌ها را می‌سازد و تزریق می‌کند؛ با type hint در سازنده یا متد خودکار حل می‌شود و می‌توان Interface را به پیاده‌سازی bind کرد.
Service Provider؟جایی برای ثبت (register) و راه‌اندازی (boot) سرویس‌ها، رویدادها و روت‌ها.
Middleware؟لایه‌ای که قبل/بعد از کنترلر روی درخواست/پاسخ کار می‌کند (احراز هویت، Rate Limit، هدرها).
N+1 چیست و چطور رفعش می‌کنی؟اجرای یک کوئری برای لیست و یک کوئری برای هر ردیف؛ با with() (Eager Loading) یا withCount رفع می‌شود؛ preventLazyLoading در توسعه آن را نشان می‌دهد.
with و load؟with هنگام ساخت کوئری، load بعد از گرفتن مدل.
$fillable و $guarded؟کنترل Mass Assignment: فقط فیلدهای مجاز یا همه‌ به‌جز فیلدهای ممنوع؛ امن‌تر $fillable است.
Policy و Gate؟Gate قانون ساده با Closure؛ Policy قوانین یک مدل در یک کلاس.
Queue چه مشکلی را حل می‌کند؟کارهای کند را از پاسخ کاربر جدا می‌کند؛ با Worker، تلاش مجدد و failed_jobs.
Event/Listener و Observer؟Event اتفاق کسب‌وکار را اعلام می‌کند؛ Observer به رویدادهای چرخه‌ی عمر مدل (created, updated) گوش می‌دهد.
config:cache و env()؟بعد از کش‌کردن config، env() خارج از فایل‌های config مقدار نمی‌دهد؛ همیشه از config() بخوان.
چطور API را امن می‌کنی؟Sanctum/توکن، Policy، Validation، Rate Limit، Resource برای کنترل خروجی، HTTPS.
چطور تست می‌نویسی؟Feature Test برای مسیرهای مهم با RefreshDatabase و Factory؛ Unit Test برای منطق خالص؛ Mail::fake/Http::fake برای وابستگی‌های بیرونی.

دیتابیس و وب

سؤالجواب کوتاه و کافی
ایندکس چیست و کی بد است؟ساختاری که جست‌وجو را سریع می‌کند؛ نوشتن را کند و حجم را زیاد می‌کند؛ فقط ستون‌های پرکاربرد در WHERE/JOIN/ORDER.
تراکنش و ACID؟مجموعه‌ی کارها یا کاملاً انجام می‌شود یا هیچ؛ Atomicity، Consistency، Isolation، Durability.
INNER JOIN و LEFT JOIN؟INNER فقط سطرهای جفت‌شده؛ LEFT همه‌ی سطرهای چپ حتی بدون جفت.
REST چیست؟ کدهای وضعیت؟منابع با آدرس و متدهای HTTP؛ ۲۰۰/۲۰۱/۲۰۴ موفق، ۴۰۱ نیاز به ورود، ۴۰۳ ممنوع، ۴۰۴ نیست، ۴۲۲ اعتبارسنجی، ۵۰۰ خطای سرور.
SQL Injection؟ XSS؟ CSRF؟تزریق به SQL (راه‌حل: bind)؛ اجرای اسکریپت کاربر در صفحه (راه‌حل: escape)؛ ارسال درخواست ناخواسته از مرورگر قربانی (راه‌حل: توکن CSRF).

تمرین کدنویسی کوتاه

معمولاً مسئله‌های ساده ولی با توجه به کیفیت: نام‌گذاری، حالت‌های خاص، تست. نمونه‌ی مرسوم: «گروه‌بندی سفارش‌ها بر اساس کاربر و جمع مبلغ».

کدphp
<?php

declare(strict_types=1);

/**
 * @param array<int, array{user_id: int, total: int}> $orders
 * @return array<int, int>  [user_id => جمع مبلغ]
 */
function totalsByUser(array $orders): array
{
    $totals = [];

    foreach ($orders as $order) {
        $totals[$order['user_id']] = ($totals[$order['user_id']] ?? 0) + $order['total'];
    }

    arsort($totals);   // بیشترین به کمترین

    return $totals;
}

print_r(totalsByUser([
    ['user_id' => 1, 'total' => 100],
    ['user_id' => 2, 'total' => 300],
    ['user_id' => 1, 'total' => 250],
]));
خروجیخروجی
Array
(
    [1] => 350
    [2] => 300
)
  • ابتدا مسئله را با صدای بلند بازگو و حالت‌های خاص را بپرس (ورودی خالی؟ مقدار منفی؟).
  • اول راه ساده و درست، بعد بهینه؛ فکر کردنت را بلند بگو.
  • نام‌ها را خوانا بنویس و در آخر یک تست ذهنی یا کوچک بزن.
  • در لاراول: collect($orders)->groupBy('user_id')->map->sum('total') هم یک راه کوتاه است؛ ولی نشان بده که اصل الگوریتم را هم می‌دانی.

درباره‌ی پروژه‌هایت صحبت کن

بیشترین سؤال‌ها از همین بخش می‌آید، چون نمی‌شود تقلب کرد. برای هر پروژه آماده باش:

  1. مسئله چه بود و چرا آن را ساختی؟ (۳۰ ثانیه)
  2. معماری و جداول اصلی؛ چرا اینطور طراحی کردی؟
  3. سخت‌ترین مشکل و چطور حلش کردی (باگ، کندی، امنیت).
  4. چه چیزی را اگر دوباره می‌ساختی عوض می‌کردی؟
  5. کدام قسمت را خودت نوشتی و کدام از دوره/کتابخانه است؟ (صادقانه)
STAR برای سؤال‌های رفتاری

Situation (موقعیت)، Task (وظیفه)، Action (کاری که خودت کردی)، Result (نتیجه و درسی که گرفتی). مثلاً درباره‌ی «یک اشتباه بزرگ»: ماجرا، سهم تو، چطور اصلاحش کردی و چه چیزی عوض شد.

تکلیف خانگی (Take-home)

  • فهرست نیازها را بخوان و اگر مبهم بود قبل از شروع بپرس.
  • کوچک اما کامل: README، دستور اجرا، Seeder، چند تست، کد تمیز. یک کار نیمه‌ی بزرگ از یک کار کوچک و کامل بدتر است.
  • یک فایل کوتاه «تصمیم‌ها و محدودیت‌ها» بنویس: چه چیزی را عمداً ساده گرفتی و اگر زمان بود چه می‌کردی.
  • به مهلت احترام بگذار و اسرار/داده‌ی واقعی در کار نگذار.

سؤال از مصاحبه‌کننده و مذاکره

  • سؤال‌های خوب بپرس: «فرایند Code Review و تست چطور است؟»، «دیپلوی چطور انجام می‌شود؟»، «در ۳ ماه اول از من چه انتظاری دارید؟».
  • درباره‌ی حقوق: پیش از مذاکره بازار مشابه را بسنج؛ بازه‌ی منطقی و دلیل بگو و فقط به عدد فکر نکن (دورکاری، آموزش، رشد، مزایا، قرارداد).
  • قرارداد/توافق را مکتوب بخوان؛ مدت آزمایشی، ساعت کار، مالکیت کد و بیمه را بپرس.
  • اگر جواب منفی گرفتی، بازخورد بخواه؛ هر مصاحبه تمرین بعدی است.

اشتباه‌های رایج

  1. حفظ‌کردن جواب‌ها بدون فهمیدن؛ با یک سؤال «چرا؟» می‌ریزد.
  2. ادعای مهارتی که عمق ندارد.
  3. نشناختن پروژه‌ی خودت.
  4. سکوت طولانی در کدنویسی؛ فکر کردنت را بلند بگو.
  5. بد گفتن از کارفرمای قبلی.
  6. نپرسیدن هیچ سؤالی در پایان.

تمرین ۱
