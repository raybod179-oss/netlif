پروژه‌ی پایانی: مارکت‌پلیس چندفروشنده

مارکت‌پلیس کامل: فروشگاه درس‌ها به فروشندگان مستقل تبدیل می‌شود؛ هر فروشنده پنل، محصول، سفارش، کمیسیون و کیف پول دارد. برای دوره‌ی «Laravel از 0 تا 1000» توسط Rayvo (رایبد اکبرلو) ساخته شده است.

۱. دانلود با یک کلیک

⬇ دانلود laravel-marketplace-source.zip

136 فایل: مدل، مایگریشن، کنترلر، ویو، پنل مدیریت، داده‌ی آزمایشی و تست. این zip یک «لایه‌ی روی لاراول» است، نه پروژه‌ی کامل؛ پوشه‌ی vendor را Composer نصب می‌کند.

این zip شامل کل فروشگاه پروژه‌ی اول به‌علاوه‌ی لایه‌ی فروشنده است؛ پس فقط همین یک zip را روی پروژه‌ی تازه استخراج کن، نه zip فروشگاه را هم. این فایل‌های فروشگاه بازنویسی می‌شوند: routes/web.php، User.php، Product.php، Order.php، CheckoutController.php، config/shop.php، DatabaseSeeder.php و layout.

۲. نصب و اجرا

همان الگوی همیشگی: لاراول تازه، استخراج zip، migrate با seed و اجرا:

کدترمینال
composer create-project laravel/laravel laravel-marketplace
cd laravel-marketplace

# ویندوز (PowerShell):
tar -xf "$env:USERPROFILE\Downloads\laravel-marketplace-source.zip" -C .
# مک / لینوکس:
unzip -o ~/Downloads/laravel-marketplace-source.zip -d .

php artisan migrate --seed
php artisan storage:link
php artisan serve

۳. اگر با MySQL (XAMPP یا Laragon) کار می‌کنی

اگر با MySQL کار می‌کنی، XAMPP یا Laragon را باز و MySQL را Start کن. در http://127.0.0.1/phpmyadmin/ دیتابیسی به اسم laravel_marketplace با collation برابر utf8mb4_unicode_ci بساز، این مقدارها را در .env بگذار و دیتابیس را از نو بساز:

کد.env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=laravel_marketplace
DB_USERNAME=root
DB_PASSWORD=

php artisan migrate:fresh --seed

۴. حساب‌ها

مدیر: admin@shop.test، مشتری: customer@shop.test، فروشنده‌ی تأییدشده: vendor@shop.test؛ گذرواژه‌ی هر سه password. آدرس‌ها: /vendor پنل فروشنده، /vendor/apply درخواست فروشندگی، /shops/{id} صفحه‌ی عمومی فروشگاه، /admin/vendors و /admin/payouts مدیریت فروشندگان و برداشت‌ها.

۵. چرخه‌ی کار مارکت‌پلیس

۱) مشتری از «فروشنده شو» درخواست می‌دهد. ۲) مدیر در /admin/vendors تأیید می‌کند. ۳) فروشنده محصول می‌سازد (فقط محصول خودش را می‌بیند و ویرایش می‌کند). ۴) مشتری سبدی از چند فروشنده می‌خرد؛ هر ردیف سفارش، فروشنده و کمیسیون را snapshot می‌کند. ۵) وقتی مدیر وضعیت سفارش را «تحویل داده شد» کرد، سهم هر فروشنده (قیمت منهای کمیسیون) به کیف پولش واریز می‌شود، فقط یک بار. ۶) فروشنده درخواست برداشت می‌دهد و مدیر پرداخت یا رد می‌کند (رد، مبلغ را برمی‌گرداند).

۶. کمیسیون و حداقل برداشت

در config/shop.php:

کدconfig
'commission_percent' => 10,
'min_payout' => 50000,

۷. قلب پروژه: واریز به کیف پول

فایل app/Services/Wallet.php. واریز با firstOrCreate و یک ایندکس یکتا انجام می‌شود تا تسویه‌ی دوباره‌ی یک سفارش ممکن نباشد؛ برداشت داخل تراکنش و با قفل ردیف کاربر انجام می‌شود تا دو برداشت هم‌زمان موجودی را منفی نکنند:

کدOrder.php
protected static function booted(): void
{
    static::updated(function (Order $order) {
        if ($order->wasChanged('status') && $order->status === 'completed') {
            app(\App\Services\Wallet::class)->settle($order);
        }
    });
}

۸. امنیت

vendor_id هنگام ساخت محصول همیشه از سرور تعیین می‌شود نه از فرم؛ هر فروشنده فقط محصول خودش را ویرایش می‌کند (۴۰۳ برای بقیه)؛ نقش فروشنده با Middleware جدا بررسی می‌شود و وضعیت فروشنده فقط ادمین عوض می‌کند.

۹. اجرای تست

کدتست
php artisan test

۱۰. نکته‌ی مهم قبل از راه‌اندازی واقعی

این پروژه پرداخت آنلاین واقعی را انجام نمی‌دهد (سفارش‌ها دستی تحویل داده می‌شوند) و برداشت‌ها را مدیر دستی پرداخت می‌کند. قبل از استفاده‌ی واقعی باید درگاه پرداخت (درس سطح ۲)، قوانین مالی و مالیاتی و شرایط استفاده برای فروشندگان را خودت اضافه و بررسی کنی.

۱۱. تمرین

نظرات و امتیاز محصول، چت مشتری و فروشنده با Broadcasting، تقسیم سفارش به چند ارسال، کد تخفیف، گزارش فروش با نمودار برای فروشنده و API با Sanctum.

اشتباه‌های رایج

  1. استخراج هر دو zip (فروشگاه و مارکت‌پلیس) روی یک پروژه؛ فقط zip مارکت‌پلیس کافی است.
  2. فراموش‌کردن تأیید فروشنده توسط ادمین و تعجب از ۴۰۳ در /vendor.
  3. فراموش‌کردن تغییر وضعیت سفارش به «تحویل داده شد» و ندیدن واریز به کیف پول.
