۱

چرا Storage لازم است؟

تا الان جدولِ products ما فقط نام، توضیح و قیمت داشت. در دنیایِ واقعی، هر محصولِ فروشگاهی عکس دارد. عکس یک فایلِ دودویی (binary) است و جایِ آن در دیتابیس نیست: باید در فایل‌سیستمِ سرور ذخیره شود.

Laravel مفهومی به نام Filesystem دارد که به تو اجازه می‌دهد بدونِ نگرانی از مسیرِ دقیقِ سرور، فایل‌ها را «ذخیره»، «خواندن» و «حذف» کنی.

فایل ذخیره شود کجا؟

  • درِ دیتابیس → فقط نامِ فایل (string)
  • درِ فایل‌سیستم → خودِ فایلِ باینری

نقشِ Laravel

  • مدیریتِ مسیر با Disk
  • validate، store، delete، url
تلفیقِ فصل‌ها

این فصل هم‌راهِ فصلِ ۱۰ (فرم‌ها و validation) و فصلِ ۸ (CRUD) است. فرمی می‌سازیم که فایل بگیرد، validate شود، ذخیره شود و عکسِ آن درِ صفحه‌ی محصول نمایش داده شود.

۲

Disk‌ها در filesystems.php

هر «محلِ ذخیره» در لاراول به نامِ Disk شناخته می‌شود. تنظیماتِ دیسک‌ها در فایل config/filesystems.php تعریف شده‌اند:

کدconfig/filesystems.php (بخشِ disks)
'disks' => [

    'local' => [
        'driver' => 'local',
        'root'   => storage_path('app/private'),
        'serve'  => true,   // لاراول ۱۳
        'throw'  => false,
    ],

    'public' => [
        'driver' => 'local',
        'root'   => storage_path('app/public'),
        'url'    => env('APP_URL').'/storage',
'visibility' => 'public',
        'throw'  => false,
    ],

    's3' => [
        'driver' => 's3',
        'key'    => env('AWS_ACCESS_KEY_ID'),
        // ... تنظیماتِ S3
    ],

],

    // پیوندِ دستی به public/storage
    'links' => [
        public_path('storage') => storage_path('app/public'),
    ],
  • local: فایل‌ها در storage/app/private ذخیره می‌شوند؛ قابلِ دسترسی از وب نیستند.
  • public: فایل‌ها در storage/app/public ذخیره می‌شوند؛ برایِ فایل‌های عمومی مثل عکسِ محصول.
  • s3: فضایِ ابریِ آمازون؛ درِ پروژه‌های واقعی برایِ هاست‌های ابری.
کدام disk را انتخاب کنیم؟

برایِ عکسِ محصولِ فروشگاه، 'public' مناسب است. اگر فایل باید پنهان باشد (مثلِ فاکتورِ PDF)، از 'local' استفاده کن و لینکِ دانلود را با auth محافظت کن.

۳

ساختِ symbolic link با storage:link

فایل‌هایِ diskِ public درِ storage/app/public ذخیره می‌شوند؛ اما مرورگر فقط از پوشه‌ی public/ محتوا سرو می‌کند. باید یک «پیوندِ نمادین» بسازیم:

$ php artisan storage:link INFO The [public/storage] link has been connected to [storage/app/public].
  • بعد از اجرایِ این فرمان، فایلِ public/storage به storage/app/public اشاره می‌کند.
  • درِ ویندوز، ممکن است نیاز به دسترسیِ Developer Mode داشته باشی.
  • درِ تولید، این فرمان بخشی از فرایندِ deploy است.
فراموش نکن!

اگر storage:link را اجرا نکنی، عکس‌هایِ آپلودشده ۴۰۴ می‌خورند. این رایج‌ترین اشتباهِ مبتدیان است.

۴

آپلودِ ساده در کنترلر

درِ فرمِ HTML، فایل با <input type="file"> گرفته می‌شود. درِ کنترلرِ لاراول، فایلِ آپلودشده از طریقِ $request->file('name') در دسترس است و با متدِ store() ذخیره می‌شود:

کدPHP — آپلودِ ساده
use Illuminate\Http\Request;

public function store(Request $request)
{
    // ۱. فایل را از فرم بگیر
    $file = $request->file('image');

    // ۲. درِ diskِ public و پوشه‌ی images ذخیره کن
    $path = $file->store('images', 'public');
    // نتیجه: "images/a1b2c3d4e5.jpg"

    // ۳. مسیرِ ذخیره‌شده را در دیتابیس ذخیره کن
    Product::create([
        'name'     => $request->input('name'),
        'price'    => $request->input('price'),
        'image'    => $path,   // "images/abc.jpg"
    ]);
}
  • $request->file('image') → شیءِ UploadedFile را برمی‌گرداند.
  • store('images', 'public') → فایل را با نامِ تصادفیِ Hash درِ storage/app/public/images/ ذخیره می‌کند.
  • نامِ فایل خودکار Hash شده است (امنیت: نامِ اصلی فاش نمی‌شود).
کدHTML — فرمِ آپلود
<form method="POST" action="{{ route('products.store') }}"
      enctype="multipart/form-data">
    @csrf

    <label>نام محصول</label>
    <input type="text" name="name">

    <label>قیمت</label>
    <input type="number" name="price">

    <label>عکس محصول</label>
    <input type="file" name="image" accept="image/*">

    <button type="submit">ذخیره</button>
</form>
enctype را فراموش نکن

اگر enctype="multipart/form-data" را ننویسی، فایل به کنترلر نمی‌رسد. هر فرمی که فایل آپلود می‌کند باید این ویژگی را داشته باشد.

۵

اعتبارسنجیِ فایل

آپلودِ بدونِ validation یعنی کاربر می‌تواند فایلِ اجرایی (.exe) یا فایلِ بزرگ آپلود کند. Laravel قواعدِ validationِ مخصوصِ فایل دارد:

کدPHP — Validation فایل
public function store(Request $request)
{
    $validated = $request->validate([
        'name'  => 'required|string|max:255',
        'price' => 'required|integer|min:0',
        'image' => [
            'required',
            'image',                // باید تصویر باشد
            'mimes:jpg,jpeg,png',   // فرمت‌های مجاز
            'max:2048',             // حداکثر ۲ مگابایت
        ],
    ]);

    $path = $request->file('image')->store('images', 'public');

    Product::create([...$validated, 'image' => $path]);
}
  • image: فایل باید تصویر باشد (بر اساسِ MIME type واقعی).
  • mimes:jpg,jpeg,png: فقط این پسوندها مجازند.
  • max:2048: حداکثر حجم ۲۰۴۸ کیلوبایت.
کدPHP — قواعدِ رایجِ فایل
// تصویر با حداکثر ۵ مگابایت
'image' => 'required|image|mimes:jpg,png|max:5120',

// PDF با حداکثر ۱۰ مگابایت
'document' => 'required|mimes:pdf|max:10240',

// هر فایلی
'attachment' => 'required|file|max:2048',

// ابعادِ تصویر
'image' => ['required', 'image', 'dimensions:min_width=300,min_height=300'],
max و تنظیماتِ PHP

مقدارِ max درِ قواعدِ لاراول با upload_max_filesize و post_max_size درِ php.ini هماهنگ باشد. اگر حجمِ فایل از تنظیماتِ PHP بیشتر باشد، PHP خودش فایل را قطع می‌کند.

۶

store() و storeAs()

دو روش برایِ ذخیره‌ی فایل داریم:

store()

  • نامِ فایل خودکار Hash می‌شود
  • امن: نامِ اصلی فاش نمی‌شود
  • store('images', 'public')
  • نتیجه: images/x8k3f.jpg

storeAs()

  • نامِ فایل را تو تعیین می‌کنی
  • باید مطمئن شوی نامِ تکراری نباشد
  • storeAs('images', 'cover.jpg', 'public')
کدPHP — storeAs
// storeAs: نامِ فایل را خودت مشخص می‌کنی
$path = $request->file('image')
    ->storeAs('images', 'cover-product-1.jpg', 'public');
// ذخیره در: storage/app/public/images/cover-product-1.jpg

// storeAs با مسیرِ کامل
$path = $request->file('image')
    ->storeAs('images/products', 'hero.png', 'public');
  • store() → نامِ تصادفی و امن (پیشنهادی).
  • storeAs() → نامِ مشخص؛ فقط وقتی لازم است که بخواهی نامِ خاصی داشته باشی.
  • درِ هر دو حالت، مسیرِ برگشت‌شده را درِ دیتابیس ذخیره کن (نه خودِ فایل را).
چه چیزی در دیتابیس ذخیره می‌شود؟

فقط رشته‌ی مسیر مثل images/a1b2c3d4e5.jpg. خودِ فایل درِ فایل‌سیستم است و دیتابیس فقط «کجاست» را نگه می‌دارد.

۷

نمایشِ فایلِ آپلودشده

برایِ نمایشِ عکس درِ بلید، از helperِ asset() استفاده کن. مسیرِ ذخیره‌شده درِ دیتابیس را به لینکِ وب تبدیل می‌کند:

کدBlade — نمایشِ عکسِ محصول
<!-- عکسِ محصول از دیتابیس -->
<img src="{{ asset('storage/' . $product->image) }}"
     alt="{{ $product->name }}"
     width="300">

<!-- اگر عکس نداشت، پیش‌فرض نشان بده -->
@if ($product->image)
    <img src="{{ asset('storage/' . $product->image) }}"
         alt="{{ $product->name }}">
@else
    <img src="{{ asset('images/placeholder.png') }}"
         alt="عکس ندارد">
@endif
  • asset('storage/images/abc.jpg') → http://localhost:8000/storage/images/abc.jpg
  • مسیرِ برگشت‌شده از store() دقیقاً همان چیزی است که asset() نیاز دارد.
  • اگر عکسِ پیش‌فرض نداری، می‌توانی درِ دیتابیس مقدارِ null بگذاری و درِ بلید شرطی کنی.
Storage facade و URL

روشِ جایگزین: Storage::url($path) که دقیقاً همان خروجیِ asset('storage/...') را می‌دهد.

۸

حذفِ فایل با Storage::delete

وقتی محصول را حذف یا ویرایش می‌کنیم، باید فایلِ قدیمی را هم از فایل‌سیستم پاک کنیم. facadeِ Storage متدِ delete() دارد:

کدPHP — حذفِ فایل
use Illuminate\Support\Facades\Storage;

// حذفِ یک فایل از دیسکِ public
Storage::disk('public')->delete('images/old-photo.jpg');

// حذفِ چند فایل
Storage::disk('public')->delete(['images/pic1.jpg', 'images/pic2.jpg']);

// حذفِ فایلِ محصول قبل از آپلودِ جدید (ویرایش)
public function update(Request $request, Product $product)
{
    $validated = $request->validate([
        'name'  => 'required|string|max:255',
        'price' => 'required|integer|min:0',
        'image' => 'nullable|image|mimes:jpg,jpeg,png|max:2048',
    ]);

    if ($request->hasFile('image')) {
        // حذفِ عکسِ قدیمی
if ($product->image) {
            Storage::disk('public')->delete($product->image);
        }
        // ذخیره‌ی عکسِ جدید
        $validated['image'] = $request->file('image')
            ->store('images', 'public');
    }

    $product->update($validated);
}
کدPHP — حذفِ محصول و فایل
public function destroy(Product $product)
{
// حذفِ فایلِ عکس
    if ($product->image) {
        Storage::disk('public')->delete($product->image);
    }

    // حذفِ ردیفِ دیتابیس
    $product->delete();

    return redirect()->route('products.index')
        ->with('success', 'محصول حذف شد.');
}
  • عکس‌ها روی دیسکِ public ذخیره می‌شوند، پس برای حذف هم باید همان دیسک را صدا بزنی: Storage::disk('public')->delete('images/abc.jpg').
  • Storage::delete(...) بدونِ نامِ دیسک، روی دیسکِ پیش‌فرض (local) کار می‌کند؛ یعنی حذف نمی‌شود و فایل یتیم می‌ماند.
  • همیشه اولِ فایل را حذف کن، بعدِ ردیفِ دیتابیس را.
فایلِ یتیم نساز!

اگر فقط ردیفِ دیتابیس را حذف کنی ولی فایل را نه، فایلِ «یتیم» (orphan) روی سرور باقی می‌ماند و فضا می‌گیرد. همیشه حذفِ فایل را درِ destroy() فراموش نکن.

۹

فرمِ آپلودِ کامل در بلید

حالا بیا یک فرمِ کاملِ آپلود برایِ محصول بسازیم که همه‌ی مواردِ بالا را داشته باشد:

کدresources/views/products/create.blade.php
@extends('layouts.app')

@section('content')
<h1>افزودنِ محصول</h1>

<form method="POST" action="{{ route('products.store') }}"
      enctype="multipart/form-data">
    @csrf

    <div>
        <label>نام محصول</label>
        <input type="text" name="name" value="{{ old('name') }}">
        @error('name')
            <span style="color:red">{{ $message }}</span>
        @enderror
    </div>

    <div>
        <label>قیمت (تومان)</label>
        <input type="number" name="price" value="{{ old('price') }}">
        @error('price')
            <span style="color:red">{{ $message }}</span>
        @enderror
    </div>

    <div>
        <label>عکس محصول</label>
        <input type="file" name="image" accept="image/*">
        @error('image')
            <span style="color:red">{{ $message }}</span>
        @enderror
    </div>

    <button type="submit">ذخیره</button>
</form>
@endsection
کدresources/views/products/edit.blade.php (بخشِ عکس)
<div>
    <label>عکس محصول</label>
    <input type="file" name="image" accept="image/*">

    @if ($product->image)
        <div style="margin-top:8px">
            <p>عکسِ فعلی:</p>
            <img src="{{ asset('storage/' . $product->image) }}"
                 width="150" style="border-radius:8px">
        </div>
    @endif

    @error('image')
        <span style="color:red">{{ $message }}</span>
    @enderror
</div>
  • accept="image/*" درِ مرورگر فقط فایل‌هایِ تصویری نشان می‌دهد (اما جایگزینِ validation نیست).
  • درِ فرمِ ویرایش، عکسِ فعلی را قبل از آپلودِ جدید نشان بده تا کاربر بداند چه چیزی دارد.
  • فیلدِ image درِ ویرایش nullable است: اگر فایل جدیدی آپلود نشد، عکسِ قبلی باقی بماند.
۱۰

گام پروژه: عکسِ محصول

تکمیلی: فروشگاه با عکسِ محصول

تا پیش از این، محصولاتِ فروشگاه فقط متنی بودند. حالا عکسِ واقعی به هر محصول اضافه می‌کنیم.

  1. فرمانِ storage:link را اجرا کن: php artisan storage:link
  2. Migration جدید بساز: ستونِ image (nullable string) به جدولِ products اضافه کن: php artisan make:migration add_image_to_products_table
  3. Migration را اجرا کن: php artisan migrate
  4. ProductFactory را بروزرسانی: فیلدِ 'image' => null اضافه کن (یا عکسِ پیش‌فرض).
  5. ProductController را بروزرسانی: متدهای store() و update() را با validation و آپلودِ فایل تکمیل کن.
  6. فرم‌های بلید (create و edit) را با فیلدِ <input type="file"> و نمایشِ عکس تکمیل کن.
  7. نمایش: درِ products/show.blade.php عکسِ محصول را با asset('storage/...') نشان بده.
  8. تست: یک محصول با عکس بساز، درِ صفحه ببین، ویرایش کن (عکسِ جدید آپلود کن)، حذف کن.
ادامه‌ی راه

همین الگو (آپلود + ذخیره‌ی مسیر + نمایش + حذف) پایه‌ی آپلودِ تصویر در پروژه‌ی پایانی (بخشِ ۹۹) است.

۱۱

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: آپلودِ چند عکس
  1. فرمی بساز که ۳ عکس همزمان آپلود کند: $request->file('images') یک آرایه برمی‌گرداند.
  2. هر عکس را با foreach درِ پوشه‌ی images/gallery/ ذخیره کن.
  3. مسیرِ هر عکس را درِ یک جدولِ جداگانه ذخیره کن (رابطه‌ی hasMany).
تمرین ۲: دانلودِ فایل
  1. یک لینکِ «دانلودِ عکس» درِ صفحه‌ی نمایشِ محصول بگذار.
  2. روتِ /products/{product}/download بساز که فایل را با Storage::download() تحویل دهد.
  3. نامِ فایلِ دانلودی باید نامِ اصلیِ محصول باشد (مثلاً cover.jpg).
تمرین ۳: اعتبارسنجیِ ابعاد
  1. Validation را طوری تنظیم کن که عکسِ آپلودی حداقل ۳۰۰×۳۰۰ پیکسل باشد: dimensions:min_width=300,min_height=300.
  2. اگر کاربر عکسِ کوچکتر آپلود کند، خطا نشان بده.
چالش

آپلودِ تصویر را به صورت AJAX (بدونِ رفرشِ صفحه) پیاده کن: فایل را با JavaScript بفرست، آدرسِ عکس را بگیر و درِ فرم قرار بده. راهنما: لاراول خودش endpointِ آپلود ندارد؛ باید یک route و کنترلرِ جداگانه بسازی.

چیزی که از این بخش توی ذهنت بماند

  1. Disk تعیین‌کننده‌ی «جای ذخیره» است: public برایِ فایلِ عمومی، local برایِ فایلِ خصوصی.
  2. حتماً php artisan storage:link اجرا کن وگرنه عکس‌ها ۴۰۴ می‌خورند.
  3. store('path', 'disk') نامِ تصادفی می‌سازد؛ storeAs() نامِ دلخواهِ تو.
  4. فرمِ HTML باید enctype="multipart/form-data" داشته باشد وگرنه فایل ارسال نمی‌شود.
  5. Validation فایل: image|mimes:jpg,png|max:2048 — امنیت را جدی بگیر.
  6. فقط مسیرِ فایل (رشته) درِ دیتابیس ذخیره شود، خودِ فایل درِ فایل‌سیستم.
  7. حذفِ محصول بدونِ حذفِ فایل = فایلِ یتیم؛ همیشه Storage::disk('public')->delete() را فراموش نکن.
