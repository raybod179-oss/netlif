Scheduler چیست؟

کارهایی هستند که باید خودکار و در زمان مشخص اجرا شوند: لغو سفارش‌های پرداخت‌نشده بعد از ۳۰ دقیقه، گزارش روزانه‌ی فروش، پاک‌سازی داده‌های قدیمی. روش قدیمی این بود که برای هر کار یک Cron جدا در سرور بسازی. در لاراول فقط یک Cron می‌سازی و همه‌ی زمان‌بندی‌ها را داخل خود کد می‌نویسی؛ در گیت می‌ماند و قابل‌تست است.

۲

ساخت یک دستور Artisan

کدbash
php artisan make:command CancelUnpaidOrders
کدphp
<?php

namespace App\Console\Commands;

use App\Models\Order;
use Illuminate\Console\Command;

class CancelUnpaidOrders extends Command
{
    protected $signature = 'orders:cancel-unpaid {--minutes=30 : چند دقیقه بعد لغو شود}';

    protected $description = 'سفارش‌های پرداخت‌نشده‌ی قدیمی را لغو می‌کند';

    public function handle(): int
    {
        $cutoff = now()->subMinutes((int) $this->option('minutes'));
        $count = 0;

        Order::where('status', 'pending')
            ->where('created_at', '<', $cutoff)
            ->chunkById(100, function ($orders) use (&$count) {
                foreach ($orders as $order) {
                    $order->update(['status' => 'cancelled']);
                    $count++;
                }
            });

        $this->info("{$count} سفارش لغو شد.");

        return self::SUCCESS;
    }
}
کدbash
php artisan orders:cancel-unpaid               # با ۳۰ دقیقه‌ی پیش‌فرض
php artisan orders:cancel-unpaid --minutes=60

زمان‌بندی در routes/console.php

کدphp
<?php

use App\Jobs\SendDailyReport;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Schedule;

Schedule::command('orders:cancel-unpaid')
    ->everyFiveMinutes()
    ->withoutOverlapping();                 // اگر اجرای قبلی تمام نشده، دوباره شروع نکن

Schedule::job(new SendDailyReport)
    ->dailyAt('08:00')
    ->timezone('Asia/Tehran');

Schedule::call(function () {
    DB::table('password_reset_tokens')->where('created_at', '<', now()->subDay())->delete();
})->hourly()->name('prune-reset-tokens');

Schedule::command('model:prune')->daily();                       // مدل‌های Prunable
Schedule::command('backup:run')->weeklyOn(6, '03:00');            // شنبه‌ها ساعت ۳ (۶ = شنبه، ۰ = یکشنبه)
متداجرا
everyMinute() / everyFiveMinutes()هر ۱ / ۵ دقیقه
hourly() / daily()هر ساعت / هر روز ۰۰:۰۰
dailyAt('13:00')هر روز ساعت مشخص
weeklyOn(1, '8:00')هفتگی (۱ = دوشنبه)
monthlyOn(1, '02:00')اول هر ماه
cron('*/10 * * * *')عبارت Cron دلخواه
دستور backup:run

مثال بالا فقط برای نمایش است و نیازمند پکیج‌های بکاپ (مثل spatie/laravel-backup) است. دستور خودت را جایگزین کن.

راه‌اندازی روی سرور

کدbash
# توسعه‌ی محلی: اجرای دائمی زمان‌بند
php artisan schedule:work

# دیدن فهرست کارها و زمان اجرای بعدی
php artisan schedule:list

# اجرای یک‌باره‌ی کارهای «سررسید شده»
php artisan schedule:run

روی سرور واقعی فقط همین یک Cron را اضافه می‌کنی (در cPanel بخش Cron Jobs، روی VPS با crontab -e) تا هر دقیقه لاراول بررسی کند چه کاری سررسید شده:

کدtext
* * * * * cd /path/to/your-project && php artisan schedule:run >> /dev/null 2>&1
اگر Cron نباشد

هیچ‌کدام از کارهای زمان‌بندی‌شده اجرا نمی‌شوند و خطایی هم نمی‌بینی. بعد از دیپلوی حتماً با schedule:list و بررسی لاگ مطمئن شو Cron واقعاً می‌دود.

۵

عادت‌های درست

  • withoutOverlapping() برای کارهای طولانی تا دو نمونه هم‌زمان اجرا نشوند.
  • onOneServer() اگر چند سرور داری تا کار فقط یک‌بار اجرا شود (نیازمند Cache مشترک).
  • کار سنگین را Job کن (Schedule::job) تا زمان‌بند معطل نماند.
  • هر دستور باید «idempotent» باشد: اگر دوبار اجرا شد ضرری نزند.
  • برای خطا اعلان بگیر: ->onFailure(fn () => ...) یا لاگ را مانیتور کن.

تست دستور

کدphp
<?php

namespace Tests\Feature;

use App\Models\Order;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class CancelUnpaidOrdersTest extends TestCase
{
    use RefreshDatabase;

    public function test_old_pending_orders_are_cancelled(): void
    {
        $old = Order::factory()->create(['status' => 'pending', 'created_at' => now()->subHours(2)]);
        $new = Order::factory()->create(['status' => 'pending', 'created_at' => now()->subMinutes(5)]);

        $this->artisan('orders:cancel-unpaid')->assertSuccessful();

        $this->assertSame('cancelled', $old->fresh()->status);
        $this->assertSame('pending', $new->fresh()->status);
    }
}

جلوگیری از هم‌پوشانی، چند سرور و اجرا در پس‌زمینه

زمان‌بندی ساده کار می‌کند تا روزی که یک کار طولانی‌تر از فاصله‌اش طول بکشد؛ آن‌وقت دو نمونه هم‌زمان اجرا می‌شود و داده خراب می‌شود. این گزینه‌ها برای همین‌اند:

کدphp
// routes/console.php
use Illuminate\Support\Facades\Schedule;

Schedule::command('reports:daily')
    ->dailyAt('02:00')
    ->timezone('Asia/Tehran')
    ->withoutOverlapping(30)      // اگر اجرای قبلی هنوز تمام نشده، رد کن (قفل حداکثر ۳۰ دقیقه)
    ->onOneServer()               // با چند سرور فقط روی یکی اجرا شود (نیاز به کش مشترک: Redis/DB)
    ->runInBackground()           // کارهای دیگر منتظر این یکی نمانند
    ->environments(['production']);

Schedule::command('orders:release-unpaid')
    ->everyFiveMinutes()
    ->between('08:00', '23:00')
    ->when(fn () => config('shop.auto_release'))   // فقط اگر شرط برقرار بود
    ->evenInMaintenanceMode();                      // در حالت تعمیر هم اجرا شود
متدکاربرد
withoutOverlapping()جلوگیری از اجرای هم‌زمان دو نمونه‌ی یک کار
onOneServer()در معماری چندسروری فقط یک سرور کار را اجرا کند
runInBackground()کار طولانی بقیه‌ی زمان‌بندی را عقب نیندازد
timezone()ساعت به وقت تهران (پیش‌فرض ساعت APP_TIMEZONE است)
between() / when() / environments()محدودکردن اجرا به بازه‌ی ساعتی، شرط یا محیط
قفل‌ها و کش

withoutOverlapping و onOneServer با قفل کش کار می‌کنند. اگر CACHE_STORE=array باشد قفل بی‌اثر است؛ از database یا redis استفاده کن.

نظارت: بفهم کار اجرا شد یا نه

بدترین حالت این است که زمان‌بندی ماه‌ها خاموش بماند و کسی نفهمد. لاراول چند قلاب برای نظارت دارد:

کدphp
Schedule::command('backup:run')
    ->dailyAt('03:00')
    ->onSuccess(fn () => logger()->info('backup ok'))
    ->onFailure(fn () => Notification::route('mail', 'admin@example.com')->notify(new BackupFailed()))
    ->emailOutputOnFailure('admin@example.com')       // خروجی خطا را ایمیل کن
    ->appendOutputTo(storage_path('logs/backup.log')); // خروجی را در فایل ذخیره کن
کدbash
php artisan schedule:list        # فهرست کارها و زمان اجرای بعدی
php artisan schedule:run         # یک بار اجرای کارهای «موعدرسیده» (همان که cron صدا می‌زند)
php artisan schedule:test        # انتخاب و اجرای دستی یک کار برای تست
php artisan schedule:work        # شبیه‌ساز محلی: هر دقیقه اجرا می‌کند، بدون cron

برای نظارت بیرونی می‌توانی از سرویس‌هایی مثل Healthchecks.io یا Uptime Kuma (خودمیزبان) استفاده کنی: بعد از هر اجرای موفق یک آدرس را صدا بزن و اگر چند دقیقه صدا نخورد، هشدار بگیرد.

کدphp
Schedule::command('reports:daily')
    ->dailyAt('02:00')
    ->pingBefore('https://hc-ping.example/uuid/start')
    ->thenPing('https://hc-ping.example/uuid');
۹

راه‌اندازی روی سرور واقعی

زمان‌بند لاراول یک ورودی cron می‌خواهد که هر دقیقه schedule:run را صدا بزند؛ بقیه‌ی تصمیم‌ها را خود لاراول می‌گیرد.

کدbash
crontab -e
* * * * * cd /var/www/shop && php artisan schedule:run >> /dev/null 2>&1
  • مسیر PHP را کامل بنویس اگر چند نسخه داری: /usr/bin/php8.3 (با which php پیدایش کن).
  • cron را با همان کاربری تنظیم کن که وب‌سرور و Queue با آن اجرا می‌شوند تا مالک فایل‌های storage به‌هم نریزد.
  • روی هاست اشتراکی (cPanel): در بخش Cron Jobs همان دستور را با فاصله‌ی «هر دقیقه» ثبت کن.
  • در Docker: سرویس جدا با php artisan schedule:work (در درس Docker دیدی).
  • ساعت سرور را با date چک کن و منطقه‌ی زمانی را با APP_TIMEZONE=Asia/Tehran بگذار.

کارهای نگه‌داری که حتماً زمان‌بندی کن

کدphp
Schedule::command('model:prune')->daily();                       // حذف رکوردهای قدیمی مدل‌هایی که Prunable هستند
Schedule::command('queue:prune-batches --hours=48')->daily();
Schedule::command('sanctum:prune-expired --hours=24')->daily();  // توکن‌های منقضی‌شده
Schedule::command('queue:prune-failed --hours=168')->weekly();   // Jobهای شکست‌خورده‌ی قدیمی
کدphp
// app/Models/Cart.php: سبدهای رهاشده‌ی بیش از ۳۰ روز پاک شوند
use Illuminate\Database\Eloquent\Prunable;

class Cart extends Model
{
    use Prunable;

    public function prunable()
    {
        return static::where('updated_at', '<=', now()->subDays(30));
    }
}

اشتباه‌های رایج

  1. فراموش‌کردن Cron روی سرور (مهم‌ترین!).
  2. ساعت‌ها: زمان سرور و timezone برنامه را چک کن؛ برای ساعت تهران ->timezone('Asia/Tehran') بده.
  3. کار طولانی داخل call() که همه‌ی زمان‌بندها را عقب می‌اندازد.
  4. نبود withoutOverlapping و اجرای هم‌زمان چندباره.
  5. تغییر دستور و ندیدن اثر: روی هاست‌ها گاهی Cache پیکربندی را با php artisan config:clear پاک کن.
  6. فراموش‌کردن ورودی cron؛ در محیط محلی با schedule:work کار می‌کند ولی روی سرور هیچ اتفاقی نمی‌افتد.
  7. onOneServer با کش array یا فایل محلی (قفل کار نمی‌کند).
  8. اجرای cron با کاربر root و ساخته‌شدن فایل‌های لاگ با مالک اشتباه.

تمرین‌ها

تمرین ۱
  1. دستور products:low-stock بساز که محصولات با موجودی کمتر از ۵ را در لاگ بنویسد و هر روز ساعت ۹ صبح اجرا شود.
تمرین ۲
  1. schedule:work را اجرا کن و کاری بنویس که هر دقیقه یک خط در لاگ بزند؛ سپس با schedule:list ببین.
تمرین ۳
  1. برای دستور لغو سفارش، تستی بنویس که سفارش‌های «paid» را لمس نکند.
تمرین ۴
  1. یک دستور orders:release-unpaid بنویس که سفارش‌های پرداخت‌نشده‌ی بیش از ۳۰ دقیقه را لغو کند و آن را هر ۵ دقیقه با withoutOverlapping زمان‌بندی کن.
  2. با schedule:list مطمئن شو ثبت شده و با schedule:test آن را دستی اجرا کن.
تمرین ۵
  1. مدل Cart را Prunable کن و با php artisan model:prune --pretend ببین چه چیزهایی حذف می‌شوند.
