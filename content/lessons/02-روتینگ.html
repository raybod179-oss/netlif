روتینگ (مسیریابی)

هر درخواستی که به سایت می‌آید، اول از یک روت رد می‌شود. به این‌جا می‌گوییم «نقشه‌ی سایت»؛ حالا این نقشه را درست می‌خوانیم و می‌کشیم.

۱

نقشه‌ی سایت: routes/web.php

همه‌ی مسیرهای سایت‌ت (که با مرورگر باز می‌شوند) در فایل routes/web.php نوشته می‌شوند. هر بار که کسی آدرسی را باز کند، لاراول اول این فایل را نگاه می‌کند: «این آدرس با کدام روت می‌خواند؟» اگر خواند، کارِ همان روت انجام می‌شود؛ اگر نه، به صفحه‌ی ۴۰۴ می‌رسد.

فایلِ پیش‌فرض پروژه‌ات دقیقاً همین است:

کدPHP
<?php

use Illuminate\Support\Facades\Route;

Route::get('/', function () {
    return view('welcome');
});

قسمت‌هایش را بشکنیم:

  • Route::get('/') یعنی «وقتی کسی آدرس ریشه (/) را با روش GET باز کرد...».
  • function () { ... } کارِ همان آدرس است؛ این‌جا فقط صفحه‌ی خوش‌آمد را برمی‌گرداند.
  • view('welcome') یعنی «فایل resources/views/welcome.blade.php را نشان بده».
چرا «روش GET» مهم است؟

مرورگرها برای بازکردن صفحه از GET استفاده می‌کنند؛ اما برای ارسال فرم‌ها روش‌های دیگری مثل POST هم هست. لاراول برای هرکدام متد جدا دارد: Route::get، Route::post، Route::put، Route::delete و...

۲

اولین مسیر

ساده‌ترین روت، یک آدرس + یک تابع است. هر چیزی که تابع برگرداند، همان توی مرورگر نشان داده می‌شود:

کدPHP
Route::get('/hello', function () {
    return 'سلام دنیا!';
});
خروجی نمونهچه می‌بینی؟
بازدید از /hello توی مرورگر:
سلام دنیا!

وقتی تابع فقط یک خط است، می‌توانی از تابع کوتاهِ fn() هم استفاده کنی:

کدPHP
Route::get('/hello', fn () => 'سلام دنیا!');

// یعنی همان تابع بالا، فقط خلاصه‌تر؛ هر دو یکی‌اند
نکته
  • این مسیر را توی routes/web.php بنویس (بعد از روتِ ریشه)، سپس صفحه را در /hello باز کن.
  • وقتی چیزی را از کد تغییر می‌دهی، فقط کافی است صفحه را رفرش کنی؛ لاراول خودش تازه‌اش می‌کند.
  • برای دیدن همه‌ی مسیرهایت: php artisan route:list — یک نقشه‌ی مرتب از روت‌ها.
۳

پارامترهای مسیر

بعضی آدرس‌ها «متغیر» هستند؛ مثلاً هر کاربر باید صفحه‌ی خودش را داشته باشد. به‌جای نوشتن صدها روت، یک بخش متغیر با {...} تعریف می‌کنیم و مقدارش به تابع می‌رسد:

کدPHP
Route::get('/users/{name}', function (string $name) {
    return 'درود، ' . $name . '!';
});
خروجی نمونهچه می‌بینی؟
بازدید از /users/zahra:
درود، zahra!
با /users/ali هم «درود، ali!» را می‌بینی؛ همه با یک روت.

پارامترِ اختیاری

اگر بخواهی پارامترِ حذف‌شدنی باشد، بعد از نامش ? بگذار و برایش یک مقدار پیش‌فرض بده:

کدPHP
Route::get('/greet/{name?}', function (?string $name = null) {
    return $name ? "درود، $name!" : 'درود، مهمان!';
});
خروجی نمونهچه می‌بینی؟
/greet:
درود، مهمان!
/greet/sara:
درود، sara!
دقت کن

در پارامترِ اختیاری، مقدارِ پیش‌فرض حتماً باید باشد؛ وگرنه وقتی پارامتر نیاید، خطای «مقدارِ آرگومان ندارد» می‌گیری. پس توابع PHP را به یاد بیاور: ?string $name = null.

۴

محدودکردن پارامتر با where

گاهی می‌خواهیم بگوییم «اینجا فقط عدد قبول است» یا «فقط حروفِ انگلیسی». این کار با ->where() و یک الگو (Regular Expression) انجام می‌شود:

کدPHP
Route::get('/posts/{id}', function (string $id) {
    return "پست شماره‌ی $id";
})->where('id', '[0-9]+');
خروجی نمونهچه می‌بینی؟
/posts/12:
پست شماره‌ی 12
/posts/laravel (خوانده نمی‌شود):
404
Not Found — چون «laravel» با الگوی عددی نمی‌خواند

برای چند پارامتر هم می‌توانی یک آرایه بدهی، یا از میان‌برهای آماده استفاده کنی:

کدPHP
// چند پارامتر با یک‌جا
Route::get('/user/{id}/{name}', function (string $id, string $name) {
    // ...
})->where(['id' => '[0-9]+', 'name' => '[a-z]+']);

// میان‌برهای آماده‌ی لاراول
Route::get('/post/{id}', function (string $id) {
    // ...
})->whereNumber('id');      // فقط عدد

Route::get('/post/{slug}', function (string $slug) {
    // ...
})->whereAlpha('slug');     // فقط حروف انگلیسی
چرا این‌قدر مهم است؟

چون اگر الگو نگذاری، آدرسِ «اشتباه‌نویسی» وارد تابع‌ات می‌شود و باید خودت خطاها را مدیریت کنی؛ با where، لاراول خودش درخواستِ خارج از محدوده را با ۴۰۴ رد می‌کند.

۵

مسیرهای نامدار و route()

به‌جای این‌که مسیرها را همیشه با آدرسِ خامشان صدا بزنی، می‌توانی به هر روت یک نام بدهی. فایده‌اش: اگر آدرسِ یک روت را عوض کنی، همه‌ی لینک‌های سایت خودکار آپدیت می‌شوند.

کدPHP
Route::get('/products/create', function () {
    return 'فرمِ ساختِ محصول';
})->name('products.create');

// ساختِ لینک با نام مسیر:
$url = route('products.create');
خروجی نمونهچه می‌بینی؟
مقدارِ $url:
http://127.0.0.1:8000/products/create
یعنی با وجودِ پارامترها هم کار می‌کند: route('products.show', ['id' => 3])

با route:list می‌توانی نامِ مسیرهایت را در یک نگاه ببینی:

کدترمینال
php artisan route:list
خروجی نمونهخلاصه
GET|HEAD / → Closure GET|HEAD /hello → Closure GET|HEAD /products/create → products.create GET|HEAD /users/{name} → Closure GET|HEAD /posts/{id} → Closure
نکته
  • اسم مسیرها در کل برنامه باید یکتا باشد. رسمِ معمول، نقطه‌گذاری مثل blog.create و blog.show است.
  • برای رد‌ایرکت به یک مسیرِ نامدار: return to_route('blog.create'); — در درس بعد کامل می‌بینیم.
۶

view() و redirect()

دو پاسخِ پرکاربرد در روت‌ها: یکی «یک صفحه را نشان بده» با view() و دیگری «کاربر را به جای دیگری بفرست» با redirect().

view() — نشان‌دادن یک صفحه

تا وقتی Blade را کامل یاد نگرفتی، ویو فقط یک فایلِ HTML در resources/views است (فایلِ welcome.blade.php را از بخش قبل می‌شناسی). روتِ ریشه‌ی خود لاراول هم همین را می‌کند:

کدPHP
Route::get('/', function () {
    return view('welcome');
});
خروجی نمونهچه می‌بینی؟
بازدید از /:
Laravel
همان صفحه‌ی خوش‌آمدِ پیش‌فرض

redirect() — فرستادن به جای دیگر

مثلاً یک آدرسِ قدیمی داری که می‌خواهی کاربر به صفحه‌ی اصلی برود. با Route::redirect این کار یک‌خطی می‌شود:

کدPHP
// بازدید از /home → رفتن به /
Route::redirect('/home', '/');
خروجی نمونهچه می‌بینی؟
بازدید از /home:
HTTP/302 Found Location: http://127.0.0.1:8000/
مرورگر خودکار به / می‌رود؛ این را «ریدایرکت ۳۰۲» می‌گویند.
نکته
  • اگر بخواهی همان‌لحظه به یک مسیرِ نامدار بفرستی: Route::get('/product/4', fn () => to_route('products.show', ['id' => 4]));
  • برای رفتن به بیرون از سایت هم redirect()->away('https://example.com') هست.
۷

گروه‌کردن مسیرها

وقتی چند مسیر مشترکِ یک بخش دارید (مثلاً همه‌ی بخشِ «پنل مدیریت» با /admin شروع می‌شوند)، می‌توانی آن‌ها را گروه کنی تا پیشوندِ مشترک را یک‌بار بنویسی:

کدPHP
Route::prefix('admin')->group(function () {
    Route::get('/dashboard', fn () => 'پنل مدیریت');
    Route::get('/users', fn () => 'فهرست کاربران');
    Route::get('/settings', fn () => 'تنظیمات');
});

علاوه بر پیشوندِ آدرس، می‌توانی پیشوندِ نام هم بدهی تا همه‌ی مسیرهای گروه با یک اسمِ مشترک شروع شوند:

کدPHP
Route::prefix('admin')->name('admin.')->group(function () {
    Route::get('/users', fn () => 'کاربران')->name('users');
    // آدرس: /admin/users   --   نام: admin.users
});
تعریف آدرس نام
/dashboard داخل گروه /admin/dashboard —
->name('users') داخل گروه /admin/users admin.users
کی به درد می‌خورد؟

وقتی بخشِ بزرگی داری که همه‌ی مسیرهایش یک پیشوند دارند — مثل پنلِ مدیریت، دکمه‌ی «حساب کاربری» یا هوکِ «فروشگاه». به‌جای تکرارِ «admin» و «admin.» در هر خط، یک‌بار در سرِ گروه می‌نویسی.

۸

گام پروژه: مسیرهای فروشگاه

نقشه‌ی اولیه‌ی فروشگاه

توی routes/web.php، محتوای قبلی را با این نقشه‌ی اولیه‌ی فروشگاه عوض کن (کامنت‌ها به فارسی‌اند):

کدPHP
<?php

use Illuminate\Support\Facades\Route;

// صفحه‌ی اصلی فروشگاه
Route::get('/', fn () => view('welcome'));

// فهرست همه‌ی محصول‌ها
Route::get('/products', fn () => 'فهرست محصول‌ها');

// نمایش یک محصول با شماره (فقط عدد)
Route::get('/products/{id}', fn (string $id) => "محصول شماره‌ی $id")
    ->whereNumber('id')
    ->name('products.show');

// محصول‌های یک دسته
Route::get('/categories/{id}', fn (string $id) => "دسته شماره‌ی $id")
    ->whereNumber('id')
    ->name('categories.show');

// سبد خرید (فعلاً فقط یک متن؛ منطقش را بعداً می‌سازیم)
Route::get('/cart', fn () => 'سبد خرید: خالی');
  1. فایل را ذخیره کن و php artisan serve را اجرا کن.
  2. آدرس‌های /، /products، /products/1، /categories/2 و /cart را باز کن.
  3. حالا /products/abc را باز کن؛ ببین چرا ۴۰۴ می‌گیری!
  4. با php artisan route:list نقشه‌ی کامل مسیرهایت را ببین.
یادت باشد

توی این مرحله همه‌چیز «متن ساده» است؛ چون هنوز مدل و ویو را یاد نگرفته‌ایم. ساختارِ مسیرها تا آخرِ دوره تقریباً همین می‌ماند؛ فقط بدنه‌هایشان از «متن» به «کنترلر + مدل + Blade» ارتقا می‌یابد.

۹

تمرین‌ها؛ حالا نوبت توست!

تمرین ۱: مسیرهای خودت
  1. یک روت /about-me بساز که نام و رشته‌ات را برگرداند.
  2. یک روت با پارامتر بساز: /skills/{skill} که مثلاً «علاقه‌ی من: PHP» را نشان دهد.
  3. به آن یک نام بده و با route('...') آدرسش را چک کن.
تمرین ۲: بازی با پارامتر
  1. یک روت /age/{age?} بساز که بدون پارامتر، «سن تو مشخص نیست» و با پارامتر، «سن تو: ...» را نشان دهد.
  2. با ->whereNumber('age') جلوی خروجیِ غیرعددی را بگیر.
  3. /age/abc را تست کن؛ ۴۰۴ گرفتی؟
چالش

به فروشگاهت دو مسیر اضافه کن: /sale که «محصول‌های تخفیف‌دار» را نشان دهد و /sale/{code} که فقط کدهای حراج (حروف انگلیسی کوچک) را بپذیرد — با whereAlpha. با php artisan route:list هر دو را چک کن.

چیزی که از این بخش توی ذهنت بماند

  1. همه‌ی مسیرها در routes/web.php هستند؛ اول هر درخواست از این‌جا عبور می‌کند.
  2. روت = آدرس + تابع: Route::get('/x', fn () => ...).
  3. پارامتر با {x} و اختیاری با {x?} + مقدارِ پیش‌فرض.
  4. با ->where() و میان‌برهای whereNumber / whereAlpha مقدار را محدود کن.
  5. به مسیرهای مهم نام بده (->name('...')) و با route() / to_route() لینک بساز.
  6. مسیرهای هم‌خانواده را با Route::prefix و Route::name گروه کن.
  7. php artisan route:list نقشه‌ی کامل مسیرهایت را نشان می‌دهد.
مطالعه‌ی بیشتر (انگلیسی): مسیر پایه و redirect/view routes، پارامترها و پارامترِ اختیاری، محدودیت با where، مسیرهای نامدار و گروه‌بندی (prefix/name).
